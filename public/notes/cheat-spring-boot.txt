# 01 | Spring Boot Cheat Sheet | Concepts on one page for Spring Boot 4 (and 3): what each part is, why it exists, how it compares with the alternatives, and only the tricky code | Spring Boot on one page

## Spring vs Spring Boot vs Spring Cloud
- **Spring Framework**: the core: IoC container, dependency injection, AOP, Spring MVC, transactions, data access. Powerful but needs a lot of configuration.
- **Spring Boot**: Spring with **auto-configuration**, **starters**, an **embedded server** (Tomcat) and production features (Actuator): runnable jar, almost no setup. "Opinionated defaults you can override."
- **Spring Cloud**: microservice tools on top of Boot: discovery, config server, gateway, load balancing, circuit breakers.
- **vs Jakarta EE / Quarkus / Micronaut**: Boot has the largest ecosystem; Quarkus/Micronaut start faster with less memory (compile-time DI, native images).

## Auto-Configuration & Starters
> **What:** Boot looks at your **classpath and properties** and creates the beans you probably need (a `DataSource` if a JDBC driver is present, Jackson for JSON, Tomcat for web).
- Each auto-config class is guarded by **conditions** (`@ConditionalOnClass`, `@ConditionalOnMissingBean`, `@ConditionalOnProperty`): **your own beans always win**.
- **Starters**: one dependency bringing a tested set of libraries: `spring-boot-starter-webmvc` (Boot 3: `-web`), `-data-jpa`, `-validation`, `-security`, `-actuator`, `-test`. Versions come from the Boot parent BOM.
- Debug what was applied: run with `--debug` (conditions report) or `/actuator/conditions`.

## @SpringBootApplication
> **What:** one annotation on the main class = `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`.
- Component scanning covers the main class's **package and sub-packages**, so keep it in the root package.
- Startup: `SpringApplication.run` → load properties/profiles → create the context → scan + auto-configure beans → start the embedded server → run `CommandLineRunner`s → `ApplicationReadyEvent`.

## IoC & Dependency Injection
> **What:** **Inversion of Control**: the Spring container creates objects (**beans**) and wires their dependencies, instead of classes creating them with `new`.
- **Constructor injection** (recommended): `final` fields, explicit dependencies, easy unit tests, no `@Autowired` needed with one constructor.
- **Field injection** (`@Autowired private X x`): short but hides dependencies and needs reflection in tests. **Setter injection**: optional dependencies.
- **Why DI**: loose coupling, swap implementations (interfaces), easy mocking, one shared configured instance.

## Stereotype Annotations
```text
@Component       generic Spring bean
@Service         business logic layer
@Repository      data access + DB exception translation
@Controller      MVC controller returning views
@RestController  @Controller + @ResponseBody (returns JSON)
@Configuration   class holding @Bean methods
```
- **@Component vs @Bean**: `@Component` on your class (found by scanning); `@Bean` method in a `@Configuration` class for third-party classes or custom construction.

## Choosing Between Beans
- Several beans of one type → `NoUniqueBeanDefinitionException`. Fix with **`@Primary`** (the default choice) or **`@Qualifier("name")`** (exact pick, wins over `@Primary`).
- Inject `List<T>` to get all beans of a type; `ObjectProvider<T>` for optional/lazy lookup.
- Circular dependencies fail at startup (since 2.6): redesign, or break with `@Lazy`.

## Bean Scopes & Lifecycle
- **singleton** (default): one instance per container, shared by all threads → keep it **stateless**.
- **prototype**: new instance each injection. **request** / **session** / **application**: web scopes (use proxies when injected into singletons).
- Lifecycle: instantiate → inject → `@PostConstruct` → ready → `@PreDestroy` on shutdown. `BeanPostProcessor`s wrap beans (that's where AOP proxies come from).

## Configuration & Profiles
- `application.properties` or `application.yml`: `server.port`, `spring.datasource.url`, `spring.jpa.*`, `logging.level.*`, your own `app.*` keys.
- **`@Value("${app.x:default}")`**: one value. **`@ConfigurationProperties(prefix = "app")`**: binds a whole group into a typed, validatable class/record → preferred for groups.
- **Profiles**: `application-dev.yml` loaded when `spring.profiles.active=dev`; `@Profile("dev")` beans.
- **Precedence** (later wins): files in the jar → external config files → environment variables (`SPRING_DATASOURCE_URL`) → `-D` system props → command-line args.

## REST Controllers
> **What:** `@RestController` classes map HTTP requests to methods and return objects serialised to JSON by Jackson.
- Mappings: `@GetMapping`, `@PostMapping`, `@PutMapping`, `@PatchMapping`, `@DeleteMapping` (on top of `@RequestMapping("/api/x")`).
- Inputs: `@PathVariable` (`/users/{id}`), `@RequestParam` (`?page=2`), `@RequestBody` (JSON body), `@RequestHeader`, `@CookieValue`, `MultipartFile`, `Pageable`.
- Output: return the object (200) or **`ResponseEntity<T>`** to control status and headers (`ResponseEntity.created(uri).body(x)`); `@ResponseStatus(HttpStatus.NO_CONTENT)`.
- **@Controller vs @RestController**: view names (server-side HTML) vs response body (APIs).

## HTTP Methods & Status Codes
```text
GET read · POST create · PUT replace · PATCH partial · DELETE
idempotent: GET PUT DELETE   safe: GET HEAD OPTIONS
200 OK  201 Created  204 No Content
400 Bad Request  401 Unauthorized  403 Forbidden
404 Not Found  409 Conflict  422 Unprocessable  429 Too Many
500 Server Error  502 Bad Gateway  503 Unavailable
```

## Validation
> **What:** **Jakarta Bean Validation** annotations on DTOs, checked automatically with `@Valid`.
- Common: `@NotNull`, `@NotBlank` (not null, not only spaces), `@NotEmpty`, `@Size`, `@Min`, `@Max`, `@Positive`, `@Email`, `@Pattern`, `@Past`, `@Future`; custom constraints with `ConstraintValidator`.
- **@Valid vs @Validated**: `@Valid` (Jakarta) validates and cascades into nested objects; `@Validated` (Spring) adds **groups** and **method validation** on services.
- A failed `@Valid @RequestBody` → `MethodArgumentNotValidException` → 400.

## Global Error Handling
> **What:** a `@RestControllerAdvice` class with `@ExceptionHandler` methods turns exceptions into consistent HTTP responses for all controllers.
- Return **`ProblemDetail`** (RFC 9457 JSON: `type`, `title`, `status`, `detail`, `instance`) or a `ResponseEntity`.
- **vs try/catch in every controller**: one place, consistent error format, cleaner controllers.
- **Tricky**: with `spring.mvc.problemdetails.enabled=true`, Boot's own handler catches MVC exceptions first; extend `ResponseEntityExceptionHandler` and override `handleMethodArgumentNotValid` to customise validation errors. Exceptions thrown in **filters** (incl. Spring Security) never reach `@ControllerAdvice`.

## JPA, Hibernate & Spring Data JPA
- **JPA**: the Java standard (specification) for mapping objects to tables. **Hibernate**: the most used JPA implementation (the ORM). **Spring Data JPA**: generates repository implementations on top of JPA.
- **ORM vs JDBC**: work with objects, automatic SQL, caching, dirty checking, less boilerplate; JDBC/`JdbcClient` gives full SQL control and speed for complex queries.
- Entity annotations: `@Entity`, `@Table`, `@Id`, `@GeneratedValue` (IDENTITY, SEQUENCE), `@Column`, `@Enumerated(EnumType.STRING)`, `@Version` (optimistic lock), `@Transient`.

## Entity Relationships
- `@OneToMany(mappedBy = "x")` / `@ManyToOne` (the **owning side** holds the FK, `@JoinColumn`), `@OneToOne`, `@ManyToMany` (+ `@JoinTable`).
- **Fetch types**: LAZY (load when accessed) vs EAGER (load immediately). Defaults: `@ManyToOne`/`@OneToOne` EAGER, collections LAZY → set everything LAZY.
- **Cascade** (`PERSIST`, `MERGE`, `REMOVE`, `ALL`) passes operations to children; `orphanRemoval` deletes children removed from the collection.
- Entity states: transient → **managed** (changes auto-saved: dirty checking) → detached → removed.

## Spring Data Repositories
> **What:** declare an interface `extends JpaRepository<Product, Long>` and Spring generates the implementation.
- Built-in: `save`, `findById`, `findAll`, `findAll(Pageable)`, `deleteById`, `count`, `existsById`, `saveAndFlush`.
- **Derived queries** from method names: `findByNameContainingIgnoreCase`, `findByPriceBetween`, `findTop3ByOrderByPriceDesc`, `countByStatus`.
- **@Query**: JPQL (entity names) or `nativeQuery = true` (SQL); `@Modifying` for update/delete. **Projections**: interface or record DTOs with only needed columns.
- **CrudRepository vs JpaRepository**: basic CRUD vs + paging/sorting, flush, batch operations.

## @Transactional
> **What:** wraps a method in a database transaction through a **proxy**: commit on success, rollback on failure.
- Rolls back on **unchecked** exceptions (RuntimeException, Error) only; add `rollbackFor = Exception.class` for checked ones.
- **Propagation**: `REQUIRED` (default: join or create) · `REQUIRES_NEW` (always a new, independent one) · `NESTED` (savepoint) · `MANDATORY` · `SUPPORTS` · `NEVER`.
- `readOnly = true` for queries (no dirty checking). Put it on **service** methods.
- **Doesn't work** for: self-invocation (`this.method()`), `private` methods, objects created with `new`, exceptions caught and swallowed inside.

## N+1 Problem & Lazy Loading
> **What:** 1 query loads N parents, then N more queries load each parent's lazy children = N+1 queries.
- Fix: `JOIN FETCH` in JPQL, `@EntityGraph`, batch fetching (`hibernate.default_batch_fetch_size`), or DTO projections.
- **LazyInitializationException**: accessing a lazy field after the transaction closed. Fetch what you need inside the transaction; set `spring.jpa.open-in-view=false` so it isn't hidden.
- `ddl-auto`: `validate` in production + **Flyway/Liquibase** migrations; `update`/`create-drop` only for demos/tests.

## Spring Security
> **What:** a chain of **servlet filters** in front of your app that handles **authentication** (who are you) and **authorisation** (what may you do).
- Configure a `SecurityFilterChain` bean: `authorizeHttpRequests(...)` rules (`permitAll`, `hasRole("ADMIN")`, `authenticated()`), `httpBasic`, `formLogin`, `oauth2ResourceServer(jwt)`, `csrf`, `cors`, session policy.
- Flow: request → filters → `AuthenticationManager` → `UserDetailsService` + `PasswordEncoder` → `SecurityContextHolder`.
- **401** = not authenticated; **403** = authenticated but not allowed. Method security: `@PreAuthorize("hasRole('ADMIN')")` with `@EnableMethodSecurity`.
- Passwords: store **BCrypt/Argon2 hashes** only (`PasswordEncoder`).

## JWT vs Sessions, CSRF & CORS
- **Session**: server stores login state, browser sends a cookie. **JWT**: signed token carrying claims, sent in `Authorization: Bearer`; stateless, scales across services; hard to revoke before expiry.
- **OAuth2 / OIDC**: delegated login via an authorisation server (Keycloak, Okta, Google); Boot app acts as a **resource server** validating JWTs.
- **CSRF**: attack using the browser's automatic cookies. Keep protection for cookie sessions; disable for stateless token APIs.
- **CORS**: browser rule blocking calls to another origin unless the server allows it (`allowedOrigins`); enable it in the security chain too.

## Testing
- **Unit tests**: JUnit 5 + Mockito (`@Mock`, `@InjectMocks`, `when(...).thenReturn`, `verify`), no Spring context: fastest.
- **Slices**: `@WebMvcTest` (controllers + MockMvc), `@DataJpaTest` (repositories + embedded DB, rollback), `@JsonTest`, `@RestClientTest`.
- **@SpringBootTest**: full application context (integration tests); with Testcontainers + `@ServiceConnection` for a real database.
- **@Mock vs @MockitoBean**: plain Mockito mock vs replaces a bean in the Spring context (`@MockBean` was removed in Boot 4).
- With Spring Security on the classpath, slice tests are secured: use `@WithMockUser` and `.with(csrf())`.

## Actuator & Observability
> **What:** production endpoints under `/actuator`: `health` (UP/DOWN, liveness/readiness for Kubernetes), `info`, `metrics`, `prometheus`, `loggers`, `env`, `beans`, `mappings`, `threaddump`.
- Only `health` is exposed by default; expose more with `management.endpoints.web.exposure.include`, secure the rest.
- **Metrics**: Micrometer (counters, timers) → Prometheus/Grafana. **Tracing**: Micrometer Tracing + OpenTelemetry → Zipkin/Jaeger, trace IDs in logs.
- **Liveness vs readiness**: "restart me" (don't check the DB) vs "send me traffic" (check dependencies).

## Logging
- SLF4J API + Logback by default. Levels: TRACE < DEBUG < INFO < WARN < ERROR; set with `logging.level.com.acme=DEBUG`.
- Use placeholders `log.info("Order {}", id)` (no string building when disabled); pass the exception last to keep the stack trace.
- **MDC** adds request IDs to every line; JSON structured logs: `logging.structured.format.console=ecs` (3.4+).

## Async, Scheduling & Caching
- **@Async** (+ `@EnableAsync`): run a method on another thread, return `CompletableFuture`. **Virtual threads**: `spring.threads.virtual.enabled=true`.
- **@Scheduled** (+ `@EnableScheduling`): `fixedRate`, `fixedDelay`, `cron = "0 0 2 * * MON-FRI"`. In a cluster every instance runs it (use ShedLock).
- **Caching** (+ `@EnableCaching`): `@Cacheable` (skip method on hit), `@CachePut` (always run, update), `@CacheEvict` (remove). Providers: Caffeine, Redis.
- All of these use **proxies**: self-invocation and private methods are ignored, like `@Transactional`.

## Calling Other Services
```text
RestTemplate     old synchronous template (maintenance mode)
RestClient       modern fluent synchronous client (Boot 3.2+)
WebClient        reactive, non-blocking (WebFlux)
@HttpExchange    declarative interface client (Spring 6/7)
OpenFeign        declarative client from Spring Cloud
Kafka / RabbitMQ asynchronous messaging, decoupled
```
- Always set timeouts; add retries (`@Retryable` in Spring 7 core, or Resilience4j) and circuit breakers for remote calls.
- **Sync vs async messaging**: REST is simple and immediate but couples availability; messaging decouples services and absorbs load spikes but adds eventual consistency.

## AOP & Proxies
> **What:** **Aspect-Oriented Programming** adds cross-cutting behaviour (logging, transactions, security, caching) around methods without changing them.
- Terms: **aspect** (`@Aspect` class), **advice** (`@Before`, `@After`, `@AfterReturning`, `@AfterThrowing`, `@Around`), **pointcut** (which methods: `execution(* com.acme..*Service.*(..))`), **join point** (a method call).
- Spring AOP uses **proxies** (CGLIB subclass or JDK interface proxy): only **external calls to public methods** of Spring beans are intercepted. This is why self-calls skip `@Transactional`.
```java
@Service
class OrderService {
  public void place() { this.save(); }        // self-call: NO transaction
  @Transactional public void save() { }
}
```

## Microservices
> **What:** an application split into small, independently deployable services, each owning its data and doing one business capability.
- **vs monolith**: independent deploys and scaling, team autonomy, tech freedom; cost: network calls, distributed data, harder debugging and ops. Start with a modular monolith if unsure.
- Patterns: **API gateway**, **service discovery** (Eureka / Kubernetes DNS), **config server**, **circuit breaker**, **database per service**, **saga**, **outbox**, **CQRS**, **event-driven** communication.

## Spring Cloud Components
- **Eureka**: service registry (instances register, clients look up). **Spring Cloud LoadBalancer**: client-side load balancing (`@LoadBalanced`).
- **Config Server**: central configuration from Git (`spring.config.import=configserver:`).
- **Gateway**: single entry point: routing (`lb://order-service`), auth, rate limiting, CORS.
- **OpenFeign**: declarative REST clients. **Resilience4j**: circuit breaker, retry, rate limiter, bulkhead, time limiter.
- Release trains: 2025.0 ↔ Boot 3.5, 2025.1 ↔ Boot 4.0.

## Circuit Breaker
> **What:** stops calling a failing service after a failure threshold, fails fast with a **fallback**, then tests recovery.
- States: **CLOSED** (normal, counting failures) → **OPEN** (calls rejected immediately) → **HALF_OPEN** (a few trial calls) → back to CLOSED or OPEN.
- **Why**: prevents cascading failures and thread exhaustion when a dependency is down. Combine with **timeouts**, **retries with backoff** and **bulkheads**.

## Distributed Transactions
- **2PC** (two-phase commit): strong consistency but blocking, slow, poorly supported across services.
- **Saga**: a sequence of local transactions with **compensating actions** on failure. **Choreography** (services react to events) vs **orchestration** (a coordinator tells each step).
- **Transactional outbox**: write the event to an outbox table in the same local transaction, then publish it to Kafka: no lost or phantom events. Consumers must be **idempotent**.

## Deployment
- Executable jar (`java -jar`), container image (`./mvnw spring-boot:build-image` or a Dockerfile), GraalVM native image (fast start, low memory).
- Kubernetes: liveness/readiness probes from Actuator, config via ConfigMaps/Secrets (env vars), graceful shutdown (default since 3.4), horizontal scaling of stateless instances.

## Boot Versions
- **2.x**: `javax.*`, Java 8+ (end of life). **3.0** (2022): Java 17, Spring 6, **`jakarta.*`** packages, Micrometer tracing, native images, ProblemDetail.
- **3.2**: virtual threads, `RestClient`, `JdbcClient`. **3.4**: structured logging, `@MockitoBean`.
- **4.0** (Nov 2025): Spring 7, Jakarta EE 11, Jackson 3, modular starters, **API versioning**, HTTP service clients, `@Retryable` in core, `@MockBean` removed. Current: 4.1.1.

## Common Pitfalls
- Main class not in the root package → beans not found.
- `@Transactional`/`@Async`/`@Cacheable` on private or self-called methods → silently ignored.
- Mutable fields in singleton beans → data shared between users' requests.
- Catching an exception inside `@Transactional` without rethrowing → the transaction commits.
- Returning JPA entities from APIs → lazy-loading errors, infinite JSON recursion: return DTOs.
- `ddl-auto=update` in production, HTTP clients without timeouts, secrets committed to Git.

## Interview One-Liners
- **Spring vs Spring Boot**: framework vs auto-configured, runnable apps.
- **IoC / DI**: the container creates and injects dependencies.
- **@Component vs @Bean**: scanned class vs factory method.
- **@Primary vs @Qualifier**: default choice vs exact choice.
- **@Controller vs @RestController**: views vs JSON body.
- **JPA vs Hibernate vs Spring Data**: spec vs implementation vs repository abstraction.
- **save vs saveAndFlush**: SQL at commit vs SQL immediately.
- **REQUIRED vs REQUIRES_NEW**: join vs new independent transaction.
- **401 vs 403**: not logged in vs not allowed.
- **Monolith vs microservices**: one deployable vs many independent services.

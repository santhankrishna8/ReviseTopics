# 14 | Binary Trees | Tree vocabulary, DFS traversals (preorder, inorder, postorder) recursive and iterative, BFS level order, the "solve left, solve right, combine" recursion, height, diameter, balanced, path sum, lowest common ancestor, max path sum, build from traversals, serialize | Binary Trees

## The Idea
> A tree is a **family tree turned upside down**: one **root** at the top, each node has up to two **children** (left, right), and no node has more than one parent. A node with no children is a **leaf**.
```java TreeNode.java
class TreeNode {
  int val;
  TreeNode left, right;
  TreeNode() {}
  TreeNode(int val) { this.val = val; }
  TreeNode(int val, TreeNode left, TreeNode right) { this.val = val; this.left = left; this.right = right; }
}
```
- **Depth** of a node = edges from the root to it. **Height** of a node = edges down to its deepest leaf. (LeetCode "max depth" counts **nodes**, so an empty tree is 0 and one node is 1.)
- A tree with `n` nodes has `n - 1` edges. A **balanced** tree has height about `log2 n`; a **skewed** one (a linked list in disguise) has height `n`.
- **Binary** tree: at most 2 children. **Full**: every node has 0 or 2 children. **Complete**: every level full except maybe the last, filled left to right (heaps). **Perfect**: all leaves on one level, `2^h - 1` nodes.
! Almost every tree problem is recursion: solve the left subtree, solve the right subtree, combine at the node.

## The Four Traversals
```text
        1
       / \
      2   3        preorder  (node, left, right):  1 2 4 5 3
     / \          inorder   (left, node, right):  4 2 5 1 3
    4   5         postorder (left, right, node):  4 5 2 3 1
                  level order (BFS, by level):    1 | 2 3 | 4 5
```
- **DFS** (go deep first): preorder, inorder, postorder. They differ only in **when you handle the node**: before the children (pre), between them (in), after them (post).
- **BFS** (level order): uses a **queue**, visits level by level.
- Remember **P**re = node **P**rior, **I**n = node **I**n the middle, **P**ost = node **P**ost (last).
- Preorder: copy or serialize a tree. Inorder: **sorted order for a BST**. Postorder: compute something from the children first (height, size, delete a tree).
```java Traversals.java
class Solution {
  public List<Integer> preorder(TreeNode root) { List<Integer> out = new ArrayList<>(); pre(root, out); return out; }
  private void pre(TreeNode n, List<Integer> out) {      // LeetCode 144
    if (n == null) return;
    out.add(n.val); pre(n.left, out); pre(n.right, out);
  }
  public List<Integer> inorder(TreeNode root) {           // LeetCode 94, iterative with an explicit stack
    List<Integer> out = new ArrayList<>();
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !st.isEmpty()) {
      while (cur != null) { st.push(cur); cur = cur.left; }   // dive as far left as possible
      cur = st.pop();
      out.add(cur.val);                                       // visit between left and right
      cur = cur.right;
    }
    return out;
  }
  public List<Integer> iterativePreorder(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> st = new ArrayDeque<>();
    st.push(root);
    while (!st.isEmpty()) {
      TreeNode n = st.pop();
      out.add(n.val);
      if (n.right != null) st.push(n.right);                  // right first so left is popped first
      if (n.left != null) st.push(n.left);
    }
    return out;
  }
  public List<Integer> postorder(TreeNode root) {         // LeetCode 145: reverse of (node, right, left)
    LinkedList<Integer> out = new LinkedList<>();
    if (root == null) return out;
    Deque<TreeNode> st = new ArrayDeque<>();
    st.push(root);
    while (!st.isEmpty()) {
      TreeNode n = st.pop();
      out.addFirst(n.val);
      if (n.left != null) st.push(n.left);
      if (n.right != null) st.push(n.right);
    }
    return out;
  }
}
```

## BFS: Level Order (the queue template)
> Freeze `size = queue.size()` at the start of each level. Process exactly that many nodes; their children form the next level.
```java LevelOrder.java
class Solution {
  public List<List<Integer>> levelOrder(TreeNode root) {  // LeetCode 102
    List<List<Integer>> out = new ArrayList<>();
    if (root == null) return out;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
      int size = q.size();                                // exactly this level's nodes
      List<Integer> level = new ArrayList<>();
      for (int i = 0; i < size; i++) {
        TreeNode n = q.poll();
        level.add(n.val);
        if (n.left != null) q.offer(n.left);
        if (n.right != null) q.offer(n.right);
      }
      out.add(level);
    }
    return out;
  }
  public List<Integer> rightSideView(TreeNode root) {     // LeetCode 199: last node of each level
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
      int size = q.size();
      for (int i = 0; i < size; i++) {
        TreeNode n = q.poll();
        if (i == size - 1) out.add(n.val);
        if (n.left != null) q.offer(n.left);
        if (n.right != null) q.offer(n.right);
      }
    }
    return out;
  }
  public List<List<Integer>> zigzagLevelOrder(TreeNode root) {   // LeetCode 103
    List<List<Integer>> out = levelOrder(root);
    for (int i = 1; i < out.size(); i += 2) Collections.reverse(out.get(i));   // flip every second level
    return out;
  }
}
```

## The Recursion Pattern: Solve Left, Solve Right, Combine
> For every tree problem ask two questions: **(1) what is the answer for an empty tree (base case)?** **(2) given the answers for the left and right subtrees, how do I get the answer for this node?**
```java SimpleRecursion.java
class Solution {
  public int maxDepth(TreeNode n) {                       // LeetCode 104
    if (n == null) return 0;
    return 1 + Math.max(maxDepth(n.left), maxDepth(n.right));
  }
  public int minDepth(TreeNode n) {                       // LeetCode 111: depth to the nearest LEAF
    if (n == null) return 0;
    if (n.left == null) return 1 + minDepth(n.right);     // a missing child is not a leaf: go the other way
    if (n.right == null) return 1 + minDepth(n.left);
    return 1 + Math.min(minDepth(n.left), minDepth(n.right));
  }
  public TreeNode invertTree(TreeNode n) {                // LeetCode 226
    if (n == null) return null;
    TreeNode left = invertTree(n.left), right = invertTree(n.right);
    n.left = right; n.right = left;
    return n;
  }
  public boolean isSameTree(TreeNode a, TreeNode b) {     // LeetCode 100
    if (a == null || b == null) return a == b;            // both null: same. One null: different.
    return a.val == b.val && isSameTree(a.left, b.left) && isSameTree(a.right, b.right);
  }
  public boolean isSymmetric(TreeNode root) {             // LeetCode 101: a mirror of itself
    return root == null || mirror(root.left, root.right);
  }
  private boolean mirror(TreeNode a, TreeNode b) {
    if (a == null || b == null) return a == b;
    return a.val == b.val && mirror(a.left, b.right) && mirror(a.right, b.left);   // outer with outer, inner with inner
  }
  public boolean hasPathSum(TreeNode n, int target) {     // LeetCode 112: root-to-leaf path
    if (n == null) return false;
    if (n.left == null && n.right == null) return n.val == target;
    return hasPathSum(n.left, target - n.val) || hasPathSum(n.right, target - n.val);
  }
}
```

## The Global-Variable Pattern (answer bends at a node)
> Some answers are **paths that bend** at a node (they use both children), but a function can only **return** a path that goes up through **one** child. So: **return** the one-sided value to the parent, and **update a global best** with the two-sided value.
```java Diameter.java
class Solution {
  private int best;
  public int diameterOfBinaryTree(TreeNode root) {        // LeetCode 543: longest path in EDGES between two nodes
    best = 0;
    height(root);
    return best;
  }
  private int height(TreeNode n) {
    if (n == null) return 0;
    int l = height(n.left), r = height(n.right);
    best = Math.max(best, l + r);                         // path bending at n uses both sides
    return 1 + Math.max(l, r);                            // the parent can only extend one side
  }
}
```
```java Balanced.java
class Solution {
  public boolean isBalanced(TreeNode root) { return check(root) != -1; }   // LeetCode 110
  private int check(TreeNode n) {                          // height, or -1 as soon as any subtree is unbalanced
    if (n == null) return 0;
    int l = check(n.left);  if (l == -1) return -1;
    int r = check(n.right); if (r == -1) return -1;
    return Math.abs(l - r) > 1 ? -1 : 1 + Math.max(l, r);
  }
}
```
```java MaxPathSum.java
class Solution {
  private int best;
  public int maxPathSum(TreeNode root) {                  // LeetCode 124: any node to any node, values can be negative
    best = Integer.MIN_VALUE;
    gain(root);
    return best;
  }
  private int gain(TreeNode n) {                          // best sum of a downward path starting at n
    if (n == null) return 0;
    int l = Math.max(0, gain(n.left)), r = Math.max(0, gain(n.right));   // drop negative branches
    best = Math.max(best, n.val + l + r);                 // path that bends here
    return n.val + Math.max(l, r);
  }
}
```
! Return one side up to the parent. Record the bend (both sides) in a global.

## Lowest Common Ancestor
> Search both sides. If **one side finds p and the other finds q**, this node is the split point = the LCA. If only one side returns something, pass it up.
```java LCA.java
class Solution {
  public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {   // LeetCode 236
    if (root == null || root == p || root == q) return root;
    TreeNode left = lowestCommonAncestor(root.left, p, q);
    TreeNode right = lowestCommonAncestor(root.right, p, q);
    if (left != null && right != null) return root;       // p and q are on different sides
    return left != null ? left : right;
  }
}
```

## Build From Traversals and Serialize
> **Preorder** tells you the root first. **Inorder** tells you how many nodes are in the left subtree (everything before the root's position). Recurse with those sizes.
```java BuildTree.java
class Solution {
  public TreeNode buildTree(int[] preorder, int[] inorder) {   // LeetCode 105
    Map<Integer, Integer> pos = new HashMap<>();               // value -> index in inorder
    for (int i = 0; i < inorder.length; i++) pos.put(inorder[i], i);
    return build(preorder, 0, 0, inorder.length - 1, pos);
  }
  // preIdx: where this subtree's root sits in preorder; [lo, hi]: its range in inorder
  private TreeNode build(int[] pre, int preIdx, int lo, int hi, Map<Integer, Integer> pos) {
    if (lo > hi) return null;
    TreeNode root = new TreeNode(pre[preIdx]);
    int mid = pos.get(pre[preIdx]);
    root.left = build(pre, preIdx + 1, lo, mid - 1, pos);
    root.right = build(pre, preIdx + 1 + (mid - lo), mid + 1, hi, pos);   // skip the left subtree's nodes
    return root;
  }
}
```
```java Codec.java
class Codec {                                                  // LeetCode 297: preorder with "#" for null
  public String serialize(TreeNode root) { StringBuilder sb = new StringBuilder(); write(root, sb); return sb.toString(); }
  private void write(TreeNode n, StringBuilder sb) {
    if (n == null) { sb.append("#,"); return; }
    sb.append(n.val).append(',');
    write(n.left, sb);
    write(n.right, sb);
  }
  public TreeNode deserialize(String data) { return read(new ArrayDeque<>(Arrays.asList(data.split(",")))); }
  private TreeNode read(Deque<String> tokens) {
    String t = tokens.poll();
    if (t.equals("#")) return null;
    TreeNode n = new TreeNode(Integer.parseInt(t));
    n.left = read(tokens);
    n.right = read(tokens);
    return n;
  }
}
```

## Complexity of Tree Algorithms
- Visiting every node once: **O(n)** time.
- **Space** = recursion depth = the tree **height h**: O(log n) balanced, **O(n) skewed**. BFS space = the widest level (up to n/2).
- For deep trees (100,000 nodes in a chain) recursion can overflow the stack: use an iterative DFS with an explicit stack.

## Common Mistakes
- Mixing up node counts and edge counts (depth, diameter).
- `minDepth`: forgetting that a node with one child is **not** a leaf.
- Reading `n.left.val` without a null check.
- Using a global variable but forgetting to reset it between calls (fine on LeetCode per test, risky in real code).
- Level order: reading `q.size()` inside the loop condition instead of freezing it before.

## Explain It Like This
> "I'll solve it recursively. The height of a node is one plus the larger height of its children, and an empty tree has height 0. While computing heights I also track the longest left-plus-right path seen at any node. That is the diameter. One pass, O(n) time, O(h) stack space."

## Interview Q&A
Q*: What are the types of tree traversal?
A: Depth-first: preorder (node, left, right), inorder (left, node, right) and postorder (left, right, node). Breadth-first: level order using a queue. Inorder of a BST gives sorted order.
Q*: How do you find the height of a binary tree?
A: Recursively: an empty tree has height 0 (or -1 counting edges), otherwise one plus the larger of the children's heights. O(n) time and O(h) stack space.
Q*: How do you do level-order traversal?
A: BFS with a queue. At the start of each level record the queue size, process exactly that many nodes while enqueuing their children, and collect them as one level.
Q: How do you find the lowest common ancestor in a binary tree?
A: Recurse into both children. If both return a non-null node, the current node is the split point and the LCA; otherwise return whichever side is non-null. O(n).
Q: What is the time and space complexity of tree recursion?
A: O(n) time to visit each node once. Space is the recursion depth, O(h): O(log n) for a balanced tree and O(n) for a skewed one.
Q: How do you compute the diameter in one pass?
A: Compute heights bottom up. At each node the longest path through it is left height plus right height; keep the maximum in a variable and return 1 plus the larger height to the parent.

# 15 | Binary Search Tree (BST) | The BST rule and why inorder is sorted, search/insert/delete (three delete cases), validating with bounds, kth smallest, LCA in a BST, sorted array to balanced BST, BST iterator, balanced trees (AVL, red-black) and Java's TreeMap | Binary Search Tree

## The Idea
> A BST is a binary tree with a **sorting rule**: for every node, **everything in the left subtree is smaller and everything in the right subtree is larger**. Like a decision tree for "higher or lower?": each comparison throws away a whole subtree.
- **Search / insert / delete** walk one path from the root: **O(h)**, where h is the height. Balanced: **O(log n)**. Sorted input inserted one by one makes a **skewed** tree: O(n).
- **Inorder traversal visits values in sorted order.** This one fact solves half of all BST questions.
- Duplicates: LeetCode BSTs usually have **distinct** values. (Real implementations decide: reject, count, or always go right.)
! BST = binary tree + "left < node < right" everywhere, not just between parent and child.

## Search and Insert
```java BstBasics.java
class Solution {
  public TreeNode searchBST(TreeNode root, int val) {     // LeetCode 700
    while (root != null && root.val != val) root = val < root.val ? root.left : root.right;
    return root;
  }
  public TreeNode insertIntoBST(TreeNode root, int val) { // LeetCode 701
    if (root == null) return new TreeNode(val);           // found the empty spot
    if (val < root.val) root.left = insertIntoBST(root.left, val);
    else root.right = insertIntoBST(root.right, val);
    return root;
  }
}
```

## Delete: Three Cases
- **Leaf**: just remove it.
- **One child**: replace the node with its child.
- **Two children**: replace its value with the **inorder successor** (the smallest node in the right subtree), then delete that successor from the right subtree. (The inorder predecessor works too.)
```java BstDelete.java
class Solution {
  public TreeNode deleteNode(TreeNode root, int key) {    // LeetCode 450
    if (root == null) return null;
    if (key < root.val) root.left = deleteNode(root.left, key);
    else if (key > root.val) root.right = deleteNode(root.right, key);
    else {
      if (root.left == null) return root.right;           // 0 or 1 child: splice the node out
      if (root.right == null) return root.left;
      TreeNode succ = root.right;                         // 2 children: successor = leftmost of right subtree
      while (succ.left != null) succ = succ.left;
      root.val = succ.val;
      root.right = deleteNode(root.right, succ.val);      // remove the successor node instead
    }
    return root;
  }
}
```

## Validate a BST (the classic trap)
> Checking only `left.val < node.val < right.val` is **wrong**: a node deep in the left subtree can still be bigger than the root. Pass **down a valid range** `(lo, hi)`: going left tightens `hi`, going right tightens `lo`.
```java ValidateBst.java
class Solution {
  public boolean isValidBST(TreeNode root) { return valid(root, Long.MIN_VALUE, Long.MAX_VALUE); }   // LeetCode 98
  private boolean valid(TreeNode n, long lo, long hi) {   // long bounds: node values can be Integer.MIN_VALUE
    if (n == null) return true;
    if (n.val <= lo || n.val >= hi) return false;         // strict: no duplicates
    return valid(n.left, lo, n.val) && valid(n.right, n.val, hi);
  }
}
```
- Equivalent check: the **inorder traversal must be strictly increasing**.

## Using Inorder: Kth Smallest, Min Difference, BST Iterator
```java InorderTricks.java
class Solution {
  public int kthSmallest(TreeNode root, int k) {          // LeetCode 230: stop after k nodes of the inorder walk
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !st.isEmpty()) {
      while (cur != null) { st.push(cur); cur = cur.left; }
      cur = st.pop();
      if (--k == 0) return cur.val;
      cur = cur.right;
    }
    throw new IllegalArgumentException("k is larger than the tree");
  }
  private Integer prev;
  private int minDiff;
  public int getMinimumDifference(TreeNode root) {        // LeetCode 530: the closest pair is always inorder neighbours
    prev = null; minDiff = Integer.MAX_VALUE;
    walk(root);
    return minDiff;
  }
  private void walk(TreeNode n) {
    if (n == null) return;
    walk(n.left);
    if (prev != null) minDiff = Math.min(minDiff, n.val - prev);
    prev = n.val;
    walk(n.right);
  }
}
```
```java BstIterator.java
class BSTIterator {                                       // LeetCode 173: next() in amortized O(1), O(h) memory
  private final Deque<TreeNode> st = new ArrayDeque<>();
  BSTIterator(TreeNode root) { pushLeft(root); }
  int next() { TreeNode n = st.pop(); pushLeft(n.right); return n.val; }
  boolean hasNext() { return !st.isEmpty(); }
  private void pushLeft(TreeNode n) { for (; n != null; n = n.left) st.push(n); }
}
```

## Using the BST Rule: LCA, Range Sum, Trim
```java BstRule.java
class Solution {
  public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {   // LeetCode 235
    while (root != null) {
      if (p.val < root.val && q.val < root.val) root = root.left;     // both smaller: go left
      else if (p.val > root.val && q.val > root.val) root = root.right;
      else return root;                                               // they split here (or one equals root)
    }
    return null;
  }
  public int rangeSumBST(TreeNode n, int lo, int hi) {    // LeetCode 938: skip subtrees that cannot match
    if (n == null) return 0;
    if (n.val < lo) return rangeSumBST(n.right, lo, hi);
    if (n.val > hi) return rangeSumBST(n.left, lo, hi);
    return n.val + rangeSumBST(n.left, lo, hi) + rangeSumBST(n.right, lo, hi);
  }
  public TreeNode trimBST(TreeNode root, int low, int high) {     // LeetCode 669
    if (root == null) return null;
    if (root.val < low) return trimBST(root.right, low, high);    // root and its left subtree are too small
    if (root.val > high) return trimBST(root.left, low, high);
    root.left = trimBST(root.left, low, high);
    root.right = trimBST(root.right, low, high);
    return root;
  }
}
```

## Build a Balanced BST, and Reverse Inorder
```java BstBuild.java
class Solution {
  public TreeNode sortedArrayToBST(int[] a) { return build(a, 0, a.length - 1); }   // LeetCode 108
  private TreeNode build(int[] a, int lo, int hi) {       // the middle becomes the root: height stays log n
    if (lo > hi) return null;
    int mid = lo + (hi - lo) / 2;
    TreeNode n = new TreeNode(a[mid]);
    n.left = build(a, lo, mid - 1);
    n.right = build(a, mid + 1, hi);
    return n;
  }
  private int sum = 0;
  public TreeNode convertBST(TreeNode root) {             // LeetCode 538: each node becomes the sum of all >= it
    if (root == null) return null;
    convertBST(root.right);                               // reverse inorder: biggest first
    sum += root.val;
    root.val = sum;
    convertBST(root.left);
    return root;
  }
}
```

## Self-Balancing Trees (know the names)
- A plain BST can degrade to a linked list. **Self-balancing** trees fix this with **rotations** after inserts and deletes, keeping height O(log n).
- **AVL tree**: strictly balanced (child heights differ by at most 1). Faster lookups, more rotations on writes.
- **Red-black tree**: looser balance (colour rules), fewer rotations. Used by Java's **`TreeMap`/`TreeSet`** and by `HashMap` buckets that treeify (sheet 04).
- **B-tree / B+ tree**: many keys per node, used by **databases** and file systems to minimise disk reads.
- In interviews you rarely code a rotation. Say: "I'd use `TreeMap` (a red-black tree) for O(log n) ordered operations."

## Common Mistakes
- Validating only parent-child (not the whole range). Use bounds or inorder.
- Using `int` bounds when a node can hold `Integer.MIN_VALUE` or `MAX_VALUE`. Use `long`.
- Forgetting that inserting sorted data gives a skewed tree.
- Delete with two children: copying the successor's value but not deleting the successor node.

## Explain It Like This
> "Because it's a BST, an inorder traversal visits values in sorted order. So the kth smallest is the kth node I visit; I walk iteratively with a stack and stop at k. That's O(h + k) time and O(h) space."

## Interview Q&A
Q*: What is a binary search tree?
A: A binary tree where every node's left subtree holds smaller values and its right subtree holds larger values. This allows search, insert and delete in O(h) time: O(log n) when balanced.
Q*: What does inorder traversal of a BST give?
A: The values in sorted ascending order. That is why kth smallest, validation, and nearest-value problems use inorder.
Q*: How do you validate a BST?
A: Recurse with a valid range for each node (lo, hi): going left sets hi to the node's value, going right sets lo to it. Checking only a node against its direct children is wrong. Alternatively verify the inorder sequence is strictly increasing.
Q: How do you delete a node from a BST?
A: If it has no child, remove it. With one child, replace it by that child. With two, copy the value of its inorder successor (smallest in the right subtree) into it, then delete the successor from the right subtree.
Q: What is the worst case for a BST and how do you avoid it?
A: Inserting sorted data produces a chain of height n, so operations become O(n). Self-balancing trees such as AVL or red-black trees rebalance with rotations to keep the height O(log n); Java's TreeMap is a red-black tree.
Q: BST vs hash map?
A: A hash map gives O(1) average lookup but no ordering. A BST (TreeMap) gives O(log n) operations plus ordered operations: min, max, floor, ceiling, range queries and sorted iteration.

# 16 | Heap & Priority Queue | What a heap is, array layout and the index formulas, sift up and sift down, building a heap in O(n), Java PriorityQueue, the top-K pattern, merge K sorted lists, two heaps for the running median, task scheduling and greedy heap problems | Heap

## The Idea
> A heap is a **tournament bracket where the winner is always on top**. You cannot see the full ranking, but you can always grab the best element instantly, and fixing the bracket after removing it is cheap.
- **Min-heap**: the **smallest** element is at the root. **Max-heap**: the largest.
- A heap is a **complete binary tree** (every level full except maybe the last, filled left to right), where **every parent is <= its children** (min-heap). It does **not** keep siblings sorted.
- Because it is complete, it is stored in a plain **array**: no node objects. For index `i`: **parent = (i - 1) / 2**, **left child = 2i + 1**, **right child = 2i + 2**.
```text
min-heap as a tree           as an array
        1                    index: 0  1  2  3  4  5
       / \                   value: 1  3  2  7  4  5
      3   2                  children of index 1: indexes 3 and 4
     / \  /
    7  4 5
```
```text
operation                time      how
peek (min)               O(1)      a[0]
offer (insert)           O(log n)  add at the end, sift UP while smaller than its parent
poll (remove min)        O(log n)  move the last item to the root, sift DOWN
build from n items       O(n)      heapify: sift down every non-leaf, bottom up
search / remove(Object)  O(n)      a heap is not built for lookups
```
! Heap = instant access to the min (or max) + O(log n) updates. Use it when the question keeps asking for "the best remaining".

## A Min-Heap From Scratch
```java MinHeap.java
class MinHeap {
  private int[] a;
  private int size;

  MinHeap() { a = new int[16]; }
  MinHeap(int[] values) {                              // heapify: O(n), not O(n log n)
    a = Arrays.copyOf(values, Math.max(16, values.length));
    size = values.length;
    for (int i = size / 2 - 1; i >= 0; i--) siftDown(i);   // leaves are already valid heaps
  }
  int peek() { return a[0]; }
  int size() { return size; }
  boolean isEmpty() { return size == 0; }

  void offer(int x) {
    if (size == a.length) a = Arrays.copyOf(a, size * 2);
    a[size] = x;
    siftUp(size++);
  }
  int poll() {
    int top = a[0];
    a[0] = a[--size];                                  // move the last item to the root ...
    siftDown(0);                                       // ... and let it sink to where it belongs
    return top;
  }
  private void siftUp(int i) {
    while (i > 0) {
      int p = (i - 1) / 2;
      if (a[p] <= a[i]) break;
      swap(p, i);
      i = p;
    }
  }
  private void siftDown(int i) {
    while (true) {
      int l = 2 * i + 1, r = l + 1, smallest = i;
      if (l < size && a[l] < a[smallest]) smallest = l;
      if (r < size && a[r] < a[smallest]) smallest = r;
      if (smallest == i) return;
      swap(i, smallest);
      i = smallest;
    }
  }
  private void swap(int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}
```
- **Why heapify is O(n)**: half the nodes are leaves (cost 0), a quarter sift down at most 1 level, an eighth at most 2 ... the sum n/4 + 2·n/8 + 3·n/16 ... converges to O(n).
- **Heap sort** = heapify, then `poll` n times: O(n log n), in place (with a max-heap), not stable.

## Java's PriorityQueue
```java PqApi.java
PriorityQueue<Integer> min = new PriorityQueue<>();                      // min-heap

min.offer(5); min.offer(1); min.offer(3);
System.out.println(min.peek() + " " + min.poll() + " " + min.size());    // 1 1 2

byDist.offer(new int[] {7, 30}); byDist.offer(new int[] {9, 10});
System.out.println(byDist.poll()[0]);                                    // 9

```
- `offer`, `poll` are O(log n). `peek` is O(1). `remove(Object)` and `contains` are **O(n)**.
- **Iterating or printing a PriorityQueue does not give sorted order.** Only repeated `poll()` does.
- There is **no decrease-key**. To "update" a priority, add a new entry and ignore the stale one when you pop it (lazy deletion). Dijkstra does exactly this (sheet 22).
- Use `Integer.compare`, not subtraction, in comparators.

## The Top-K Pattern (the heap's most asked job)
> To keep the **K largest** of a stream: use a **min-heap of size K**. Offer each item; if the size exceeds K, `poll` (that removes the smallest, which cannot be in the top K). At the end the heap holds the K largest, and its root is the **Kth largest**. Cost: **O(n log k)**, memory O(k). For K **smallest**, flip: a max-heap of size K.
```java TopK.java
class KthLargest {                                         // LeetCode 703: kth largest of a growing stream
  private final PriorityQueue<Integer> heap = new PriorityQueue<>();   // min-heap holding the k largest
  private final int k;
  KthLargest(int k, int[] nums) { this.k = k; for (int x : nums) add(x); }
  int add(int val) {
    heap.offer(val);
    if (heap.size() > k) heap.poll();                      // drop the smallest of the k+1
    return heap.peek();                                    // root = kth largest
  }
}
class Solution {
  public int[][] kClosest(int[][] points, int k) {         // LeetCode 973: k points closest to the origin
    PriorityQueue<int[]> farthestFirst = new PriorityQueue<>((a, b) -> Integer.compare(dist(b), dist(a)));
    for (int[] p : points) {
      farthestFirst.offer(p);
      if (farthestFirst.size() > k) farthestFirst.poll();  // drop the farthest
    }
    return farthestFirst.toArray(new int[0][]);
  }
  private static int dist(int[] p) { return p[0] * p[0] + p[1] * p[1]; }   // squared distance: no sqrt needed
  public int lastStoneWeight(int[] stones) {               // LeetCode 1046
    PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());
    for (int s : stones) pq.offer(s);
    while (pq.size() > 1) {
      int a = pq.poll(), b = pq.poll();
      if (a != b) pq.offer(a - b);                         // the smash leaves the difference
    }
    return pq.isEmpty() ? 0 : pq.peek();
  }
}
```
! Kth largest = min-heap of size k. Kth smallest = max-heap of size k. (Opposite of what feels natural.)

## Merge K Sorted Lists
> Put the **head of every list** in a min-heap. Poll the smallest, append it to the result, and push that node's `next`. The heap never holds more than K nodes: **O(N log K)** for N total nodes.
```java MergeK.java
class Solution {
  public ListNode mergeKLists(ListNode[] lists) {          // LeetCode 23
    PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> Integer.compare(a.val, b.val));
    for (ListNode l : lists) if (l != null) pq.offer(l);
    ListNode dummy = new ListNode(), tail = dummy;
    while (!pq.isEmpty()) {
      ListNode n = pq.poll();
      tail.next = n;
      tail = n;
      if (n.next != null) pq.offer(n.next);
    }
    return dummy.next;
  }
}
```

## Two Heaps: the Running Median
> Split the numbers into a **lower half** (max-heap, its top is the largest of the small ones) and an **upper half** (min-heap, its top is the smallest of the large ones). Keep their sizes equal (or lower half one bigger). The median is the top of the lower half, or the average of both tops.
```java MedianFinder.java
class MedianFinder {                                       // LeetCode 295: addNum O(log n), findMedian O(1)
  private final PriorityQueue<Integer> low = new PriorityQueue<>(Collections.reverseOrder());   // smaller half
  private final PriorityQueue<Integer> high = new PriorityQueue<>();                            // larger half
  void addNum(int num) {
    low.offer(num);
    high.offer(low.poll());                                // the biggest small one crosses to the large half
    if (high.size() > low.size()) low.offer(high.poll());  // rebalance: low is never smaller than high
  }
  double findMedian() {
    return low.size() > high.size() ? low.peek() : (low.peek() + (double) high.peek()) / 2;
  }
}
```

## Greedy With a Heap: Task Scheduler and Reorganize String
> "Always do the task with the **most remaining** work next" is greedy, and a max-heap supplies it. A task that was just used must **wait** (cooldown, or not adjacent), so hold it out for a round before pushing it back.
```java HeapGreedy.java
class Solution {
  public int leastInterval(char[] tasks, int n) {          // LeetCode 621: cooldown n between equal tasks
    int[] count = new int[26];
    for (char c : tasks) count[c - 'A']++;
    PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());
    for (int c : count) if (c > 0) pq.offer(c);
    int time = 0;
    while (!pq.isEmpty()) {
      List<Integer> cooling = new ArrayList<>();
      int slots = n + 1;                                   // one round: n + 1 time slots
      while (slots > 0 && !pq.isEmpty()) {
        int c = pq.poll();
        if (c > 1) cooling.add(c - 1);
        time++; slots--;
      }
      pq.addAll(cooling);
      if (!pq.isEmpty()) time += slots;                    // unused slots in a round are idle time
    }
    return time;
  }
  public int leastIntervalFormula(char[] tasks, int n) {   // same answer in O(n), no heap
    int[] count = new int[26];
    for (char c : tasks) count[c - 'A']++;
    int max = Arrays.stream(count).max().getAsInt();
    int withMax = (int) Arrays.stream(count).filter(c -> c == max).count();
    return Math.max(tasks.length, (max - 1) * (n + 1) + withMax);
  }
  public String reorganizeString(String s) {               // LeetCode 767: no two equal letters adjacent
    int[] count = new int[26];
    for (char c : s.toCharArray()) count[c - 'a']++;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(b[1], a[1]));   // {letter, remaining}
    for (int i = 0; i < 26; i++) if (count[i] > 0) pq.offer(new int[] {i, count[i]});
    StringBuilder sb = new StringBuilder();
    int[] prev = null;                                     // last letter used, held out for one step
    while (!pq.isEmpty()) {
      int[] cur = pq.poll();
      sb.append((char) ('a' + cur[0]));
      if (prev != null) pq.offer(prev);
      cur[1]--;
      prev = cur[1] > 0 ? cur : null;
    }
    return sb.length() == s.length() ? sb.toString() : "";   // impossible if one letter is too frequent
  }
}
```

## When to Reach for a Heap
- "**Top K** / Kth largest / Kth smallest / K most frequent / K closest".
- "Repeatedly take the **minimum or maximum** and update" (scheduling, merging, Huffman coding, Dijkstra).
- "**Median** of a stream", "merge K sorted ...".
- Compare: **sorting** is O(n log n) for everything; a **heap of size k** is O(n log k) and works on streams; **quickselect** is O(n) average for one Kth value.

## Common Mistakes
- Thinking a heap is sorted (printing a `PriorityQueue` shows heap order, not sorted order).
- Using `remove(x)` or `contains(x)` in a loop: O(n) each.
- Choosing the wrong heap type for top-K (use the **opposite** of what you want to keep).
- Comparators written as `a - b` (overflow), or forgetting that a mutable key changed **after** insertion breaks the heap.
- Offering `null` (not allowed).

## Explain It Like This
> "I need the K largest of n items. I keep a min-heap of size K: for each item I push it, and if the heap has more than K, I pop the smallest. At the end the heap holds the K largest. That's O(n log k) time and O(k) space, better than sorting when k is small."

## Interview Q&A
Q*: What is a heap and how is it stored?
A: A complete binary tree where every parent is smaller (min-heap) or larger (max-heap) than its children. Being complete, it is stored in an array: the children of index i are 2i + 1 and 2i + 2, and its parent is (i - 1) / 2.
Q*: Complexity of heap operations?
A: Peek is O(1); insert and remove-min are O(log n) because they sift along one root-to-leaf path; building a heap from n items is O(n); searching for an arbitrary element is O(n).
Q*: Why is building a heap O(n) and not O(n log n)?
A: Sifting down from the bottom up, most nodes are near the leaves and move only a level or two: n/4 nodes move at most 1, n/8 at most 2, and so on. The sum converges to O(n).
Q: How do you find the Kth largest element?
A: Keep a min-heap of size k while scanning: push each element and pop when the size exceeds k. The root is the kth largest. O(n log k) time, O(k) space. Quickselect does it in O(n) average.
Q: How do you maintain a running median?
A: Two heaps: a max-heap for the smaller half and a min-heap for the larger half, balanced so their sizes differ by at most one. The median is the top of the larger heap or the average of both tops. Insert is O(log n), median O(1).
Q: Heap vs sorted array vs BST for priority access?
A: A heap gives O(1) min and O(log n) insert/delete with a compact array. A sorted array has O(n) inserts. A balanced BST also has O(log n) but with higher constants and supports ordered traversal and arbitrary deletion, which a heap does not.

# 17 | Backtracking | The choose-explore-undo template, the decision tree, subsets, permutations, combinations, combination sum, skipping duplicates, pruning, parentheses, palindrome partitioning, word search, N-Queens, and how to tell backtracking from DP | Backtracking

## The Idea
> Backtracking is **exploring a maze and leaving breadcrumbs you can pick up again**. At every junction you try one corridor; if it leads nowhere (or to an answer you record), you **step back, undo your last move, and try the next corridor**.
- It is **DFS over a tree of choices** (a "decision tree") where you build a solution one decision at a time.
- Three steps in the loop: **choose** (add to the path), **explore** (recurse), **un-choose** (remove it again).
- **Pruning**: if a partial solution can never become valid, stop immediately instead of exploring its whole subtree. Pruning is what makes backtracking practical.
- Cost is **exponential** (that is inherent: the answer itself is exponentially large). The small constraints give it away: `n <= 20` or `n <= 8` usually means backtracking or bitmask.
! Choose, explore, undo. If you forget the undo, the path is polluted for the next branch.

## The Template
```java Template.java
class Solution {
  List<List<Integer>> out = new ArrayList<>();

  void backtrack(int[] nums, int start, List<Integer> path) {
    if (/* path is a complete answer */ false) {
      out.add(new ArrayList<>(path));           // store a COPY: path keeps changing
      return;
    }
    for (int i = start; i < nums.length; i++) { // the choices at this level
      if (/* this choice is invalid or useless */ false) continue;   // prune
      path.add(nums[i]);                        // 1. choose
      backtrack(nums, i + 1, path);             // 2. explore
      path.remove(path.size() - 1);             // 3. un-choose (undo)
    }
  }
}
```
- Two ways to say "which choices are allowed next": a **`start` index** (combinations and subsets: never go backwards, so no reordered duplicates) or a **`used[]` array** (permutations: any unused element can come next).

## How Big Are the Answers?
```text
problem                    how many results        total work
subsets of n               2^n                     O(n * 2^n)
permutations of n          n!                      O(n * n!)
combinations C(n, k)       n! / (k! (n-k)!)        O(k * C(n, k))
valid parentheses (n)      Catalan(n)  (~4^n)      ~O(4^n / sqrt(n))
N-Queens (n)               far fewer than n^n      depends on pruning
```
- The factor `n` (or `k`) is the cost of **copying** each answer into the result.

## Subsets (include or exclude)
```java Subsets.java
class Solution {
  public List<List<Integer>> subsets(int[] nums) {          // LeetCode 78
    List<List<Integer>> out = new ArrayList<>();
    go(nums, 0, new ArrayList<>(), out);
    return out;
  }
  private void go(int[] nums, int start, List<Integer> path, List<List<Integer>> out) {
    out.add(new ArrayList<>(path));                         // every path, at every depth, is a subset
    for (int i = start; i < nums.length; i++) {
      path.add(nums[i]);
      go(nums, i + 1, path, out);                           // i + 1: never reuse or go backwards
      path.remove(path.size() - 1);
    }
  }
  public List<List<Integer>> subsetsWithDup(int[] nums) {   // LeetCode 90: input may contain duplicates
    Arrays.sort(nums);                                      // equal values must be neighbours
    List<List<Integer>> out = new ArrayList<>();
    goDup(nums, 0, new ArrayList<>(), out);
    return out;
  }
  private void goDup(int[] nums, int start, List<Integer> path, List<List<Integer>> out) {
    out.add(new ArrayList<>(path));
    for (int i = start; i < nums.length; i++) {
      if (i > start && nums[i] == nums[i - 1]) continue;    // skip a repeat AT THE SAME LEVEL
      path.add(nums[i]);
      goDup(nums, i + 1, path, out);
      path.remove(path.size() - 1);
    }
  }
}
```
! Duplicates rule: sort first, then `if (i > start && nums[i] == nums[i - 1]) continue;`. It skips a duplicate only when it would start a **new branch at the same level**, but still allows using both copies in one path.

## Permutations (any unused element next)
```java Permutations.java
class Solution {
  public List<List<Integer>> permute(int[] nums) {          // LeetCode 46
    List<List<Integer>> out = new ArrayList<>();
    go(nums, new boolean[nums.length], new ArrayList<>(), out);
    return out;
  }
  private void go(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> out) {
    if (path.size() == nums.length) { out.add(new ArrayList<>(path)); return; }
    for (int i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true;
      path.add(nums[i]);
      go(nums, used, path, out);
      path.remove(path.size() - 1);
      used[i] = false;
    }
  }
  public List<List<Integer>> permuteUnique(int[] nums) {    // LeetCode 47: with duplicates
    Arrays.sort(nums);
    List<List<Integer>> out = new ArrayList<>();
    goUnique(nums, new boolean[nums.length], new ArrayList<>(), out);
    return out;
  }
  private void goUnique(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> out) {
    if (path.size() == nums.length) { out.add(new ArrayList<>(path)); return; }
    for (int i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue;   // use equal values in left-to-right order only
      used[i] = true;
      path.add(nums[i]);
      goUnique(nums, used, path, out);
      path.remove(path.size() - 1);
      used[i] = false;
    }
  }
}
```

## Combinations and Combination Sum
```java Combinations.java
class Solution {
  public List<List<Integer>> combine(int n, int k) {        // LeetCode 77: choose k of 1..n
    List<List<Integer>> out = new ArrayList<>();
    go(n, k, 1, new ArrayList<>(), out);
    return out;
  }
  private void go(int n, int k, int start, List<Integer> path, List<List<Integer>> out) {
    if (path.size() == k) { out.add(new ArrayList<>(path)); return; }
    for (int i = start; i <= n - (k - path.size()) + 1; i++) {   // prune: stop if too few numbers remain
      path.add(i);
      go(n, k, i + 1, path, out);
      path.remove(path.size() - 1);
    }
  }
  public List<List<Integer>> combinationSum(int[] cands, int target) {   // LeetCode 39: reuse allowed
    Arrays.sort(cands);
    List<List<Integer>> out = new ArrayList<>();
    sum(cands, target, 0, new ArrayList<>(), out);
    return out;
  }
  private void sum(int[] c, int remain, int start, List<Integer> path, List<List<Integer>> out) {
    if (remain == 0) { out.add(new ArrayList<>(path)); return; }
    for (int i = start; i < c.length && c[i] <= remain; i++) {   // sorted: once too big, all later are too big
      path.add(c[i]);
      sum(c, remain - c[i], i, path, out);                  // i, not i + 1: the same number may be reused
      path.remove(path.size() - 1);
    }
  }
  public List<List<Integer>> combinationSum2(int[] cands, int target) {  // LeetCode 40: each number once, duplicates in input
    Arrays.sort(cands);
    List<List<Integer>> out = new ArrayList<>();
    sum2(cands, target, 0, new ArrayList<>(), out);
    return out;
  }
  private void sum2(int[] c, int remain, int start, List<Integer> path, List<List<Integer>> out) {
    if (remain == 0) { out.add(new ArrayList<>(path)); return; }
    for (int i = start; i < c.length && c[i] <= remain; i++) {
      if (i > start && c[i] == c[i - 1]) continue;          // the duplicates rule again
      path.add(c[i]);
      sum2(c, remain - c[i], i + 1, path, out);             // i + 1: each element used at most once
      path.remove(path.size() - 1);
    }
  }
}
```
! Reuse allowed → recurse with `i`. Each used once → recurse with `i + 1`.

## Strings: Phone Letters, Parentheses, Palindrome Partitions
```java StringBacktracking.java
class Solution {
  private static final String[] KEYS = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
  public List<String> letterCombinations(String digits) {   // LeetCode 17
    List<String> out = new ArrayList<>();
    if (digits.isEmpty()) return out;
    letters(digits, 0, new StringBuilder(), out);
    return out;
  }
  private void letters(String d, int i, StringBuilder sb, List<String> out) {
    if (i == d.length()) { out.add(sb.toString()); return; }
    for (char c : KEYS[d.charAt(i) - '0'].toCharArray()) {
      sb.append(c);
      letters(d, i + 1, sb, out);
      sb.deleteCharAt(sb.length() - 1);
    }
  }
  public List<String> generateParenthesis(int n) {          // LeetCode 22
    List<String> out = new ArrayList<>();
    parens(n, 0, 0, new StringBuilder(), out);
    return out;
  }
  private void parens(int n, int open, int close, StringBuilder sb, List<String> out) {
    if (sb.length() == 2 * n) { out.add(sb.toString()); return; }
    if (open < n) {                                          // may open while we have openers left
      sb.append('(');
      parens(n, open + 1, close, sb, out);
      sb.deleteCharAt(sb.length() - 1);
    }
    if (close < open) {                                      // may close only what is currently open
      sb.append(')');
      parens(n, open, close + 1, sb, out);
      sb.deleteCharAt(sb.length() - 1);
    }
  }
  public List<List<String>> partition(String s) {           // LeetCode 131: split into palindromes
    List<List<String>> out = new ArrayList<>();
    cut(s, 0, new ArrayList<>(), out);
    return out;
  }
  private void cut(String s, int start, List<String> path, List<List<String>> out) {
    if (start == s.length()) { out.add(new ArrayList<>(path)); return; }
    for (int end = start + 1; end <= s.length(); end++) {
      if (!isPal(s, start, end - 1)) continue;               // prune: only palindromic pieces
      path.add(s.substring(start, end));
      cut(s, end, path, out);
      path.remove(path.size() - 1);
    }
  }
  private boolean isPal(String s, int l, int r) {
    while (l < r) if (s.charAt(l++) != s.charAt(r--)) return false;
    return true;
  }
}
```

## Grid Backtracking: Word Search
> DFS from every cell. **Mark** the current cell as used (overwrite it with a sentinel), explore four directions, then **restore** it.
```java WordSearch.java
class Solution {
  public boolean exist(char[][] board, String word) {        // LeetCode 79
    for (int r = 0; r < board.length; r++)
      for (int c = 0; c < board[0].length; c++)
        if (dfs(board, word, 0, r, c)) return true;
    return false;
  }
  private boolean dfs(char[][] b, String w, int i, int r, int c) {
    if (i == w.length()) return true;
    if (r < 0 || c < 0 || r >= b.length || c >= b[0].length || b[r][c] != w.charAt(i)) return false;
    char saved = b[r][c];
    b[r][c] = '#';                                           // mark: this cell is on the current path
    boolean found = dfs(b, w, i + 1, r + 1, c) || dfs(b, w, i + 1, r - 1, c)
                 || dfs(b, w, i + 1, r, c + 1) || dfs(b, w, i + 1, r, c - 1);
    b[r][c] = saved;                                         // undo
    return found;
  }
}
```

## N-Queens (pruning with constraint sets)
> Place one queen per **row**. A column is blocked if a column, a `/` diagonal (same `r + c`) or a `\` diagonal (same `r - c`) already holds a queen. Three boolean arrays make each check O(1), so a conflict prunes the whole subtree immediately.
```java NQueens.java
class Solution {
  public List<List<String>> solveNQueens(int n) {            // LeetCode 51
    List<List<String>> out = new ArrayList<>();
    place(n, 0, new int[n], new boolean[n], new boolean[2 * n], new boolean[2 * n], out);
    return out;
  }
  // queens[r] = column of the queen in row r
  private void place(int n, int r, int[] queens, boolean[] cols, boolean[] d1, boolean[] d2, List<List<String>> out) {
    if (r == n) { out.add(draw(queens)); return; }
    for (int c = 0; c < n; c++) {
      if (cols[c] || d1[r + c] || d2[r - c + n]) continue;   // attacked: prune
      queens[r] = c;
      cols[c] = d1[r + c] = d2[r - c + n] = true;            // choose
      place(n, r + 1, queens, cols, d1, d2, out);            // explore
      cols[c] = d1[r + c] = d2[r - c + n] = false;           // undo
    }
  }
  private List<String> draw(int[] queens) {
    List<String> board = new ArrayList<>();
    for (int q : queens) {
      char[] row = new char[queens.length];
      Arrays.fill(row, '.');
      row[q] = 'Q';
      board.add(new String(row));
    }
    return board;
  }
}
```
- Sudoku solver (**37**) is the same idea: pick an empty cell, try digits 1-9 that do not clash with the row, column and box, recurse, undo.

## Backtracking vs DP vs Greedy
- **Backtracking**: "list **all** solutions" or "does **any** solution exist", with constraints. Exponential, prunes dead ends.
- **DP**: "**count** the ways" or "best value", and the same subproblems **repeat** (overlapping). Polynomial. If a backtracking tree computes the same state twice, add a memo and it becomes DP (sheet 20).
- **Greedy**: one locally best choice per step, **no undoing**. Fast, but only correct when a proof says so (sheet 19).
! "Return all ..." means backtracking. "Return how many ..." or "the maximum ..." usually means DP.

## Common Mistakes
- Adding `path` to the result instead of `new ArrayList<>(path)`.
- Forgetting the undo step (or undoing in the wrong order).
- `start` vs `used`: using `start` for permutations loses answers; using `used` for combinations produces duplicates in different orders.
- Handling duplicates without sorting first, or skipping with the wrong condition (`i > 0` instead of `i > start`).
- No pruning: `combine(20, 10)` without the `n - (k - path.size()) + 1` bound explores many dead branches.

## Explain It Like This
> "At each position I choose one of the remaining numbers, recurse for the rest, then remove it to try the next. When the path has all n numbers I save a copy. There are n! permutations and each costs O(n) to copy, so O(n * n!) time."

## Interview Q&A
Q*: What is backtracking?
A: A depth-first search over a decision tree. You build a candidate solution one choice at a time, recurse, and then undo the choice to try the alternatives. Branches that cannot lead to a valid solution are pruned early.
Q*: Subsets vs permutations vs combinations in code?
A: Subsets and combinations use a start index so elements are only taken in increasing positions (no reordered duplicates). Permutations allow any unused element at each step, tracked with a used array. Combinations stop at a fixed size; subsets record every path.
Q*: How do you avoid duplicate results when the input has duplicates?
A: Sort the array, then within a loop at one recursion level skip an element equal to the previous one (i > start && nums[i] == nums[i - 1]). For permutations, skip a duplicate whose equal predecessor is not currently used.
Q: What is the complexity of backtracking?
A: Exponential: roughly the number of nodes in the decision tree times the work per node, for example O(n * 2^n) for subsets and O(n * n!) for permutations, with O(depth) space excluding the output.
Q: How is backtracking different from DP?
A: Backtracking enumerates all solutions and prunes; the work can be exponential. DP is used when subproblems overlap and you only need a count or an optimum, so cached results make it polynomial. Backtracking plus memoization of repeated states is top-down DP.
Q: How does pruning help in N-Queens?
A: Tracking attacked columns and diagonals in boolean arrays lets you reject a placement in O(1) as soon as it conflicts, which cuts off the entire subtree of boards that would extend that placement.

## The Idea
> A graph is **dots connected by lines**: dots are **nodes (vertices)**, lines are **edges**. Cities and roads, people and friendships, courses and prerequisites, web pages and links.
- **Undirected**: edges go both ways (friendship). **Directed**: one way (follow, prerequisite). **Weighted**: edges carry a cost (distance, price).
- **Path**: a sequence of edges. **Cycle**: a path that returns to its start. **Connected component**: a group of nodes all reachable from each other. **DAG**: directed acyclic graph (no cycles), the shape of a dependency graph.
- A **tree** is a connected graph with no cycles (`n` nodes, `n - 1` edges).
- **V** = number of vertices, **E** = number of edges. Traversals cost **O(V + E)**.
! If the problem has "connected", "reachable", "shortest path", "dependencies" or a grid, think graph.

## How to Store a Graph
```text
representation    space     edge u-v?   neighbours of u  use when
adjacency list    O(V + E)  O(degree)   O(degree)        almost always (sparse graphs)
adjacency matrix  O(V^2)    O(1)        O(V)             dense graphs, small V
edge list         O(E)      O(E)        O(E)             sorting edges (Kruskal)
```
```java GraphBasics.java
class Solution {
  // Build an adjacency list from an edge list (undirected: add both directions).
  static List<List<Integer>> build(int n, int[][] edges, boolean directed) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) {
      adj.get(e[0]).add(e[1]);
      if (!directed) adj.get(e[1]).add(e[0]);
    }
    return adj;
  }

  // BFS: shortest number of edges from start to every node (unweighted graph). -1 = unreachable.
  static int[] bfs(List<List<Integer>> adj, int start) {
    int[] dist = new int[adj.size()];
    Arrays.fill(dist, -1);                                   // -1 doubles as the "visited" marker
    Queue<Integer> q = new ArrayDeque<>();
    dist[start] = 0;
    q.offer(start);
    while (!q.isEmpty()) {
      int u = q.poll();
      for (int v : adj.get(u))
        if (dist[v] == -1) { dist[v] = dist[u] + 1; q.offer(v); }   // mark when ENQUEUED, never twice in the queue
    }
    return dist;
  }

  // DFS recursive: visit everything reachable from u.
  static void dfs(List<List<Integer>> adj, int u, boolean[] seen) {
    seen[u] = true;
    for (int v : adj.get(u)) if (!seen[v]) dfs(adj, v, seen);
  }

  // DFS iterative with your own stack (avoids StackOverflowError on long chains).
  static boolean hasPath(List<List<Integer>> adj, int from, int to) {          // LeetCode 1971 idea
    boolean[] seen = new boolean[adj.size()];
    Deque<Integer> st = new ArrayDeque<>();
    st.push(from);
    seen[from] = true;
    while (!st.isEmpty()) {
      int u = st.pop();
      if (u == to) return true;
      for (int v : adj.get(u)) if (!seen[v]) { seen[v] = true; st.push(v); }
    }
    return false;
  }

  // Number of connected components: start a DFS from every node not yet seen.
  static int components(int n, int[][] edges) {
    List<List<Integer>> adj = build(n, edges, false);
    boolean[] seen = new boolean[n];
    int count = 0;
    for (int i = 0; i < n; i++) if (!seen[i]) { count++; dfs(adj, i, seen); }
    return count;
  }
}
```

## BFS vs DFS (when to use which)
```text
               BFS                              DFS
structure      queue (FIFO)                     stack or recursion (LIFO)
explores       level by level (nearest first)   one path deep, then back up
finds          SHORTEST path, unweighted        any path, cycles, components
memory         widest level                     longest path (depth)
use for        min steps, spreading             connectivity, flood fill, ordering
```
- **Always keep a `visited` set**, or cycles make the search run forever. Mark nodes **when you add them to the queue/stack**, not when you remove them (otherwise a node can be queued many times).
! "Minimum number of steps/moves/edges" → BFS. "Is it connected / count regions / any path" → DFS or BFS.

## Grids Are Graphs
> Each cell is a node; its neighbours are the 4 (or 8) adjacent cells. Use a **directions array** and a bounds check instead of building an adjacency list.
```java GridDfs.java
class Solution {
  public int numIslands(char[][] grid) {                      // LeetCode 200
    int count = 0;
    for (int r = 0; r < grid.length; r++)
      for (int c = 0; c < grid[0].length; c++)
        if (grid[r][c] == '1') { count++; sink(grid, r, c); } // each unvisited land cell starts a new island
    return count;
  }
  private void sink(char[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != '1') return;
    g[r][c] = '0';                                            // mark visited by overwriting (or use a boolean[][])
    sink(g, r + 1, c); sink(g, r - 1, c); sink(g, r, c + 1); sink(g, r, c - 1);
  }
  public int maxAreaOfIsland(int[][] g) {                     // LeetCode 695
    int best = 0;
    for (int r = 0; r < g.length; r++)
      for (int c = 0; c < g[0].length; c++) best = Math.max(best, area(g, r, c));
    return best;
  }
  private int area(int[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != 1) return 0;
    g[r][c] = 0;
    return 1 + area(g, r + 1, c) + area(g, r - 1, c) + area(g, r, c + 1) + area(g, r, c - 1);
  }
  public int[][] floodFill(int[][] image, int sr, int sc, int color) {   // LeetCode 733
    int old = image[sr][sc];
    if (old != color) fill(image, sr, sc, old, color);        // old == color would loop forever
    return image;
  }
  private void fill(int[][] img, int r, int c, int old, int color) {
    if (r < 0 || c < 0 || r >= img.length || c >= img[0].length || img[r][c] != old) return;
    img[r][c] = color;
    fill(img, r + 1, c, old, color); fill(img, r - 1, c, old, color);
    fill(img, r, c + 1, old, color); fill(img, r, c - 1, old, color);
  }
}
```
- On a very large grid, recursive DFS can overflow the stack (a snake-shaped island is as deep as the cell count). Switch to BFS with a queue.

## Multi-Source BFS (spreading from many starts at once)
> Put **all** the sources in the queue at the start. BFS then expands them **simultaneously**, so the level number is the time/distance to the nearest source.
```java MultiSourceBfs.java
class Solution {
  static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

  public int orangesRotting(int[][] g) {                      // LeetCode 994: minutes until no fresh orange
    int rows = g.length, cols = g[0].length, fresh = 0, minutes = 0;
    Queue<int[]> q = new ArrayDeque<>();
    for (int r = 0; r < rows; r++)
      for (int c = 0; c < cols; c++) {
        if (g[r][c] == 2) q.offer(new int[] {r, c});
        else if (g[r][c] == 1) fresh++;
      }
    while (!q.isEmpty() && fresh > 0) {
      minutes++;                                              // one BFS level = one minute
      for (int size = q.size(); size > 0; size--) {
        int[] cur = q.poll();
        for (int[] d : DIRS) {
          int nr = cur[0] + d[0], nc = cur[1] + d[1];
          if (nr < 0 || nc < 0 || nr >= rows || nc >= cols || g[nr][nc] != 1) continue;
          g[nr][nc] = 2;
          fresh--;
          q.offer(new int[] {nr, nc});
        }
      }
    }
    return fresh == 0 ? minutes : -1;
  }

  public int[][] updateMatrix(int[][] mat) {                  // LeetCode 542: distance of each cell to the nearest 0
    int rows = mat.length, cols = mat[0].length;
    int[][] dist = new int[rows][cols];
    Queue<int[]> q = new ArrayDeque<>();
    for (int r = 0; r < rows; r++)
      for (int c = 0; c < cols; c++) {
        if (mat[r][c] == 0) q.offer(new int[] {r, c});        // every zero is a source
        else dist[r][c] = -1;                                 // unvisited
      }
    while (!q.isEmpty()) {
      int[] cur = q.poll();
      for (int[] d : DIRS) {
        int nr = cur[0] + d[0], nc = cur[1] + d[1];
        if (nr < 0 || nc < 0 || nr >= rows || nc >= cols || dist[nr][nc] != -1) continue;
        dist[nr][nc] = dist[cur[0]][cur[1]] + 1;
        q.offer(new int[] {nr, nc});
      }
    }
    return dist;
  }

  public List<List<Integer>> pacificAtlantic(int[][] h) {     // LeetCode 417: run the flow BACKWARDS from each ocean
    int rows = h.length, cols = h[0].length;
    boolean[][] pac = new boolean[rows][cols], atl = new boolean[rows][cols];
    for (int r = 0; r < rows; r++) { flow(h, pac, r, 0); flow(h, atl, r, cols - 1); }
    for (int c = 0; c < cols; c++) { flow(h, pac, 0, c); flow(h, atl, rows - 1, c); }
    List<List<Integer>> out = new ArrayList<>();
    for (int r = 0; r < rows; r++)
      for (int c = 0; c < cols; c++) if (pac[r][c] && atl[r][c]) out.add(List.of(r, c));
    return out;
  }
  private void flow(int[][] h, boolean[][] seen, int r, int c) {   // from the ocean, climb to equal or higher cells
    seen[r][c] = true;
    for (int[] d : DIRS) {
      int nr = r + d[0], nc = c + d[1];
      if (nr < 0 || nc < 0 || nr >= h.length || nc >= h[0].length || seen[nr][nc] || h[nr][nc] < h[r][c]) continue;
      flow(h, seen, nr, nc);
    }
  }
}
```
! Many starting points → push them all into the queue first (multi-source BFS). Think backwards from the targets when it is cheaper (Pacific Atlantic).

## Clone Graph (DFS with a map old → copy)
```java CloneGraph.java
class Node {
  public int val;
  public List<Node> neighbors = new ArrayList<>();
  Node(int val) { this.val = val; }
}
class Solution {
  public Node cloneGraph(Node node) {                         // LeetCode 133
    return node == null ? null : clone(node, new HashMap<>());
  }
  private Node clone(Node n, Map<Node, Node> copies) {
    if (copies.containsKey(n)) return copies.get(n);          // already copied: this also breaks cycles
    Node copy = new Node(n.val);
    copies.put(n, copy);                                      // register BEFORE recursing
    for (Node nb : n.neighbors) copy.neighbors.add(clone(nb, copies));
    return copy;
  }
}
```

## Topological Sort (Kahn's algorithm) and Cycle Detection
> For a **directed** graph of dependencies, a topological order lists every node **after** everything it depends on. **Kahn's algorithm**: repeatedly take a node with **in-degree 0** (no unmet dependencies), output it, and remove its outgoing edges. If you output fewer than `n` nodes, **there is a cycle** (no valid order).
```java TopoSort.java
class Solution {
  public boolean canFinish(int n, int[][] prerequisites) {    // LeetCode 207
    return findOrder(n, prerequisites).length == n;
  }
  public int[] findOrder(int n, int[][] prerequisites) {      // LeetCode 210: each pair is [course, prerequisite]
    List<List<Integer>> adj = new ArrayList<>();
    int[] indegree = new int[n];
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] p : prerequisites) { adj.get(p[1]).add(p[0]); indegree[p[0]]++; }   // prerequisite -> course
    Queue<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indegree[i] == 0) q.offer(i);
    int[] order = new int[n];
    int k = 0;
    while (!q.isEmpty()) {
      int u = q.poll();
      order[k++] = u;
      for (int v : adj.get(u)) if (--indegree[v] == 0) q.offer(v);   // all of v's dependencies are done
    }
    return k == n ? order : new int[0];                       // fewer than n output = cycle
  }
}
```
- Alternative: DFS with three colours (unvisited, in progress, done). Reaching an **in-progress** node means a cycle; the reverse of the finishing order is a topological order.
- Uses: build order, course scheduling, task dependencies, "alien dictionary" (**269**, Premium).

## Bipartite Check (two-colouring)
> A graph is **bipartite** if you can colour nodes with two colours so every edge joins different colours. BFS and colour each neighbour the opposite of the current node; a neighbour with the **same** colour means an odd cycle, so no.
```java Bipartite.java
class Solution {
  public boolean isBipartite(int[][] graph) {                 // LeetCode 785
    int n = graph.length;
    int[] color = new int[n];                                 // 0 = uncoloured, 1 and -1 = the two sides
    for (int s = 0; s < n; s++) {
      if (color[s] != 0) continue;                            // the graph may be disconnected: start from each component
      Queue<Integer> q = new ArrayDeque<>();
      q.offer(s);
      color[s] = 1;
      while (!q.isEmpty()) {
        int u = q.poll();
        for (int v : graph[u]) {
          if (color[v] == 0) { color[v] = -color[u]; q.offer(v); }
          else if (color[v] == color[u]) return false;        // an edge inside one side
        }
      }
    }
    return true;
  }
}
```

## Union-Find (Disjoint Set Union)
> Keep each group as a tree whose **root represents the group**. `find(x)` walks up to the root. `union(a, b)` joins the two groups by pointing one root at the other. Two optimisations make both operations almost O(1) (**inverse Ackermann**, practically constant): **path compression** (flatten the tree while finding) and **union by rank** (hang the shorter tree under the taller).
```java UnionFind.java
class UnionFind {
  private final int[] parent, rank;
  int components;
  UnionFind(int n) {
    parent = new int[n];
    rank = new int[n];
    components = n;
    for (int i = 0; i < n; i++) parent[i] = i;                // everyone starts as their own group
  }
  int find(int x) {
    while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }   // path halving
    return x;
  }
  boolean union(int a, int b) {                               // false if a and b were already connected
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;
    if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;                                          // shorter tree goes under the taller one
    if (rank[ra] == rank[rb]) rank[ra]++;
    components--;
    return true;
  }
}
class Solution {
  public int[] findRedundantConnection(int[][] edges) {       // LeetCode 684: the edge that closes a cycle
    UnionFind uf = new UnionFind(edges.length + 1);
    for (int[] e : edges) if (!uf.union(e[0], e[1])) return e;   // already connected: this edge is redundant
    return new int[0];
  }
  public int findCircleNum(int[][] isConnected) {             // LeetCode 547: number of provinces
    int n = isConnected.length;
    UnionFind uf = new UnionFind(n);
    for (int i = 0; i < n; i++)
      for (int j = i + 1; j < n; j++) if (isConnected[i][j] == 1) uf.union(i, j);
    return uf.components;
  }
}
```
! Use union-find when the question is about **groups merging** over time ("are these two connected?", "how many groups?", "which edge makes a cycle?"). It also drives **Kruskal's MST** (sheet 22).

## BFS on an Implicit Graph: Word Ladder
> The nodes are **words**; two words are neighbours if they differ by one letter. You do not build the graph: generate neighbours on the fly and BFS for the **shortest** transformation.
```java WordLadder.java
class Solution {
  public int ladderLength(String begin, String end, List<String> wordList) {   // LeetCode 127
    Set<String> words = new HashSet<>(wordList);
    if (!words.contains(end)) return 0;
    Queue<String> q = new ArrayDeque<>();
    q.offer(begin);
    int steps = 1;
    while (!q.isEmpty()) {
      for (int size = q.size(); size > 0; size--) {
        char[] w = q.poll().toCharArray();
        for (int i = 0; i < w.length; i++) {
          char orig = w[i];
          for (char c = 'a'; c <= 'z'; c++) {
            w[i] = c;
            String next = new String(w);
            if (next.equals(end)) return steps + 1;
            if (words.remove(next)) q.offer(next);            // remove = mark visited
          }
          w[i] = orig;
        }
      }
      steps++;
    }
    return 0;
  }
}
```

## Common Mistakes
- Forgetting a `visited` set (infinite loop on cycles), or marking visited when **polling** instead of when **enqueuing**.
- Only starting a traversal from node 0: the graph can be **disconnected**. Loop over all nodes.
- Wrong grid bounds: check `r >= 0`, `c >= 0`, `r < rows`, `c < cols`, **before** indexing.
- Directed vs undirected: for undirected input add the edge both ways. In topological sort, edge direction is **prerequisite → course**.
- Using DFS for "shortest path" (it does not guarantee shortest). Use BFS for unweighted, Dijkstra for weighted (sheet 22).

## Explain It Like This
> "It's a shortest path in an unweighted grid, so I'll use BFS: a queue, a visited array, and the level number as the distance. Each cell is enqueued once, so O(rows × cols) time and space."

## Interview Q&A
Q*: BFS vs DFS?
A: BFS explores level by level with a queue and finds the shortest path in an unweighted graph. DFS goes as deep as possible with a stack or recursion and suits connectivity, cycle detection, component counting and topological ordering. Both run in O(V + E).
Q*: How do you represent a graph and why?
A: An adjacency list (a list of neighbours per node) uses O(V + E) space and iterates neighbours quickly, so it is the default. An adjacency matrix uses O(V^2) space but checks an edge in O(1), which suits dense graphs.
Q*: How do you detect a cycle in a directed graph?
A: Run Kahn's algorithm: if fewer than n nodes can be removed with in-degree zero, there is a cycle. Or DFS with three states and report a cycle when you reach a node that is still in progress. For an undirected graph, union-find reports a cycle when an edge joins two nodes already in the same set.
Q: What is topological sort and when does it exist?
A: A linear ordering of a directed graph's nodes so every edge goes from earlier to later. It exists exactly when the graph is a DAG, and it is used for dependency resolution and scheduling.
Q: How does union-find work and what is its complexity?
A: It keeps disjoint sets as trees. find returns the root of a node's tree and union links two roots. With path compression and union by rank each operation is amortized inverse-Ackermann time, effectively constant.
Q: How do you find the shortest path in a grid?
A: Treat cells as nodes and run BFS from the start with a visited array. The first time BFS reaches the target, the number of levels is the minimum number of moves.

# 19 | Greedy & Intervals | What greedy means and when it is correct, the exchange argument, jump game, gas station, stock profit, partition labels, candy, interval problems (merge, insert, non-overlapping, arrows, intersections, meeting rooms), sorting by start vs by end | Greedy & Intervals

## The Idea
> Greedy is **always grabbing the best-looking option right now and never looking back**. Like packing a suitcase by always putting in the next most valuable item that still fits. Fast and simple, but only correct when the problem has the right structure.
- **No undoing** (unlike backtracking) and **no storing subproblems** (unlike DP). One pass, usually after a **sort**, usually O(n log n) or O(n).
- It is correct only if a **local best choice never blocks the global best**. You show this with an **exchange argument** ("swap any optimal solution's choice for the greedy one; it is not worse") or a **stays-ahead argument** ("after every step, greedy is at least as far as any other strategy").
- **Counterexample to remember**: coins `{1, 3, 4}`, make `6`. Greedy takes `4 + 1 + 1` (3 coins), but `3 + 3` uses 2. So "fewest coins" needs **DP** (sheet 20) unless the coin system is special (like real money).
! Greedy needs a proof, not a hunch. If you cannot argue why the local choice is safe, test a small counterexample or switch to DP.

## Clues That a Problem Is Greedy
- "Minimum number of ..." / "maximum number of ..." where each step has an obvious best pick.
- You can **sort** by one key (end time, ratio, size) and then scan.
- A choice made now does not reduce your options in a way that hurts later.
- Typical shapes: **intervals**, **jump/reach**, **assign/match**, **scheduling**, **two-pass scans (left then right)**.

## Reach Problems: Jump Game, Gas Station, Stock
```java GreedyReach.java
class Solution {
  public boolean canJump(int[] nums) {                       // LeetCode 55: can you reach the last index?
    int reach = 0;                                           // farthest index reachable so far
    for (int i = 0; i < nums.length; i++) {
      if (i > reach) return false;                           // stuck: index i is unreachable
      reach = Math.max(reach, i + nums[i]);
    }
    return true;
  }
  public int jump(int[] nums) {                              // LeetCode 45: minimum jumps (BFS levels in disguise)
    int jumps = 0, curEnd = 0, farthest = 0;
    for (int i = 0; i < nums.length - 1; i++) {
      farthest = Math.max(farthest, i + nums[i]);
      if (i == curEnd) { jumps++; curEnd = farthest; }       // forced to jump: take the best landing seen
    }
    return jumps;
  }
  public int canCompleteCircuit(int[] gas, int[] cost) {     // LeetCode 134
    int total = 0, tank = 0, start = 0;
    for (int i = 0; i < gas.length; i++) {
      int gain = gas[i] - cost[i];
      total += gain;
      tank += gain;
      if (tank < 0) { start = i + 1; tank = 0; }             // cannot get past i from any earlier start: restart after i
    }
    return total >= 0 ? start : -1;                          // total fuel must cover total cost
  }
  public int maxProfitOneTrade(int[] prices) {               // LeetCode 121
    int min = Integer.MAX_VALUE, best = 0;
    for (int p : prices) { min = Math.min(min, p); best = Math.max(best, p - min); }
    return best;
  }
  public int maxProfit(int[] prices) {                       // LeetCode 122: unlimited trades = collect every rise
    int profit = 0;
    for (int i = 1; i < prices.length; i++) profit += Math.max(0, prices[i] - prices[i - 1]);
    return profit;
  }
}
```
- **Gas station proof**: if you run out at `i` starting from `start`, then starting from any station between `start` and `i` also fails (you would arrive there with at least 0 fuel). So the next candidate is `i + 1`.

## Assign, Partition, Two-Pass
```java GreedyAssign.java
class Solution {
  public int findContentChildren(int[] g, int[] s) {         // LeetCode 455: greed factors vs cookie sizes
    Arrays.sort(g);
    Arrays.sort(s);
    int child = 0;
    for (int cookie : s)                                     // smallest cookie that satisfies the least greedy child
      if (child < g.length && g[child] <= cookie) child++;
    return child;
  }
  public List<Integer> partitionLabels(String s) {           // LeetCode 763: cut so no letter appears in two parts
    int[] last = new int[26];
    for (int i = 0; i < s.length(); i++) last[s.charAt(i) - 'a'] = i;
    List<Integer> out = new ArrayList<>();
    int start = 0, end = 0;
    for (int i = 0; i < s.length(); i++) {
      end = Math.max(end, last[s.charAt(i) - 'a']);          // the part must reach the last copy of every letter in it
      if (i == end) { out.add(end - start + 1); start = i + 1; }
    }
    return out;
  }
  public int candy(int[] ratings) {                          // LeetCode 135: more than a neighbour with a lower rating
    int n = ratings.length;
    int[] c = new int[n];
    Arrays.fill(c, 1);
    for (int i = 1; i < n; i++)                              // pass 1: satisfy the left neighbour
      if (ratings[i] > ratings[i - 1]) c[i] = c[i - 1] + 1;
    for (int i = n - 2; i >= 0; i--)                         // pass 2: satisfy the right neighbour, keep pass 1
      if (ratings[i] > ratings[i + 1]) c[i] = Math.max(c[i], c[i + 1] + 1);
    return Arrays.stream(c).sum();
  }
}
```
! Two-pass trick: one constraint per direction. Do left-to-right, then right-to-left, and combine with `max`.

## Intervals: the Toolkit
- An interval is `[start, end]`. Two intervals **overlap** if `a.start <= b.end && b.start <= a.end` (decide whether touching endpoints count).
- **Sort first.** By **start** to merge or insert; by **end** to pick the **most intervals that do not overlap** (the one that finishes earliest leaves the most room).
- After sorting by start, you only need to compare each interval with the **last merged one**.
```text
merge:        sort by start; if cur.start <= last.end extend last, else start new
max kept:     sort by END; keep an interval if start >= end of the last kept one
min removed:  n - max kept
min arrows:   same as max kept (one arrow per group of overlapping balloons)
rooms needed: the most intervals overlapping at any moment (heap of end times)
```
```java Intervals.java
class Solution {
  public int[][] merge(int[][] intervals) {                  // LeetCode 56
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    List<int[]> out = new ArrayList<>();
    for (int[] cur : intervals) {
      if (out.isEmpty() || out.get(out.size() - 1)[1] < cur[0]) out.add(cur.clone());   // gap: a new interval
      else out.get(out.size() - 1)[1] = Math.max(out.get(out.size() - 1)[1], cur[1]);  // overlap: extend the last
    }
    return out.toArray(new int[0][]);
  }
  public int[][] insert(int[][] intervals, int[] added) {    // LeetCode 57: intervals are sorted and disjoint
    List<int[]> out = new ArrayList<>();
    int i = 0, n = intervals.length;
    while (i < n && intervals[i][1] < added[0]) out.add(intervals[i++]);          // entirely before the new one
    int lo = added[0], hi = added[1];
    while (i < n && intervals[i][0] <= hi) {                                       // overlapping: absorb them
      lo = Math.min(lo, intervals[i][0]);
      hi = Math.max(hi, intervals[i][1]);
      i++;
    }
    out.add(new int[] {lo, hi});
    while (i < n) out.add(intervals[i++]);                                         // entirely after
    return out.toArray(new int[0][]);
  }
  public int eraseOverlapIntervals(int[][] intervals) {      // LeetCode 435: fewest removals so none overlap
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));   // earliest END first
    int kept = 0;
    long end = Long.MIN_VALUE;
    for (int[] in : intervals) if (in[0] >= end) { kept++; end = in[1]; }
    return intervals.length - kept;
  }
  public int findMinArrowShots(int[][] points) {             // LeetCode 452: balloons are [xStart, xEnd]
    Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));
    int arrows = 0;
    long end = Long.MIN_VALUE;                               // long: coordinates reach the int limits
    for (int[] p : points) if (p[0] > end) { arrows++; end = p[1]; }   // shoot at the earliest end
    return arrows;
  }
  public int[][] intervalIntersection(int[][] a, int[][] b) {  // LeetCode 986: two sorted lists, two pointers
    List<int[]> out = new ArrayList<>();
    int i = 0, j = 0;
    while (i < a.length && j < b.length) {
      int lo = Math.max(a[i][0], b[j][0]), hi = Math.min(a[i][1], b[j][1]);
      if (lo <= hi) out.add(new int[] {lo, hi});
      if (a[i][1] < b[j][1]) i++; else j++;                  // discard the one that ends first
    }
    return out.toArray(new int[0][]);
  }
  public int minMeetingRooms(int[][] intervals) {            // LeetCode 253 Meeting Rooms II (Premium)
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();     // end times of the rooms in use
    for (int[] in : intervals) {
      if (!ends.isEmpty() && ends.peek() <= in[0]) ends.poll();   // the earliest-ending room is free: reuse it
      ends.offer(in[1]);
    }
    return ends.size();
  }
}
```
- **Sort by start** → merge / insert / rooms. **Sort by end** → maximum non-overlapping, arrows, "interval scheduling".
- **Sweep line** (an alternative for counting overlap): make events `(start, +1)` and `(end, -1)`, sort, and track the running sum (the same idea as the difference array in sheet 07; **Car Pooling** uses it).

## Why "Earliest End First" Works (exchange argument, simply)
> Among all intervals that fit, picking the one that **finishes first** leaves the **most room** for the rest. Suppose an optimal answer starts with a different interval X. X ends no earlier than the greedy pick G, so replacing X by G cannot create a conflict with the later intervals. Hence there is an optimal answer that contains G, and repeating the argument proves the whole greedy choice sequence optimal.

## Greedy vs DP vs Backtracking
- **Greedy**: one safe choice per step, one pass. Needs a proof.
- **DP**: tries every option but remembers results, for problems where the best local choice is not always safe (coin change with arbitrary coins, 0/1 knapsack, longest increasing subsequence).
- **Backtracking**: tries every option and undoes, to **list** all solutions.
- If greedy "mostly works" in your examples, **try to break it** with a tiny hand-made counterexample before trusting it.

## Common Mistakes
- Sorting by the wrong key (start vs end). Merge needs start; interval scheduling needs end.
- Off-by-one on touching intervals: `[1, 2]` and `[2, 3]` overlap in "merge" but not in "meeting rooms". Read the statement.
- Mutating the input intervals (clone when you modify).
- Subtraction in comparators (`a[0] - b[0]`) overflows for large coordinates. Use `Integer.compare`.
- Assuming greedy works for min-coin or knapsack style problems.

## Explain It Like This
> "Sort the intervals by end time and always keep the one that finishes earliest if it does not overlap the last kept one. Finishing earliest leaves the most room, so I keep the maximum count, and the answer is n minus that. Sorting makes it O(n log n)."

## Interview Q&A
Q*: What is a greedy algorithm?
A: One that builds a solution step by step, always taking the choice that looks best locally and never reconsidering. It is correct only for problems where local optimal choices lead to a global optimum, which is shown with an exchange or stays-ahead argument.
Q*: Greedy vs dynamic programming?
A: Greedy commits to one choice per step and runs in one pass, but needs a proof. DP considers all choices and reuses subproblem results, so it handles cases where the best local choice can be wrong, such as coin change with arbitrary denominations.
Q*: How do you merge overlapping intervals?
A: Sort by start. Keep a result list; for each interval, if it starts after the last result's end, add it as new; otherwise extend the last result's end to the maximum of both ends. O(n log n) for the sort.
Q: How do you choose the maximum number of non-overlapping intervals?
A: Sort by end time and greedily keep each interval whose start is at or after the end of the last kept one. The earliest finish leaves the most room for the rest.
Q: Why does the gas station greedy work?
A: If the total gas is at least the total cost a solution exists. If the tank goes negative at station i starting from s, every station between s and i also fails, so the next candidate start is i + 1. One pass finds it.
Q: How do you find the minimum number of meeting rooms?
A: Sort meetings by start and keep a min-heap of end times of rooms in use. If the earliest ending room is free before the next meeting starts, reuse it, otherwise add a room. The heap size at the end is the answer.

# 01 | Angular Cheat Sheet | Concepts on one page for Angular 22: what each building block is, what it is for, how it compares with the older way, and only the tricky code | Angular on one page

## What is Angular?
> **What:** Google's **TypeScript framework** for single-page applications, "batteries included": components, DI, router, forms, HttpClient, testing and a CLI.
- **AngularJS (1.x, 2010)** vs **Angular (2+, 2016)**: AngularJS was JavaScript with controllers, `$scope` and a digest loop (end of life 2021); Angular is a TypeScript rewrite with components, DI, RxJS, AOT compilation and now signals.
- **vs React**: React is a UI library (you pick router, forms, state); Angular is a full framework with strong conventions, built-in DI and TypeScript-first.
- Modern Angular (v17-22): **standalone** components, built-in `@if/@for`, **signals**, **zoneless**, OnPush by default.

## Angular CLI
- `ng new app` (create) · `ng serve` (dev server :4200) · `ng build` (production to `dist/`) · `ng test` (Vitest) · `ng generate component|service|directive|pipe|guard|interceptor` (`ng g c x`) · `ng add` (install + configure a library) · `ng update` (upgrade with code migrations).
- Key files: `main.ts` (bootstraps), `app.config.ts` (app-wide providers), `app.routes.ts`, `angular.json` (build config).

## Components
> **What:** the building block of the UI: a TypeScript class + `@Component` metadata (`selector`, `template`/`templateUrl`, `styles`, `imports`, `changeDetection`).
- **Standalone** (default since v19): each component lists what its template uses in `imports`. **vs NgModules**: no module boilerplate, easier lazy loading, clearer dependencies. NgModules still work in older apps.
- Styles are **scoped** to the component (`ViewEncapsulation.Emulated` default; `ShadowDom`; `None` = global).
- Component vs directive: a component is a directive **with a template**.

## Data Binding
- **Interpolation** `{{ value }}`: class → text.
- **Property binding** `[src]="url"`: class → DOM property / child input. Also `[class.active]`, `[style.width.px]`, `[attr.aria-label]`.
- **Event binding** `(click)="save()"`: DOM / child output → class; `$event` holds the payload.
- **Two-way** `[(ngModel)]="name"` or `[(value)]` with `model()`: both directions (= property + event).
- **Template reference** `#box` then `box.value`; **`@let`** declares a template variable.

## Built-in Control Flow
> **What:** template blocks `@if / @else`, `@for (...; track id) / @empty`, `@switch / @case` (v17+).
- **vs `*ngIf`/`*ngFor`/`*ngSwitch`**: no imports, faster, better type narrowing, `track` is required so DOM is reused properly. The old structural directives are **deprecated since v20** (migrate with `ng g @angular/core:control-flow`).
- `@for` gives `$index`, `$first`, `$last`, `$even`, `$odd`, `$count`.
```html
@for (item of items(); track item.id) { <li>{{ item.name }}</li> }
@empty { <li>No items</li> }
```

## @defer (Deferrable Views)
> **What:** lazy-loads part of a template (and its components' code) when a trigger fires.
- Triggers: `on idle` (default), `on viewport`, `on interaction`, `on hover`, `on timer(2s)`, `when condition`; `prefetch on ...`.
- Blocks: `@placeholder`, `@loading`, `@error`. With SSR: `hydrate on ...` (incremental hydration).
- **Why**: smaller initial bundle without creating a route.

## Directives
- **Attribute directive**: changes look/behaviour of an existing element (`[appHighlight]`, `NgClass`, `NgStyle`). Uses `host` bindings and `ElementRef`.
- **Structural directive**: adds/removes DOM using `TemplateRef` + `ViewContainerRef` (the `*` prefix, e.g. `*appUnless`).
- **Host directives**: compose directives onto a component (`hostDirectives: [...]`).
- Prefer `[class.x]` / `[style.y]` bindings over `NgClass`/`NgStyle` for simple cases.

## Content Projection
> **What:** passing markup from a parent into a child's template with `<ng-content>`, like React `children` or Vue slots.
- Multi-slot: `<ng-content select="[card-title]">`. Fallback content inside `<ng-content>` (v18).
- `<ng-template>` = a template rendered only when used; `<ng-container>` = groups elements without adding a DOM node; `NgTemplateOutlet` renders a template with context.

## Inputs & Outputs
- **`input()`** (signal input): `name = input.required<string>()`, `size = input(10)`; read with `name()`. Transforms: `booleanAttribute`, `numberAttribute`.
- **`output()`**: `selected = output<string>()`; emit with `this.selected.emit(v)`.
- **`model()`**: a writable input + output for two-way binding `[(value)]`.
- **vs `@Input()` / `@Output() EventEmitter`**: signal inputs are reactive (use them in `computed`), no `ngOnChanges` needed, better typing.

## Component Communication
- Parent → child: **inputs**. Child → parent: **outputs**. Both: **model()**.
- Parent calls child methods: `viewChild(Child)` or a template ref `#child`.
- Siblings / unrelated: a shared **service** holding signals or a `BehaviorSubject`.
- Through the router: route params, query params, resolved data.
- Queries: `viewChild` / `viewChildren` (own template), `contentChild` / `contentChildren` (projected content).

## Services & Dependency Injection
> **What:** a **service** is a class for shared logic/data (API calls, state). **DI** means Angular creates it and hands it to whoever asks.
- `@Injectable({ providedIn: 'root' })` → one tree-shakable **singleton** for the app.
- Get it with `inject(Service)` (preferred) or a constructor parameter. `inject()` only works in an **injection context** (field initialisers, constructors, factories, guards, interceptors).
- **Why DI**: loose coupling, easy mocking in tests, one shared instance, configurable implementations.

## Providers & Injector Hierarchy
- Provider recipes: `useClass` (swap implementation), `useValue` (constant/config), `useFactory` (computed), `useExisting` (alias), `multi: true` (collect many).
- `InjectionToken<T>` for non-class values (config objects, URLs).
- Hierarchy: **root** injector → **route** injectors → **component (element)** injectors. Providing a service in a component's `providers` gives **each component instance its own copy**.
- Modifiers: `inject(X, { optional: true })`, `self`, `skipSelf`, `host`.

## Signals
> **What:** a reactive value that notifies its readers when it changes: `count = signal(0)`; read `count()`, write `count.set(1)` / `count.update(c => c + 1)`.
- **`computed()`**: derived, read-only, lazy and memoised. **`effect()`**: side effects (logging, storage) when signals change. **`linkedSignal()`**: writable value that resets from a source. **`untracked()`**: read without depending.
- **`resource()` / `httpResource()`**: load async data reactively (`value()`, `isLoading()`, `error()`).
- **vs RxJS / zone.js**: fine-grained updates (only views reading the signal re-render), synchronous and simple, enables **zoneless**. Use RxJS for event streams over time (debounce, websockets).
- Gotcha: signals compare with `===`: mutating an array/object in place → no update. Create new references.
```ts
const todos = signal<string[]>([]);
todos().push('x');                          // NOT detected
todos.update(list => [...list, 'x']);       // detected: new array
const total = computed(() => todos().length);
```

## RxJS & Observables
> **What:** an **Observable** is a lazy stream of values over time; you `subscribe` to receive them; operators transform them in `pipe()`.
- **Observable vs Promise**: lazy vs eager, many values vs one, cancellable (unsubscribe) vs not, rich operators vs `then`.
- **Subjects**: `Subject` (no initial value, late subscribers miss past values) · `BehaviorSubject` (has a current value, replays it) · `ReplaySubject(n)` (replays last n) · `AsyncSubject` (last value on complete).
- **Interop**: `toSignal(obs$)`, `toObservable(signal)`, `takeUntilDestroyed()`.

## RxJS Operators
- Transform: `map`, `filter`, `tap`, `scan`, `reduce`, `distinctUntilChanged`, `debounceTime`, `throttleTime`, `take`, `startWith`.
- Combine: `forkJoin` (all complete, one result: parallel HTTP), `combineLatest` (latest of each), `merge`, `concat`, `zip`, `withLatestFrom`.
- Errors: `catchError`, `retry`. Sharing: `shareReplay(1)`.
```text
switchMap   cancel previous    search box, route -> HTTP
mergeMap    all in parallel    independent requests
concatMap   one at a time      ordered saves
exhaustMap  ignore while busy  login / submit button
```

## Unsubscribing (memory leaks)
- Use the **`async` pipe** or **`toSignal`** (auto), **`takeUntilDestroyed()`**, `take(1)`, or unsubscribe in `ngOnDestroy`.
- HTTP observables complete by themselves; `interval`, `fromEvent`, Subjects, `valueChanges` and router events do **not**.

## Routing
> **What:** maps URLs to components for a single-page app: `provideRouter(routes)`, `<router-outlet>`, `routerLink`.
- Route options: `path`, `component`, `loadComponent` / `loadChildren` (**lazy loading**), `children`, `redirectTo` + `pathMatch: 'full'`, `**` wildcard (last), `title`, `data`, `resolve`, guards.
- Read params: input binding (`withComponentInputBinding()`), `ActivatedRoute.paramMap` (observable) or `snapshot`. Navigate: `router.navigate(['/products', id])`, `navigateByUrl`.
- **Lazy loading**: code split per route, downloaded only when visited → faster startup.

## Guards & Resolvers
- **Guards** decide navigation: `canActivate` (enter), `canActivateChild`, `canDeactivate` (leave, e.g. unsaved changes), `canMatch` (whether the route matches at all; lazy code not even loaded).
- Return `true`, `false`, a `UrlTree` or `RedirectCommand` (redirect), or an Observable/Promise of these.
- **Resolver** (`ResolveFn`): fetch data before the route activates.
- **Functional guards** (`CanActivateFn`) replaced class guards. Guards are UX only: the **server** must authorise.

## Forms: Template-Driven vs Reactive vs Signal
```text
            template-driven  reactive          signal forms (v22)
defined in  template         TS (FormGroup)    TS (signal model)
data flow   async, implicit  sync, explicit    signals
typing      weak             typed (v14+)      typed
testing     harder           easy              easy
best for    small, simple    complex, dynamic  new signal code
```
- Reactive building blocks: `FormControl`, `FormGroup`, `FormArray`, `FormBuilder` (`.nonNullable`). Validators: `required`, `email`, `min`, `max`, `minLength`, `maxLength`, `pattern`, custom `ValidatorFn`, async validators.
- State: `valid`, `invalid`, `pending`, `touched`, `dirty`, `errors`. `setValue` (all controls) vs `patchValue` (some). `value` omits disabled controls; `getRawValue()` includes them.

## ControlValueAccessor
> **What:** the interface that lets a **custom component** act as a form control (`formControlName`, `ngModel`).
- Methods: `writeValue` (model → view), `registerOnChange` (view → model), `registerOnTouched`, `setDisabledState`; registered with the `NG_VALUE_ACCESSOR` provider.

## Pipes
> **What:** template functions that **transform values for display**: `{{ price | currency:'INR' }}`.
- Built-in: `date`, `currency`, `number`, `percent`, `uppercase`, `lowercase`, `titlecase`, `json`, `slice`, `keyvalue`, `async`, `i18nPlural`.
- Custom: `@Pipe({ name })` + `transform(value, ...args)`.
- **Pure** (default): re-runs only when the input **reference** changes (cheap). **Impure** (`pure: false`): runs every change detection (costly).
- **async pipe**: subscribes, returns the latest value, marks for check, unsubscribes automatically.

## HttpClient
> **What:** Angular's HTTP service (`provideHttpClient()`), returning **typed Observables**: `http.get<User[]>('/api/users')`.
- Methods: `get`, `post`, `put`, `patch`, `delete`; options: `params` (`HttpParams`), `headers`, `observe: 'response'`, `responseType`.
- **Cold**: nothing is sent until you subscribe; subscribing twice sends twice.
- Errors: `catchError`, `retry`; `HttpErrorResponse.status` (0 = network error).
- **vs fetch**: typed, interceptors, RxJS operators (retry, cancel via `switchMap`), testing utilities. `httpResource()` (v22) is the signal-based way.

## Interceptors
> **What:** functions (`HttpInterceptorFn`) in the HttpClient pipeline that see every request and response.
- Uses: add auth tokens, logging, global error handling (401 → login), loading spinners, retries, caching.
- Requests are **immutable**: `req.clone({ setHeaders: { Authorization: 'Bearer ...' } })`.
- Register: `provideHttpClient(withInterceptors([authInterceptor]))`.

## Lifecycle Hooks
```text
constructor         DI only (inputs not set yet)
ngOnChanges         input changed (also before ngOnInit)
ngOnInit            once, inputs ready: load data
ngDoCheck           every change detection (custom check)
ngAfterContentInit  projected content ready
ngAfterViewInit     own view + children ready (viewChild)
ngOnDestroy         cleanup: unsubscribe, timers
```
- **Constructor vs ngOnInit**: constructor for injection; ngOnInit for initialisation that needs inputs.
- Newer: `DestroyRef.onDestroy()`, `afterNextRender()` / `afterEveryRender()` for DOM work.

## Change Detection
> **What:** the process that keeps the DOM in sync with component state by re-checking template bindings.
- **OnPush** (default in v22): a component is checked only when an **input reference** changes, a **template event** fires, a **signal** it reads changes, the **async pipe** emits, or `markForCheck()` is called. **Eager** (old "Default"): checked every time.
- **zone.js vs zoneless**: zone.js patches all async APIs and triggers CD after every event (simple but wasteful); **zoneless** (default v21+) relies on signals and explicit notifications: smaller, faster, predictable.
- `markForCheck()` = mark dirty for the next run; `detectChanges()` = run now.
- Error `ExpressionChangedAfterItHasBeenChecked`: a value changed during the check (often set in `ngAfterViewInit`).

## Performance
- Lazy routes + `@defer`; OnPush + signals; `track` by id in `@for`.
- No heavy function calls in templates (use `computed` or pure pipes).
- `NgOptimizedImage` (`ngSrc`, lazy loading, priority image), CDK virtual scroll for long lists, bundle budgets.
- **AOT** compilation (default): templates compiled at build time → faster start, errors caught early. **Ivy** (v9+): the rendering engine, tree-shakable.

## SSR & Hydration
- **SSR** (`ng new --ssr` / `@angular/ssr`): render HTML on the server → faster first paint, SEO.
- **Hydration**: the browser reuses server HTML instead of re-creating it (`provideClientHydration()`); **incremental hydration** hydrates `@defer` blocks later.
- **SSG / prerendering**: render routes at build time.

## Testing
- **TestBed** configures a test module; `TestBed.createComponent(X)` gives a `ComponentFixture`; set inputs with `fixture.componentRef.setInput()`; `await fixture.whenStable()`.
- Runners: **Vitest** (default since v21), Karma/Jasmine (older). HTTP: `provideHttpClientTesting()` + `HttpTestingController`. E2E: Playwright / Cypress.
- Services: `TestBed.inject(Service)` with mocked providers (`useValue`).

## Security
- Interpolation is **escaped**; `[innerHTML]`, `[href]`, `[src]` are **sanitised** automatically (XSS protection).
- `DomSanitizer.bypassSecurityTrust...` turns protection off: only for trusted content.
- HttpClient supports XSRF tokens. Prefer HttpOnly cookies over `localStorage` for tokens; guards are not security.

## Versions
- **2** (2016) rewrite · **9** Ivy · **14** typed forms, `inject()` · **15** standalone stable · **16** signals · **17** `@if/@for/@defer`, Vite/esbuild · **18** `@let`, zoneless preview.
- **19** standalone default, `linkedSignal`, `resource` · **20** `*ngIf` deprecated, zoneless stable · **21** zoneless + Vitest default.
- **22** (Jun 2026): **OnPush default**, Signal Forms, `httpResource`, TypeScript 6. Releases every 6 months, 18 months support.

## Interview One-Liners
- **Component vs directive**: directive with a template vs behaviour only.
- **Constructor vs ngOnInit**: DI vs initialisation with inputs.
- **Observable vs Promise**: lazy, many values, cancellable vs eager, single value.
- **Subject vs BehaviorSubject**: no current value vs replays current value.
- **switchMap vs mergeMap**: cancels previous vs runs all.
- **Pure vs impure pipe**: reference change vs every CD.
- **OnPush**: check only on new inputs, events, signals, async pipe.
- **providedIn: 'root'**: app-wide tree-shakable singleton.
- **Lazy loading**: `loadComponent`/`loadChildren` load code per route.
- **AOT vs JIT**: compile templates at build time vs in the browser.

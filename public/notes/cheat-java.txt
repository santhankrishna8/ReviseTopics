# 01 | Java Cheat Sheet | Concepts on one page: what each feature is, its key methods, why it beats the older way, and only the code that is tricky | Java on one page

## Java Platform: JDK, JRE, JVM
> **What:** Java compiles source code to **bytecode** (`.class`) that runs on the **JVM**, so the same program runs on any OS ("write once, run anywhere").
- **JVM**: runs bytecode; interpreter + **JIT** compiler that turns hot code into native code; manages memory with GC.
- **JRE** = JVM + core libraries (to run). **JDK** = JRE + tools: `javac`, `java`, `jar`, `jshell`, `jcmd` (to develop).
- **vs C++**: no pointers or manual `free`, garbage collected, single class inheritance, platform-independent bytecode; C++ compiles to native code and is closer to the hardware.

## Primitive vs Reference Types
> **What:** 8 **primitives** hold raw values on the stack/in objects; everything else is a **reference** to an object on the heap.
- Primitives: `byte` 8 · `short` 16 · `int` 32 · `long` 64 · `float` 32 · `double` 64 · `char` 16 (UTF-16) · `boolean`.
- Defaults (fields only): `0`, `0.0`, `'\u0000'`, `false`, `null`. Local variables have **no default**.
- **Wrapper classes** (`Integer`, `Double`...) let primitives live in collections and be `null`. **Autoboxing** converts automatically.
```java
Integer a = 127, b = 127;   // a == b  -> true  (cached -128..127)
Integer c = 128, d = 128;   // c == d  -> false (different objects)
c.equals(d);                // true: always compare wrappers with equals
```

## Casting & Arithmetic Traps
- **Widening** (int → long → double) is automatic; **narrowing** needs a cast and can lose data.
- `byte + byte` becomes `int`; compound operators (`+=`) cast back silently.
```java
int i = (int) 3.99;         // 3 (truncates)
byte b = (byte) 200;        // -56
7 / 2                       // 3   integer division
Integer.MAX_VALUE + 1       // -2147483648 (silent overflow)
long bad = 1000 * 60 * 60 * 24 * 365;   // overflows before widening
0.1 + 0.2                   // 0.30000000000000004 -> use BigDecimal("0.1") for money
```

## Strings
> **What:** `String` is an **immutable** sequence of characters; literals are stored once in the **string pool** and shared.
- **Key methods:** `length`, `charAt`, `substring`, `indexOf`, `contains`, `equals`, `equalsIgnoreCase`, `split`, `replace`, `trim`/`strip`, `toUpperCase`, `isBlank` (11), `repeat` (11), `String.join`, `chars`.
- **Why immutable:** safe sharing in the pool, thread safety, cached `hashCode` (great `HashMap` key), security (paths, class names can't change).
```java
String s1 = "java", s2 = "java", s3 = new String("java");
s1 == s2;        // true  (same pooled object)
s1 == s3;        // false (new object) -> compare text with equals
```

## String vs StringBuilder vs StringBuffer
```text
             mutable  thread-safe  speed
String       no       yes (immut.) slow for repeated +
StringBuilder yes     no           fastest
StringBuffer  yes     yes (sync)   slower, legacy
```
- Use `StringBuilder` when building text in a loop: `+` in a loop creates a new object every time.
- Key `StringBuilder` methods: `append`, `insert`, `delete`, `reverse`, `setCharAt`, `toString`.

## Arrays vs ArrayList
```text
               Array            ArrayList
size           fixed            grows automatically
types          primitives too   objects only (boxing)
length         arr.length       list.size()
methods        Arrays.* utils   add, remove, contains...
generics       no               yes, type-safe
```
- **Arrays utility:** `sort`, `binarySearch`, `fill`, `copyOf`, `asList`, `toString`, `stream`.

## OOP: the Four Pillars
- **Encapsulation**: hide fields (`private`) and expose behaviour through methods; protects invariants.
- **Inheritance**: a class reuses and extends another (`extends`); models "is-a".
- **Polymorphism**: one interface, many forms. **Compile-time** = overloading; **runtime** = overriding (dynamic dispatch picks the subclass method).
- **Abstraction**: expose what an object does, hide how (abstract classes, interfaces).
- Plus **composition** ("has-a"): prefer it over deep inheritance; it is more flexible.

## Classes, Objects & Constructors
> **What:** a **class** is a blueprint; an **object** is an instance created with `new` on the heap.
- **Constructor**: initialises a new object; same name as the class, no return type, not inherited. No constructor written → a default no-arg one is added.
- **Constructor chaining**: `this(...)` calls another constructor of the same class, `super(...)` the parent's; must be the first statement.
- **Java is always pass-by-value**: for objects the reference is copied, so a method can change the object's fields but not make the caller's variable point to a new object.

## static · final · this · super
- **static**: belongs to the class, not an object. Static fields are shared; static methods can't use `this`; static blocks run once when the class loads.
- **final**: variable = can't be reassigned (a final reference can still point to a mutable object); method = can't be overridden; class = can't be extended (`String`).
- **this**: the current object. **super**: the parent class's members or constructor.

## Access Modifiers
```text
            class  package  subclass  everywhere
private     yes    no       no        no
(default)   yes    yes      no        no
protected   yes    yes      yes       no
public      yes    yes      yes       yes
```
- Rule of thumb: fields `private`, methods as narrow as possible.

## Overloading vs Overriding
```text
                 Overloading          Overriding
where            same class           subclass
signature        different params     same params
decided at       compile time         runtime
return type      any                  same or subtype
static/private   allowed              not overridable
```
```java
static void f(long x)    { System.out.println("long"); }
static void f(Integer x) { System.out.println("Integer"); }
f(5);   // "long": widening is preferred over boxing
```

## Abstract Class vs Interface
> **Abstract class:** a partial class that can't be instantiated; shares **state and code** with subclasses. **Interface:** a **contract** of methods a class promises to provide.
```text
                abstract class      interface
state           instance fields     constants only
constructors    yes                 no
inheritance     extend only ONE     implement MANY
methods         any                 abstract, default (8),
                                    static (8), private (9)
use when        "is-a" + shared code "can-do" capability
```
- **Default methods** (Java 8) let interfaces add methods without breaking implementers. If two interfaces clash, the class must override and pick `A.super.m()`.

## Interface Types
- **Functional interface**: exactly one abstract method (`Runnable`, `Comparator`); can be implemented with a **lambda**.
- **Marker interface**: no methods, just tags a class (`Serializable`, `Cloneable`).
- Interface fields are implicitly `public static final`; methods implicitly `public abstract`.

## Enums
> **What:** a type with a **fixed set of named constants**, each a singleton object.
- Can have fields, constructors (always private), methods, and per-constant bodies; can implement interfaces; safe to compare with `==`; usable in `switch`.
- Built-ins: `values()`, `valueOf("X")`, `name()`, `ordinal()`. Fast collections: `EnumMap`, `EnumSet`.
- **vs int/String constants**: type-safe (no invalid values), readable, carry behaviour. `enum X { INSTANCE }` is the simplest thread-safe **singleton**.

## Records (Java 16)
> **What:** a concise **immutable data carrier**; `record Point(int x, int y) {}` auto-generates a constructor, accessors `x()`, `equals`, `hashCode`, `toString`.
- **vs POJO/Lombok**: no boilerplate, immutable by design, built into the language.
- **Limits**: fields are `final`, can't extend a class (can implement interfaces), no extra instance fields. Not for JPA entities (need mutability and a no-arg constructor).
- Validate in a **compact constructor**: `record Age(int v) { Age { if (v < 0) throw new IllegalArgumentException(); } }`.

## Sealed Classes & Pattern Matching
- **Sealed** (Java 17): `sealed interface Shape permits Circle, Square` restricts which classes can extend a type, so the compiler knows every subtype.
- **Pattern matching**: `if (obj instanceof String s)` tests and casts in one step (16). **Switch patterns** (21) match on type, deconstruct records, and add `when` guards.
- **Why**: replaces `instanceof` + cast chains; with sealed types a `switch` is checked for **exhaustiveness** (no `default` needed, adding a subtype breaks compilation until handled).

## Nested Classes
- **Static nested**: no link to an outer object; like a normal class inside another.
- **Inner (non-static)**: tied to an outer instance; can access its fields (holds a hidden reference: leak risk).
- **Local**: declared inside a method. **Anonymous**: unnamed one-off implementation, e.g. `new Runnable() {...}`.
- Prefer a **lambda** over an anonymous class for functional interfaces: shorter, and `this` means the enclosing object.

## equals, hashCode & Comparisons
- **equals** = logical equality (default compares references). **hashCode** = bucket number for hash collections.
- **Contract**: equal objects **must** have equal hash codes (unequal objects may collide). Override both, or `HashMap`/`HashSet` lookups fail.
- **Comparable** (`compareTo`, inside the class) = one natural order. **Comparator** (`compare`, outside) = any number of orders, composable: `Comparator.comparing(Emp::dept).thenComparing(Emp::salary).reversed()`.
- Don't write `return a - b;` (overflow): use `Integer.compare(a, b)`.

## Immutable Classes
> **What:** an object whose state can't change after construction (`String`, `Integer`, `LocalDate`).
- **Recipe**: `final` class, `private final` fields, no setters, set everything in the constructor, **defensive copies** of mutable inputs/outputs (`List.copyOf`). Or just use a **record**.
- **Why**: thread-safe without locks, safe as map keys, easy to reason about and cache.

## Exceptions
> **What:** an object representing an error that disrupts normal flow; thrown with `throw`, handled with `try/catch`.
- **Checked** (`IOException`, `SQLException`): compiler forces you to catch or declare (`throws`); recoverable conditions. **Unchecked** (`RuntimeException`: NPE, `IllegalArgumentException`...): programming errors, no forced handling. **Error** (`OutOfMemoryError`): JVM problems, don't catch.
- `throw` = throw one exception; `throws` = declare that a method may throw.
- `finally` always runs (except `System.exit` / JVM crash). Custom exception: extend `Exception` (checked) or `RuntimeException` (unchecked).
```java
static int f() {
  try { return 1; }
  finally { return 2; }   // returns 2 and would swallow exceptions: never return in finally
}
```

## try-with-resources (Java 7)
> **What:** `try (var r = open()) { ... }` closes any `AutoCloseable` resource automatically, in reverse order.
- **vs try/finally**: no forgotten `close()`, shorter, and if both the body and `close()` throw, the close error is kept as a **suppressed** exception instead of hiding the real one.
- Multi-catch: `catch (IOException | SQLException e)`. Catch specific exceptions before general ones.

## Collections Framework
> **What:** a set of interfaces and implementations for storing groups of objects, in `java.util`.
- Interfaces: **List** (ordered, duplicates) · **Set** (unique) · **Queue/Deque** (FIFO/LIFO) · **Map** (key → value, not a `Collection`).
- **vs arrays**: dynamic size, rich APIs (`contains`, `sort`, `removeIf`), generics, many data structures ready-made.
- Helpers: `Collections` (sort, reverse, max, unmodifiableList, synchronizedList), `Arrays`, `List.of/Set.of/Map.of`.

## ArrayList vs LinkedList vs Vector
```text
            ArrayList        LinkedList        Vector
structure   resizable array  doubly linked     array (legacy)
get(i)      O(1)             O(n)              O(1)
add/remove  O(n) middle      O(1) at ends      O(n)
memory      compact          extra node ptrs   compact
thread-safe no               no                yes (slow)
```
- Use **ArrayList** by default; `ArrayDeque` for queues/stacks; `CopyOnWriteArrayList` for concurrent reads.

## HashSet vs LinkedHashSet vs TreeSet
```text
             HashSet      LinkedHashSet  TreeSet
order        none         insertion      sorted
speed        O(1)         O(1)           O(log n)
null         one          one            no
backed by    HashMap      LinkedHashMap  TreeMap (red-black)
```
- `TreeSet` extras: `first`, `last`, `floor`, `ceiling`, `headSet`, `tailSet`.

## Map Implementations
```text
order      nulls    safe  get
HashMap           none       1 key    no    O(1)
LinkedHashMap     insertion  1 key    no    O(1)
TreeMap           sorted     no key   no    O(log n)
Hashtable         none       none     yes   O(1), slow
ConcurrentHashMap none       none     yes   O(1), fast
```
- `LinkedHashMap(16, 0.75f, true)` keeps **access** order: the basis of an LRU cache.
- Key methods: `put`, `get`, `getOrDefault`, `putIfAbsent`, `merge`, `computeIfAbsent`, `entrySet`, `keySet`, `values`, `forEach`.

## How HashMap Works
- An array of **buckets** (default 16). Index = `hash(key) & (n - 1)`; collisions are chained in a linked list.
- When a bucket has **8+** entries (and the table ≥ 64), it becomes a **red-black tree** (O(log n) worst case, Java 8).
- **Load factor 0.75**: when 75% full, the table **doubles** and entries are rehashed.
- `get` uses `hashCode` to find the bucket, then `equals` to find the key. Mutating a key after inserting it breaks lookups.

## Queue, Deque, Stack, PriorityQueue
- **Queue** (FIFO): `offer`, `poll`, `peek` (return null/false) vs `add`, `remove`, `element` (throw).
- **Deque**: both ends: `offerFirst/Last`, `pollFirst/Last`, `push`/`pop` for a stack. Use **ArrayDeque**, not the legacy synchronized `Stack`.
- **PriorityQueue**: a binary heap; `poll` returns the smallest (or by comparator). Iterating it is **not** sorted.
- **BlockingQueue** (`LinkedBlockingQueue`): `put`/`take` block when full/empty: producer-consumer.

## Iterators: Fail-Fast vs Fail-Safe
- **Fail-fast** (`ArrayList`, `HashMap`): throw `ConcurrentModificationException` if the collection is structurally changed while iterating.
- **Fail-safe / weakly consistent** (`CopyOnWriteArrayList`, `ConcurrentHashMap`): iterate a snapshot or tolerate changes, never throw.
```java
List<Integer> l = new ArrayList<>(List.of(10, 20, 30));
// for (Integer n : l) if (n == 20) l.remove(n);  -> ConcurrentModificationException
l.removeIf(n -> n == 20);        // correct way -> [10, 30]
l.add(1, 20);                    // back to [10, 20, 30]
l.remove(1);                     // removes INDEX 1 -> [10, 30]
l.remove(Integer.valueOf(10));   // removes the VALUE 10
```

## Immutable vs Unmodifiable Collections
- `List.of(...)` (9): truly **immutable**, no nulls. `List.copyOf(x)`: immutable snapshot.
- `Collections.unmodifiableList(x)`: a read-only **view**: changes to `x` still show through.
- `Arrays.asList(arr)`: **fixed-size** view of the array: `set` works, `add`/`remove` throw `UnsupportedOperationException`.
- `stream.toList()` (16): unmodifiable.

## Generics
> **What:** type parameters (`List<String>`, `class Box<T>`) that let one class or method work with many types **safely**.
- **Why vs raw types/Object**: errors caught at compile time, no casts, self-documenting APIs.
- **Bounded**: `<T extends Number>`. **Wildcards**: `List<?>` (unknown), `? extends T` (read), `? super T` (write). **PECS**: Producer Extends, Consumer Super.
- **Type erasure**: generics exist only at compile time; at runtime `List<String>` is just `List`. So no `new T()`, no `List<int>`, no `instanceof List<String>`.
- Generics are **invariant**: `List<Object> x = new ArrayList<String>()` doesn't compile (arrays are covariant and fail at runtime instead).

## Lambdas (Java 8)
> **What:** an anonymous function, `(params) -> body`, that implements a **functional interface**.
- **Why vs anonymous classes**: far less code, no extra `.class` file, clearer intent, `this` refers to the enclosing object; enables streams and functional APIs.
- Can use local variables only if they are **effectively final** (never reassigned).
- Example: `list.sort((a, b) -> a.length() - b.length())` vs a 5-line `new Comparator<>() {...}`.

## Functional Interfaces (java.util.function)
```text
Supplier<T>     () -> T          get()       a factory
Consumer<T>     T -> void        accept()    side effect
Function<T,R>   T -> R           apply()     transform
Predicate<T>    T -> boolean     test()      condition
BiFunction<T,U,R>, UnaryOperator<T>, BinaryOperator<T>
Runnable () -> void · Callable<V> () -> V (throws)
```
- Compose: `f.andThen(g)`, `f.compose(g)`, `p.and(q)`, `p.negate()`, `Predicate.not(...)`.

## Method References
- Shorthand for a lambda that only calls one method.
- **Static** `Integer::parseInt` · **bound instance** `System.out::println` · **unbound instance** `String::toUpperCase` · **constructor** `ArrayList::new`.

## Streams (Java 8)
> **What:** a **lazy pipeline** that processes elements from a source (collection, array, file) through chained operations; it stores no data and can be used **once**.
- **Intermediate** (lazy, return a stream): `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `skip`, `peek`.
- **Terminal** (run the pipeline): `collect`, `toList`, `forEach`, `reduce`, `count`, `min/max`, `findFirst`, `anyMatch/allMatch/noneMatch`.
- **Can do**: filter, transform, sort, group, partition, aggregate, flatten nested lists, parallel processing (`parallelStream`).
- **vs for-loops**: declarative (what, not how), less boilerplate, easy chaining and parallelism. Loops win for complex control flow, `break`/early exit with state, checked exceptions and tiny hot paths.
- **Tricky**: nothing runs until a terminal op; elements flow one at a time; `map` = 1:1, `flatMap` = 1:many flattened; `toList()` is unmodifiable.

## Collectors
- `toList`, `toSet`, `toMap(k, v)` (duplicate key → `IllegalStateException`; pass a merge function), `joining(", ")`.
- `groupingBy(f)` → `Map<K, List<T>>`; with a downstream collector: `counting()`, `summingInt`, `averagingDouble`, `mapping`, `maxBy`.
- `partitioningBy(pred)` → `Map<Boolean, List<T>>`. `teeing` (12) combines two collectors.
```java
// word frequency, the classic interview one-liner
Arrays.stream("a b a".split(" "))
      .collect(Collectors.groupingBy(Function.identity(), Collectors.counting()));  // {a=2, b=1}
```

## Optional (Java 8)
> **What:** a container that may or may not hold a value, used as a **return type** for "maybe no result".
- **Methods:** `of`, `ofNullable`, `empty`, `isPresent`, `isEmpty`, `orElse`, `orElseGet`, `orElseThrow`, `map`, `flatMap`, `filter`, `ifPresent`, `ifPresentOrElse`.
- **vs returning null**: makes absence explicit in the signature and forces callers to handle it, avoiding `NullPointerException`.
- **Tricky**: `orElse(x)` always evaluates `x`; `orElseGet(() -> x)` only when empty. Don't use `Optional` for fields, parameters or collections.

## Date & Time API (Java 8)
> **What:** `java.time`: `LocalDate`, `LocalTime`, `LocalDateTime`, `ZonedDateTime`, `Instant`, `Duration` (time-based), `Period` (date-based), `DateTimeFormatter`.
- **vs Date/Calendar/SimpleDateFormat**: immutable and **thread-safe**, clear API (months 1-12, not 0-11), proper time-zone support, fluent `plusDays`, `ChronoUnit.DAYS.between`.
- Store **`Instant`/UTC** in databases; convert to a zone only for display.

## I/O vs NIO
- **java.io**: **streams** of bytes (`InputStream`/`OutputStream`) or characters (`Reader`/`Writer`), blocking, one byte/char at a time, decorated with buffers (`BufferedReader`).
- **java.nio** (`Files`, `Path`, channels, buffers): simpler file API (`Files.readString`, `Files.lines`, `Files.walk`, `copy`, `move`), non-blocking channels, better error messages.
- Prefer `Files` + `Path` for files today; `BufferedReader` for big line-by-line reads.

## Serialization
> **What:** converting an object to bytes (`ObjectOutputStream`) and back; the class must implement the marker interface `Serializable`.
- `transient` fields are skipped; `static` fields aren't serialised; declare `serialVersionUID` to control versioning.
- **Risk**: deserialising untrusted bytes can execute code. Prefer JSON (Jackson) for data exchange.

## Threads
> **What:** an independent path of execution inside a process; threads share the heap but each has its own stack.
- **Create**: extend `Thread`, implement `Runnable` (preferred: keeps inheritance free), or submit a `Callable` to an executor.
- **Runnable vs Callable**: `run()` returns nothing, can't throw checked exceptions; `call()` returns a value (via `Future`) and can throw.
- **start() vs run()**: `start()` creates a new thread; calling `run()` just runs it on the current thread.
- States: NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED.
- **sleep vs wait**: `sleep` pauses and keeps locks; `wait` releases the object's lock until `notify`.

## Executor Framework
> **What:** thread pools that run tasks for you: `ExecutorService pool = Executors.newFixedThreadPool(4); pool.submit(task)`.
- **Why vs new Thread()**: reuses threads (creating them is expensive), bounds concurrency, queues tasks, returns `Future`s, clean `shutdown()`.
- Pools: `newFixedThreadPool`, `newCachedThreadPool`, `newSingleThreadExecutor`, `newScheduledThreadPool`, `newVirtualThreadPerTaskExecutor` (21).
- **Future**: `get()` blocks for the result; `cancel()`, `isDone()`.

## synchronized vs volatile vs Atomic vs Lock
```text
exclusive  visibility  notes
synchronized   yes        yes         simple, reentrant
volatile       no         yes         flags only
AtomicInteger  per op     yes         lock-free CAS
ReentrantLock  yes        yes         tryLock, timeout,
                                      fairness
```
- `count++` is **read-modify-write**: not atomic even if `volatile`. Use `synchronized` or `AtomicInteger.incrementAndGet()`.

## Concurrency Problems
- **Race condition**: result depends on thread timing (two threads updating a shared counter).
- **Deadlock**: threads wait forever for each other's locks. Prevent: always lock in the same order, `tryLock` with timeout, fewer locks.
- **Livelock**: threads keep reacting to each other and make no progress. **Starvation**: a thread never gets CPU or a lock.
- Find them with a thread dump: `jstack <pid>` / `jcmd <pid> Thread.print`.

## CompletableFuture (Java 8)
> **What:** a `Future` you can **chain and combine** without blocking: `supplyAsync(...).thenApply(...).thenAccept(...)`.
- **Key methods:** `thenApply` (map), `thenCompose` (chain another async call), `thenCombine` (join two), `allOf`/`anyOf`, `exceptionally`/`handle` (errors), `orTimeout` (9), `join`.
- **vs Future**: `Future.get()` blocks and can't be chained, combined or given callbacks.

## Concurrent Collections
- **ConcurrentHashMap**: thread-safe map with fine-grained locking and atomic `merge`, `compute`, `putIfAbsent`; no null keys/values.
- **CopyOnWriteArrayList**: copies on every write; great for many reads, rare writes (listeners).
- **BlockingQueue**: producer-consumer. **CountDownLatch** (wait for N events), **CyclicBarrier** (threads meet), **Semaphore** (limit to N concurrent users).
- **vs Collections.synchronizedMap/Hashtable**: those lock the whole object for every call; concurrent versions scale far better.

## Virtual Threads (Java 21)
> **What:** lightweight threads managed by the JVM, mounted on a few OS "carrier" threads; a blocking call parks the virtual thread instead of blocking the OS thread.
- **vs platform threads**: millions instead of thousands, cheap to create, so simple **thread-per-request** blocking code scales for I/O.
- **vs reactive (WebFlux)**: same scalability with ordinary sequential code and stack traces.
- Not faster for CPU-bound work; don't pool them; use a `Semaphore` to limit access to scarce resources.

## JVM Memory
```text
area       stores               scope       error
Heap       objects, arrays (GC) shared      OutOfMemoryError
Stack      frames, locals, refs per thread  StackOverflowError
Metaspace  class metadata (8+)  shared      OOM: Metaspace
PC reg     current instruction  per thread  -
```
- **Stack vs heap**: stack is small, fast, automatic (freed when a method returns); heap is large, shared, freed by GC.

## Garbage Collection
> **What:** the JVM automatically frees objects that are **unreachable** from GC roots (thread stacks, static fields).
- **Generations**: most objects die young → **Young** (Eden + Survivors, frequent minor GC) and **Old** (long-lived, major GC).
- **Collectors**: Serial · Parallel (throughput) · **G1** (default, balanced pauses) · **ZGC** / Shenandoah (sub-millisecond pauses, huge heaps).
- References: **strong** (normal) · **soft** (cleared before OOM, caches) · **weak** (cleared at next GC, `WeakHashMap`) · **phantom** (cleanup).
- **Memory leak** in Java = objects still referenced but no longer needed (static maps, caches, listeners, `ThreadLocal`s).
- Flags: `-Xms`/`-Xmx` heap size, `-XX:+UseZGC`, `-XX:+HeapDumpOnOutOfMemoryError`.

## Class Loading
- Loaders: **Bootstrap** (core `java.*`) → **Platform** → **Application** (your classpath). **Parent delegation**: a loader asks its parent first, so core classes can't be replaced.
- Phases: load → link (verify, prepare, resolve) → initialise (static blocks run).
- `ClassNotFoundException` (loading by name failed) vs `NoClassDefFoundError` (class was there at compile time, missing at runtime).

## Reflection & Annotations
- **Reflection**: inspect and use classes at runtime (`Class.forName`, `getMethods`, `invoke`, `setAccessible`). Powers Spring, Hibernate, JUnit, Jackson. Cost: slower, bypasses encapsulation.
- **Annotations**: metadata (`@Override`, `@Deprecated`, `@FunctionalInterface`, custom `@interface`). `@Retention(RUNTIME)` keeps them for reflection; `@Target` says where they apply.

## Design Patterns
- **Singleton**: one instance (enum or holder idiom). **Factory**: a method decides which object to create (`List.of`). **Builder**: step-by-step construction for many optional fields.
- **Strategy**: swap algorithms (pass a `Comparator`). **Observer**: notify listeners of events. **Decorator**: wrap to add behaviour (`BufferedReader`). **Adapter**: convert one interface to another (`Arrays.asList`). **Proxy**: a stand-in that adds behaviour (Spring AOP). **Template method**: base class defines steps, subclasses fill them.

## SOLID
- **S**ingle responsibility: one reason to change.
- **O**pen/closed: open for extension, closed for modification.
- **L**iskov substitution: a subclass must work wherever its parent does.
- **I**nterface segregation: small focused interfaces.
- **D**ependency inversion: depend on abstractions (what Spring DI does).

## Java Versions
- **8**: lambdas, streams, `Optional`, `java.time`, default methods, `CompletableFuture`.
- **11 LTS**: `var` (10), `HttpClient`, `String.isBlank/strip/repeat/lines`, `Files.readString`.
- **17 LTS**: switch expressions, text blocks, records, sealed classes, `instanceof` patterns.
- **21 LTS**: virtual threads, pattern matching for `switch`, record patterns, sequenced collections.
- **25 LTS** (2025): compact source files and `void main()`, scoped values, module imports, statements before `super()`. Latest release: 27.

## Tricky Outputs
```java
1 + 2 + "3" + 4 + 5          // "3345"
'a' + 'b'                    // 195 (char + char = int)
int i = 5; i = i++;          // i stays 5
Double.NaN == Double.NaN     // false
Math.abs(Integer.MIN_VALUE)  // -2147483648
short s = 1; s += 1.7;       // 2
String n = null; n + "x"     // "nullx"
new BigDecimal("2.0").equals(new BigDecimal("2.00"))  // false (scale differs)
```

# 01 | SQL Query Questions: The Logic | Every card is a commonly asked SQL interview question with the thinking first (which clause or technique solves it and why), then the query. Syntax is standard SQL; notes mark MySQL and PostgreSQL differences. | SQL query logic

### The Tables Used

## Sample Schema
> Every query below uses these tables.
```text
employees(emp_id, name, salary, dept_id, manager_id, hire_date, gender, email)
departments(dept_id, dept_name, city)
customers(customer_id, name, city)
orders(order_id, customer_id, order_date, amount)
order_items(order_id, product_id, qty, price)
products(product_id, name, category, price)
logins(user_id, login_date)
```
! `manager_id` points back to `emp_id` of the same table: that is the self-join table.

### Basic Filtering & Sorting

## Employees With Salary Above a Value / In a Range
> **Logic:** a plain `WHERE` filter.
```sql
SELECT * FROM employees WHERE salary > 50000;
SELECT * FROM employees WHERE salary BETWEEN 40000 AND 60000;      -- inclusive both ends
SELECT * FROM employees WHERE dept_id IN (1, 2) AND name LIKE 'A%';
```
! `BETWEEN` includes both ends; `LIKE 'A%'` starts with A.

## Names Starting/Ending With, Containing a Letter
> **Logic:** `LIKE` with wildcards: `%` any characters, `_` exactly one.
```sql
WHERE name LIKE 'A%'       -- starts with A
WHERE name LIKE '%a'       -- ends with a
WHERE name LIKE '%an%'     -- contains an
WHERE name LIKE '_a%'      -- second letter is a
```
! A leading `%` cannot use an index.

## Find Rows With NULL / Replace NULL
> **Logic:** `= NULL` never works. Use `IS NULL`. Replace with `COALESCE`.
```sql
SELECT * FROM employees WHERE manager_id IS NULL;
SELECT name, COALESCE(email, 'not provided') FROM employees;
```
! NULL compared with anything is unknown, not true.

## Top N Rows / Latest Records
> **Logic:** sort, then cut.
```sql
SELECT * FROM employees ORDER BY salary DESC LIMIT 5;                 -- MySQL / PostgreSQL
SELECT TOP 5 * FROM employees ORDER BY salary DESC;                   -- SQL Server
SELECT * FROM employees ORDER BY salary DESC FETCH FIRST 5 ROWS ONLY; -- Oracle, standard
```
! No `ORDER BY` means no meaningful "top".

### Salary & Ranking Questions

## Second Highest Salary (3 ways)
> **Logic:** the biggest value that is smaller than the maximum.
```sql
-- 1. Subquery
SELECT MAX(salary) FROM employees WHERE salary < (SELECT MAX(salary) FROM employees);
-- 2. Offset
SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1;
-- 3. Window function (best for Nth)
SELECT salary FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) r FROM employees) t WHERE r = 2;
```
- If there is no second value, ways 1 and 3 give NULL / no rows; wrap with `(SELECT ...)` or `IFNULL` to return NULL explicitly.
! DISTINCT matters, otherwise ties count as separate ranks.

## Nth Highest Salary
> **Logic:** `DENSE_RANK` so equal salaries share a rank, then filter `= N`.
```sql
SELECT DISTINCT salary FROM (
  SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) r FROM employees) t
WHERE r = :n;
-- without windows: SELECT DISTINCT salary ... ORDER BY salary DESC LIMIT 1 OFFSET n-1;
```
! DENSE_RANK for "Nth distinct", ROW_NUMBER for "Nth row".

## Highest Salary in Each Department (Whole Employee Row)
> **Logic:** compare each employee with the max of their own department, or rank per department.
```sql
SELECT e.* FROM employees e
WHERE salary = (SELECT MAX(salary) FROM employees WHERE dept_id = e.dept_id);   -- correlated

SELECT * FROM (SELECT e.*, RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) r FROM employees e) t WHERE r = 1;
```
- `GROUP BY dept_id` with `MAX(salary)` alone only gives the number, not who earns it.
! Group gives the number, window or join gives the person.

## Top N Salaries Per Department
> **Logic:** `PARTITION BY dept_id`, rank inside each group, keep rank ≤ N.
```sql
SELECT * FROM (
  SELECT e.*, DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) r FROM employees e) t
WHERE r <= 3;
```
! Rank in a subquery, filter outside: you cannot filter a window result in the same `WHERE`.

## Employees Earning More Than the Average / Department Average
> **Logic:** compare each row with an aggregate.
```sql
SELECT * FROM employees WHERE salary > (SELECT AVG(salary) FROM employees);

SELECT e.* FROM employees e
JOIN (SELECT dept_id, AVG(salary) a FROM employees GROUP BY dept_id) d ON d.dept_id = e.dept_id
WHERE e.salary > d.a;                       -- above own department average
```
! Aggregate in a subquery or join, then compare.

## Employees Earning More Than Their Manager
> **Logic:** **self join**: employee row joined to manager row from the same table.
```sql
SELECT e.name FROM employees e
JOIN employees m ON e.manager_id = m.emp_id
WHERE e.salary > m.salary;
```
! Alias the same table twice: e (employee) and m (manager).

## Department Totals, Averages and Departments Above a Threshold
> **Logic:** `GROUP BY` for per-group numbers; `HAVING` filters the groups.
```sql
SELECT dept_id, COUNT(*) cnt, SUM(salary) total, AVG(salary) avg_sal, MAX(salary) top
FROM employees GROUP BY dept_id HAVING COUNT(*) > 5;
```
! WHERE filters rows before grouping, HAVING filters groups after.

### Duplicates

## Find Duplicate Rows / Values
> **Logic:** group by the column(s) and keep groups with more than one row.
```sql
SELECT email, COUNT(*) FROM employees GROUP BY email HAVING COUNT(*) > 1;
```
! Group by every column that defines "duplicate".

## Delete Duplicates (Keep One)
> **Logic:** number the rows inside each duplicate group, delete everything beyond row 1.
```sql
-- keep the lowest id (works everywhere)
DELETE FROM employees WHERE emp_id NOT IN (
  SELECT MIN(emp_id) FROM employees GROUP BY email);          -- MySQL needs a derived table around the subquery

-- window version (PostgreSQL / SQL Server)
DELETE FROM employees WHERE emp_id IN (
  SELECT emp_id FROM (SELECT emp_id, ROW_NUMBER() OVER (PARTITION BY email ORDER BY emp_id) rn FROM employees) t WHERE rn > 1);
```
! Always run the SELECT version first.

## Find Distinct Values Without DISTINCT / Count Distinct
> **Logic:** `GROUP BY` gives distinct values too.
```sql
SELECT dept_id FROM employees GROUP BY dept_id;
SELECT COUNT(DISTINCT dept_id) FROM employees;
```
! DISTINCT and GROUP BY both dedupe.

### Joins & Missing Data

## Customers Who Never Placed an Order (Anti-Join)
> **Logic:** keep all customers, then keep only those with no match.
```sql
SELECT c.* FROM customers c LEFT JOIN orders o ON o.customer_id = c.customer_id WHERE o.order_id IS NULL;
SELECT * FROM customers c WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);
```
- Avoid `NOT IN (subquery)`: one NULL in the subquery returns no rows at all.
! LEFT JOIN + IS NULL, or NOT EXISTS.

## Count Per Group Including Zero (Empty Departments)
> **Logic:** LEFT JOIN from the "all groups" table, then `COUNT(child.column)` (not `COUNT(*)`).
```sql
SELECT d.dept_name, COUNT(e.emp_id) cnt
FROM departments d LEFT JOIN employees e ON e.dept_id = d.dept_id
GROUP BY d.dept_id, d.dept_name;
```
! `COUNT(*)` would count the NULL row as 1.

## Employees Without a Department / Departments Without Employees
> **Logic:** one-sided join and test the other side for NULL.
```sql
SELECT e.* FROM employees e LEFT JOIN departments d ON d.dept_id = e.dept_id WHERE d.dept_id IS NULL;
SELECT d.* FROM departments d LEFT JOIN employees e ON e.dept_id = d.dept_id WHERE e.emp_id IS NULL;
```
! Same anti-join pattern with the tables swapped.

## Employee With Manager Name (Self Join, Include Top Boss)
> **Logic:** LEFT self join so the CEO (no manager) is not lost.
```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e LEFT JOIN employees m ON e.manager_id = m.emp_id;
```
! INNER JOIN drops employees with no manager.

## Employees With the Same Salary / Pairs in the Same Department
> **Logic:** self join on the shared value with `a.id < b.id` to avoid duplicates and self-pairs.
```sql
SELECT a.name, b.name FROM employees a JOIN employees b
  ON a.salary = b.salary AND a.emp_id < b.emp_id;
```
! `<` gives each pair once.

## Rows in Table A Not in Table B / Common Rows
> **Logic:** set operations or anti-join.
```sql
SELECT id FROM a EXCEPT SELECT id FROM b;          -- MINUS in Oracle
SELECT id FROM a INTERSECT SELECT id FROM b;
```
! Both queries need the same column count and types.

## Customers Who Bought All Products (Relational Division)
> **Logic:** group by customer and compare the distinct product count with the total.
```sql
SELECT o.customer_id FROM orders o JOIN order_items i ON i.order_id = o.order_id
GROUP BY o.customer_id
HAVING COUNT(DISTINCT i.product_id) = (SELECT COUNT(*) FROM products);
```
! "All" means count equals the total count.

## Orders With Customer and Product Details (Multi-Table Join)
> **Logic:** chain joins following the foreign keys.
```sql
SELECT c.name, o.order_id, p.name, i.qty * i.price AS line_total
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
JOIN order_items i ON i.order_id = o.order_id
JOIN products p ON p.product_id = i.product_id;
```
! Draw the keys first, then join in a chain.

### Aggregation & Reporting

## Total Sales Per Customer / Per Month
> **Logic:** group by the key; for months, truncate the date.
```sql
SELECT customer_id, SUM(amount) FROM orders GROUP BY customer_id ORDER BY 2 DESC;
SELECT DATE_FORMAT(order_date, '%Y-%m') ym, SUM(amount) FROM orders GROUP BY ym;      -- MySQL
SELECT DATE_TRUNC('month', order_date) m, SUM(amount) FROM orders GROUP BY m;         -- PostgreSQL
```
! Truncate the date to the bucket you want, then group.

## Customers With More Than N Orders / Orders Above Average
> **Logic:** group + HAVING; or compare to a scalar subquery.
```sql
SELECT customer_id, COUNT(*) FROM orders GROUP BY customer_id HAVING COUNT(*) >= 3;
SELECT * FROM orders WHERE amount > (SELECT AVG(amount) FROM orders);
```
! Aggregate comparisons need HAVING or a subquery.

## Percentage of Total
> **Logic:** each group's sum divided by the grand total (a window over everything).
```sql
SELECT dept_id, SUM(salary) * 100.0 / SUM(SUM(salary)) OVER () AS pct
FROM employees GROUP BY dept_id;
```
! `100.0` forces decimal division.

## Pivot Rows to Columns (Conditional Aggregation)
> **Logic:** `SUM(CASE WHEN ... THEN ... END)` per column.
```sql
SELECT dept_id,
       SUM(CASE WHEN gender = 'M' THEN 1 ELSE 0 END) AS male,
       SUM(CASE WHEN gender = 'F' THEN 1 ELSE 0 END) AS female
FROM employees GROUP BY dept_id;
```
! CASE inside an aggregate is the universal pivot.

## Swap Values (M ↔ F) With One UPDATE
> **Logic:** a single `CASE` evaluated per row.
```sql
UPDATE employees SET gender = CASE gender WHEN 'M' THEN 'F' WHEN 'F' THEN 'M' ELSE gender END;
```
! Never do it with two updates; the second would undo the first.

## ROLLUP: Subtotals and Grand Total
> **Logic:** `GROUP BY ROLLUP` adds subtotal rows.
```sql
SELECT dept_id, gender, SUM(salary) FROM employees GROUP BY ROLLUP (dept_id, gender);   -- MySQL: GROUP BY dept_id, gender WITH ROLLUP
```
! NULL in a group column marks a subtotal row.

### Window Functions

## Running Total & Moving Average
> **Logic:** an aggregate with `OVER (ORDER BY ...)`; a frame limits the rows.
```sql
SELECT order_date, amount,
       SUM(amount) OVER (ORDER BY order_date) AS running,
       AVG(amount) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS avg7
FROM orders;
```
! Without `PARTITION BY` the window is the whole table.

## Compare With the Previous / Next Row (LAG, LEAD)
> **Logic:** `LAG` reads the previous row, `LEAD` the next row, in a defined order.
```sql
SELECT order_date, amount, amount - LAG(amount) OVER (ORDER BY order_date) AS change FROM orders;
-- rows where value increased vs yesterday
SELECT * FROM (SELECT *, LAG(amount) OVER (ORDER BY order_date) prev FROM orders) t WHERE amount > prev;
```
! A self join on `date = date + 1` is the alternative but fails with gaps.

## ROW_NUMBER vs RANK vs DENSE_RANK
> **Logic:** how ties are numbered.
```text
salary: 90 90 80      ROW_NUMBER 1 2 3     RANK 1 1 3     DENSE_RANK 1 1 2
```
! ROW_NUMBER never repeats, RANK skips, DENSE_RANK does not skip.

## First and Last Record Per Group
> **Logic:** rank by date ascending for first, descending for last, keep rank 1.
```sql
SELECT * FROM (SELECT o.*, ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date DESC) rn FROM orders o) t WHERE rn = 1;   -- latest order per customer
```
! ROW_NUMBER guarantees exactly one row per group.

## Second Order Per Customer / Nth Row Per Group
> **Logic:** same pattern, `rn = 2`.
```sql
SELECT * FROM (SELECT o.*, ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date) rn FROM orders o) t WHERE rn = 2;
```
! Change the number, not the structure.

## Median Salary
> **Logic:** the middle value; average the two middle rows if the count is even.
```sql
SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY salary) FROM employees;     -- PostgreSQL / Oracle

SELECT AVG(salary) FROM (                                                      -- portable
  SELECT salary, ROW_NUMBER() OVER (ORDER BY salary) rn, COUNT(*) OVER () cnt FROM employees) t
WHERE rn IN (FLOOR((cnt + 1) / 2.0), FLOOR((cnt + 2) / 2.0));     -- 8 rows: 4 and 5; 7 rows: 4 and 4
```
! Number the rows and pick the middle one or two.

## Month-over-Month / Year-over-Year Growth
> **Logic:** aggregate per period, then compare with `LAG`.
```sql
WITH m AS (SELECT DATE_TRUNC('month', order_date) mon, SUM(amount) rev FROM orders GROUP BY 1)
SELECT mon, rev, ROUND(100.0 * (rev - LAG(rev) OVER (ORDER BY mon)) / LAG(rev) OVER (ORDER BY mon), 2) AS growth_pct FROM m;
```
! Aggregate first in a CTE, then window over the result.

## Cumulative Count of New Customers / Distinct Counts Over Time
> **Logic:** take each customer's first date, count per day, then running total.
```sql
WITH f AS (SELECT customer_id, MIN(order_date) first_d FROM orders GROUP BY customer_id)
SELECT first_d, COUNT(*) new_cust, SUM(COUNT(*)) OVER (ORDER BY first_d) total FROM f GROUP BY first_d;
```
! MIN per user gives the "first seen" date.

### Dates & Sequences

## Consecutive Days Logins (Gaps and Islands)
> **Logic:** subtract a row number from the date. Consecutive days give the **same constant**, so group by it.
```sql
SELECT user_id, MIN(login_date) start_d, MAX(login_date) end_d, COUNT(*) streak
FROM (SELECT user_id, login_date,
             login_date - ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) * INTERVAL '1 day' AS grp
      FROM (SELECT DISTINCT user_id, login_date FROM logins) d) t
GROUP BY user_id, grp HAVING COUNT(*) >= 3;
```
- Simpler for exactly 3 in a row: `LAG(login_date, 2)` and check `login_date - lag2 = 2`.
! Date minus row number is constant inside a streak.

## Find Missing Numbers / Gaps in IDs
> **Logic:** compare each id with the next one.
```sql
SELECT id + 1 AS gap_start, next_id - 1 AS gap_end
FROM (SELECT id, LEAD(id) OVER (ORDER BY id) next_id FROM t) x
WHERE next_id - id > 1;
```
! A jump greater than 1 means a gap.

## Employees Hired in the Last N Days / This Month / Year
> **Logic:** date arithmetic in `WHERE`.
```sql
WHERE hire_date >= CURRENT_DATE - INTERVAL '30 days'                 -- PostgreSQL
WHERE hire_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)              -- MySQL
WHERE EXTRACT(YEAR FROM hire_date) = 2025                             -- better: hire_date >= '2025-01-01' AND hire_date < '2026-01-01'
```
! Compare the raw column against a range so an index can be used.

## Count Orders by Weekday / Age / Tenure
> **Logic:** extract the part you need and group by it.
```sql
SELECT DAYNAME(order_date), COUNT(*) FROM orders GROUP BY 1;          -- MySQL; PostgreSQL: TO_CHAR(order_date,'Day')
SELECT name, TIMESTAMPDIFF(YEAR, hire_date, CURDATE()) AS years FROM employees;     -- MySQL
```
! Date functions differ by database: say which one you use.

## Customer Retention: Users Who Came Back
> **Logic:** self join logins on the same user the next day, or compare first-day and later activity.
```sql
SELECT COUNT(DISTINCT a.user_id) FROM logins a JOIN logins b
  ON a.user_id = b.user_id AND b.login_date = a.login_date + INTERVAL '1 day';
```
! Self join on `date + 1` finds next-day returners.

### Hierarchies & Subqueries

## Employee Hierarchy (Recursive CTE)
> **Logic:** start from the root, repeatedly add direct reports.
```sql
WITH RECURSIVE tree AS (
  SELECT emp_id, name, manager_id, 1 AS lvl FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.emp_id, e.name, e.manager_id, t.lvl + 1 FROM employees e JOIN tree t ON e.manager_id = t.emp_id)
SELECT * FROM tree ORDER BY lvl;
```
! Anchor, UNION ALL, recursive step.

## Managers and Their Number of Reports
> **Logic:** group employees by `manager_id`.
```sql
SELECT m.name, COUNT(e.emp_id) reports FROM employees m JOIN employees e ON e.manager_id = m.emp_id GROUP BY m.emp_id, m.name HAVING COUNT(*) > 2;
```
! The manager row joins to all rows that point at it.

## Correlated Subquery vs JOIN vs EXISTS
> **Logic:** a correlated subquery runs per outer row; `EXISTS` stops at the first match.
```sql
SELECT * FROM departments d WHERE EXISTS (SELECT 1 FROM employees e WHERE e.dept_id = d.dept_id);   -- departments that have employees
SELECT * FROM departments WHERE dept_id IN (SELECT dept_id FROM employees);
```
! EXISTS for "has any", NOT EXISTS for "has none".

## Replace a Subquery With a JOIN, Update From Another Table
> **Logic:** join to supply the new value.
```sql
UPDATE employees e JOIN departments d ON d.dept_id = e.dept_id SET e.salary = e.salary * 1.1 WHERE d.dept_name = 'Sales';   -- MySQL
UPDATE employees e SET salary = salary * 1.1 FROM departments d WHERE d.dept_id = e.dept_id AND d.dept_name = 'Sales';      -- PostgreSQL
```
! Test the join with a SELECT before the UPDATE.

### Strings, Data Cleanup & Utility

## String Questions (Length, Reverse, Palindrome, Initials)
> **Logic:** built-in string functions.
```sql
SELECT name, LENGTH(name), UPPER(name), REVERSE(name), SUBSTRING(name, 1, 3) FROM employees;
SELECT name FROM employees WHERE name = REVERSE(name);                 -- palindromes
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM employees;
SELECT SUBSTRING_INDEX(email, '@', -1) AS domain FROM employees;       -- MySQL
```
! Trim and lowercase before comparing user text.

## Count Occurrences of a Character in a String
> **Logic:** length minus the length after removing that character.
```sql
SELECT name, LENGTH(name) - LENGTH(REPLACE(LOWER(name), 'a', '')) AS a_count FROM employees;
```
! Removed characters = the difference in length.

## Delete vs Truncate Rows, Copy a Table, Insert From Select
> **Logic:**
```sql
INSERT INTO emp_backup SELECT * FROM employees;                   -- copy rows
CREATE TABLE emp_copy AS SELECT * FROM employees;                 -- copy structure + data (no indexes)
CREATE TABLE emp_empty AS SELECT * FROM employees WHERE 1 = 0;    -- structure only
DELETE FROM employees WHERE dept_id = 3;                          -- rollback possible, row by row
TRUNCATE TABLE logs;                                              -- fast, resets the table
```
! `WHERE 1 = 0` copies structure without rows.

## Find the Table Structure, Row Counts, and Duplicates of Tables
> **Logic:** metadata views.
```sql
DESCRIBE employees;                                                -- MySQL;  \d employees in psql
SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'employees';
SELECT table_name FROM information_schema.tables WHERE table_schema = 'public';
SELECT COUNT(*) FROM employees;
```
! `information_schema` works in most databases.

### Last-Minute Checklist

## Pattern Cheat List: Which Technique for Which Question?
> **Logic:** match the question wording to the tool.
```text
"Nth highest / top N per group"       DENSE_RANK / ROW_NUMBER with PARTITION BY
"more than the average / their boss"  subquery or self join
"never / no / without"                LEFT JOIN ... IS NULL  or  NOT EXISTS
"duplicates"                          GROUP BY ... HAVING COUNT(*) > 1
"delete duplicates"                   ROW_NUMBER() > 1  or  keep MIN(id)
"consecutive / streak"                date - ROW_NUMBER() grouping, or LAG
"running total / moving average"      SUM/AVG OVER (ORDER BY ...)
"compare with previous"               LAG / LEAD
"each category as a column"           SUM(CASE WHEN ...) pivot
"hierarchy / org chart"               recursive CTE
"all / every"                         COUNT(DISTINCT) = total count
"per month / per year"                DATE_TRUNC / DATE_FORMAT then GROUP BY
```
! Say the technique out loud first, then write the query.

## Mistakes Interviewers Watch For
> **Logic:** habits that signal experience.
- Filtering a LEFT JOINed table in `WHERE` instead of `ON`.
- `COUNT(*)` where `COUNT(column)` is needed; `NOT IN` with possible NULLs.
- Wrapping an indexed column in a function; `SELECT *` in production queries.
- Missing `ORDER BY` with `LIMIT`; no tiebreaker so results differ run to run.
- Integer division (`5/2 = 2`): multiply by `1.0`.
- Joining a 1-to-many table then summing: it **duplicates** the parent values.
! Handle NULLs, ties and duplicates explicitly.

## The Idea
> DP is **recursion that remembers**. If you keep being asked the same question while solving a problem, write the answer down the first time and look it up after that. Like a student who writes down 7 × 8 = 56 instead of recomputing it.
- Use DP when a problem has **(1) overlapping subproblems** (the same smaller question appears again and again) and **(2) optimal substructure** (the best answer is built from best answers to smaller questions).
- Typical wording: "**how many ways**", "**minimum / maximum** ...", "**is it possible** to ...", "**longest** ...".
- Plain recursion on these problems is **exponential**. DP makes them **polynomial** by solving each distinct subproblem once.
! DP = a recursive definition + a table of answers. If you can write the recursion, you can write the DP.

## Fibonacci: the Whole Idea in 20 Lines
```java FibDp.java
class Fib {
  static long naive(int n) { return n < 2 ? n : naive(n - 1) + naive(n - 2); }   // O(2^n): fib(3) solved over and over

  static long topDown(int n, long[] memo) {            // memoization: recursion + a cache
    if (n < 2) return n;
    if (memo[n] != 0) return memo[n];                  // already solved: look it up
    return memo[n] = topDown(n - 1, memo) + topDown(n - 2, memo);
  }
  static long bottomUp(int n) {                        // tabulation: fill the table from the smallest subproblem up
    if (n < 2) return n;
    long[] dp = new long[n + 1];
    dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
  }
  static long constantSpace(int n) {                   // the recurrence only looks back 2 steps: keep just 2 values
    if (n < 2) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) { long c = a + b; a = b; b = c; }
    return b;
  }
}
```
- **Top-down (memoization)**: write the natural recursion, add a cache. Easy to write, computes only needed states, but uses recursion depth.
- **Bottom-up (tabulation)**: fill an array in the right order. No recursion, easy to optimise space.
- **Space optimisation**: if `dp[i]` only needs the previous one or two entries, keep variables instead of an array.

## The 5-Step Recipe (memorise)
> **1. State**: what does `dp[i]` mean, in words? **2. Recurrence**: how does `dp[i]` come from smaller states? **3. Base cases**. **4. Order**: compute smaller states first. **5. Answer**: which cell holds it?
- Step 1 is everything. Write the sentence: "`dp[i]` = the minimum number of coins needed to make amount `i`". If you cannot say it in a sentence, you do not have a state yet.
- Ask: "**What is the last decision?**" The last coin chosen, whether the last house is robbed, whether the last character matches. The recurrence is the list of options for that last decision.
! Define the state in words first. Then ask: what was the last choice?

## Linear DP: Climbing Stairs, Min Cost, House Robber
```java LinearDp.java
class Solution {
  public int climbStairs(int n) {                        // LeetCode 70: 1 or 2 steps at a time
    int a = 1, b = 1;                                    // ways to reach step 0 and step 1
    for (int i = 2; i <= n; i++) { int c = a + b; a = b; b = c; }   // ways(i) = ways(i-1) + ways(i-2)
    return b;
  }
  public int minCostClimbingStairs(int[] cost) {         // LeetCode 746: start at step 0 or 1, reach the top
    int a = 0, b = 0;                                    // cheapest cost to stand on step i-2 and step i-1
    for (int i = 2; i <= cost.length; i++) {
      int c = Math.min(b + cost[i - 1], a + cost[i - 2]);
      a = b; b = c;
    }
    return b;
  }
  public int rob(int[] nums) {                           // LeetCode 198: cannot rob two adjacent houses
    int prev2 = 0, prev1 = 0;                            // best loot up to house i-2 and i-1
    for (int x : nums) {
      int cur = Math.max(prev1, prev2 + x);              // skip this house, or rob it and use the best up to i-2
      prev2 = prev1;
      prev1 = cur;
    }
    return prev1;
  }
  public int robCircular(int[] nums) {                   // LeetCode 213: houses in a circle (first and last are adjacent)
    if (nums.length == 1) return nums[0];
    return Math.max(robRange(nums, 0, nums.length - 2), robRange(nums, 1, nums.length - 1));   // exclude first, or exclude last
  }
  private int robRange(int[] a, int lo, int hi) {
    int prev2 = 0, prev1 = 0;
    for (int i = lo; i <= hi; i++) { int cur = Math.max(prev1, prev2 + a[i]); prev2 = prev1; prev1 = cur; }
    return prev1;
  }
}
```
- **House robber thinking**: for house `i`, the last decision is "rob" (then house `i-1` is off limits: `dp[i-2] + nums[i]`) or "skip" (`dp[i-1]`). Take the max. Many "pick items with no neighbours" problems reduce to this (Delete and Earn).

## Unbounded Knapsack: Coin Change (min coins) and Ways
> **State**: `dp[a]` = fewest coins to make amount `a`. **Last decision**: which coin was used last? `dp[a] = 1 + min(dp[a - coin])` over coins that fit. **Base**: `dp[0] = 0`. Start every other cell at "infinity".
```java CoinChange.java
class Solution {
  public int coinChange(int[] coins, int amount) {       // LeetCode 322: fewest coins, -1 if impossible
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);                         // "infinity": more coins than could ever be needed
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
      for (int c : coins)
        if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
  }
  public int change(int amount, int[] coins) {           // LeetCode 518: number of COMBINATIONS (order does not matter)
    int[] dp = new int[amount + 1];
    dp[0] = 1;                                           // one way to make 0: use nothing
    for (int c : coins)                                  // coins on the OUTSIDE: each combination is counted once
      for (int a = c; a <= amount; a++) dp[a] += dp[a - c];
    return dp[amount];
  }
  public int combinationSum4(int[] nums, int target) {   // LeetCode 377: number of ORDERED sequences (permutations)
    int[] dp = new int[target + 1];
    dp[0] = 1;
    for (int t = 1; t <= target; t++)                    // amounts on the OUTSIDE: different orders are counted separately
      for (int x : nums) if (x <= t) dp[t] += dp[t - x];
    return dp[target];
  }
  public int numSquares(int n) {                         // LeetCode 279: fewest perfect squares that sum to n
    int[] dp = new int[n + 1];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int i = 1; i <= n; i++)
      for (int j = 1; j * j <= i; j++) dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
    return dp[n];
  }
}
```
! Loop order decides what you count: **items outside, amounts inside → combinations**. **Amounts outside, items inside → permutations.**

## Strings as Linear DP: Word Break, Decode Ways
```java StringDp.java
class Solution {
  public boolean wordBreak(String s, List<String> wordDict) {   // LeetCode 139
    Set<String> words = new HashSet<>(wordDict);
    boolean[] dp = new boolean[s.length() + 1];          // dp[i] = can the first i characters be segmented?
    dp[0] = true;                                        // the empty prefix is fine
    for (int i = 1; i <= s.length(); i++)
      for (int j = 0; j < i; j++)                        // last word = s[j..i)
        if (dp[j] && words.contains(s.substring(j, i))) { dp[i] = true; break; }
    return dp[s.length()];
  }
  public int numDecodings(String s) {                    // LeetCode 91: "12" -> AB or L = 2 ways
    int n = s.length();
    int[] dp = new int[n + 1];                           // dp[i] = ways to decode the first i characters
    dp[0] = 1;
    dp[1] = s.charAt(0) == '0' ? 0 : 1;
    for (int i = 2; i <= n; i++) {
      int one = s.charAt(i - 1) - '0';                   // last digit alone
      int two = Integer.parseInt(s.substring(i - 2, i)); // last two digits together
      if (one >= 1) dp[i] += dp[i - 1];
      if (two >= 10 && two <= 26) dp[i] += dp[i - 2];
    }
    return dp[n];
  }
}
```

## Longest Increasing Subsequence (two ways)
- **O(n^2)**: `dp[i]` = length of the LIS **ending at** `i` = `1 + max(dp[j])` over earlier `j` with `nums[j] < nums[i]`. The answer is the max over all `i` (not just the last cell).
- **O(n log n)** (patience sorting): keep `tails[k]` = the **smallest possible tail** of an increasing subsequence of length `k + 1`. For each `x`, binary search the first `tail >= x` and replace it (or append if none). The array length is the answer. (`tails` is **not** the subsequence itself.)
```java Lis.java
class Solution {
  public int lengthOfLISQuadratic(int[] nums) {          // LeetCode 300, O(n^2)
    int[] dp = new int[nums.length];
    int best = 0;
    for (int i = 0; i < nums.length; i++) {
      dp[i] = 1;
      for (int j = 0; j < i; j++) if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
      best = Math.max(best, dp[i]);
    }
    return best;
  }
  public int lengthOfLIS(int[] nums) {                   // O(n log n)
    int[] tails = new int[nums.length];
    int size = 0;
    for (int x : nums) {
      int lo = 0, hi = size;
      while (lo < hi) {                                  // first position with tails[pos] >= x
        int mid = (lo + hi) >>> 1;
        if (tails[mid] < x) lo = mid + 1; else hi = mid;
      }
      tails[lo] = x;                                     // x is a smaller (or equal) tail for length lo + 1
      if (lo == size) size++;                            // x extends the longest subsequence so far
    }
    return size;
  }
}
```

## 0/1 Knapsack and Subset Sum (each item used once)
> **State**: `dp[s]` = is sum `s` reachable (or the best value with capacity `s`). For each item, update the array **from high to low** so the item cannot be used twice. (Low to high would be the **unbounded** knapsack of coin change.)
```java SubsetSum.java
class Solution {
  public boolean canPartition(int[] nums) {              // LeetCode 416: split into two equal-sum halves
    int sum = Arrays.stream(nums).sum();
    if (sum % 2 != 0) return false;
    int target = sum / 2;
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;                                        // the empty set sums to 0
    for (int x : nums)
      for (int s = target; s >= x; s--) dp[s] |= dp[s - x];   // DOWNWARD: each number at most once
    return dp[target];
  }
}
```
! 0/1 knapsack: inner loop goes **down**. Unbounded (coin change): inner loop goes **up**.

## State Machines: Buy and Sell Stock With Cooldown
> When there are modes ("holding", "just sold", "resting"), make one variable per **state** and write how each day's value comes from yesterday's states.
```java StockCooldown.java
class Solution {
  public int maxProfit(int[] prices) {                   // LeetCode 309: after selling you must rest one day
    int hold = -prices[0];                               // best profit ending the day holding a stock
    int sold = 0;                                        // ... having just sold today
    int rest = 0;                                        // ... not holding and free to buy
    for (int i = 1; i < prices.length; i++) {
      int prevSold = sold;
      sold = hold + prices[i];                           // sell what we held
      hold = Math.max(hold, rest - prices[i]);           // keep holding, or buy (only from the rest state)
      rest = Math.max(rest, prevSold);                   // keep resting, or finish the cooldown day
    }
    return Math.max(sold, rest);
  }
}
```

## How to Think About a New DP Problem
1. **Brute force first**: write the recursion that tries every choice (it is often a backtracking tree).
2. Find the **parameters that change** between calls (index, remaining amount, last choice). Those are the **state**.
3. Notice repeated states → add a **memo** keyed by the state (top-down DP).
4. Convert to a **table** (bottom-up) if you want speed and less stack, and shrink the space if you only look back a fixed amount.
- Number of states × work per state = time complexity. `n` states with `O(1)` work = O(n); coin change = `amount × coins`.

## Common Mistakes
- A vague state ("dp[i] is the answer so far") instead of an exact sentence.
- Wrong base case, or "infinity" values that overflow when you add 1 (use `Integer.MAX_VALUE / 2` or `amount + 1`).
- Mixing the loop order for combinations vs permutations; mixing the loop **direction** for 0/1 vs unbounded knapsack.
- Reading `dp[i - 1]` before it is computed (wrong iteration order).
- LIS: returning `dp[n - 1]` instead of the **maximum** of all cells.

## Explain It Like This
> "Let dp[a] be the fewest coins to make amount a. The last coin could be any coin c ≤ a, so dp[a] = 1 + min over coins of dp[a - c], with dp[0] = 0. I fill amounts from 1 up to the target. That is amount × coins time and O(amount) space."

## Interview Q&A
Q*: What is dynamic programming?
A: A technique for problems with overlapping subproblems and optimal substructure: solve each distinct subproblem once, store the result, and build bigger answers from smaller ones. It turns exponential recursion into polynomial time.
Q*: Memoization vs tabulation?
A: Memoization is top-down: write the recursion and cache results by state. Tabulation is bottom-up: fill a table from the smallest subproblems in dependency order. Both have the same complexity; tabulation avoids recursion depth and allows easy space optimisation.
Q*: How do you approach a DP problem?
A: Define the state in words, find the recurrence by asking what the last decision could be, set the base cases, choose an order that computes dependencies first, and identify where the answer lives. Then optimise space if the recurrence only looks back a fixed distance.
Q: Coin change: why does the order of loops matter for counting ways?
A: With coins on the outer loop each combination is added in a fixed coin order, so it is counted once. With amounts on the outer loop every coin can come at every position, so different orders of the same coins count separately, which counts permutations.
Q: Why does 0/1 knapsack iterate capacity downward?
A: Updating from high to low guarantees dp[s - x] still refers to the state before item x was considered, so each item is used at most once. Iterating upward would reuse the same item repeatedly, giving the unbounded knapsack.
Q: How does the O(n log n) LIS work?
A: It keeps tails[k], the smallest possible last element of an increasing subsequence of length k + 1. For each number, binary search the first tail that is at least the number and replace it, or append when the number is larger than all tails. The size of tails is the LIS length.

# 21 | Dynamic Programming II: 2D, Strings & Intervals | Grid DP (unique paths, min path sum, maximal square), two-string DP (LCS, edit distance, distinct subsequences, regex), palindromes, 0/1 knapsack and target sum, k transactions, interval DP (burst balloons), bitmask DP, how to optimise space | Dynamic Programming 2D

## The Idea
> When the state needs **two things** to describe it (a row and a column, a position in string A and a position in string B, an index and a remaining budget), the table has **two dimensions**: `dp[i][j]`.
- Same recipe as sheet 20: **state in words → last decision → recurrence → base cases → order → answer**.
- Time = number of cells × work per cell. Most 2D DPs are O(m × n).
- **Space trick**: if row `i` only needs row `i - 1` (or the same row to the left), keep **one row** (or two) instead of the whole table: O(m × n) → O(n).
! 2D DP = a table whose cell `[i][j]` answers a smaller version of the problem using the first `i` of one thing and the first `j` of another.

## Grid DP
```java GridDp.java
class Solution {
  public int uniquePaths(int m, int n) {                 // LeetCode 62: only move right or down
    int[] dp = new int[n];                               // one row: dp[c] = ways to reach (current row, c)
    Arrays.fill(dp, 1);                                  // the first row (and column) has exactly one way
    for (int r = 1; r < m; r++)
      for (int c = 1; c < n; c++) dp[c] += dp[c - 1];    // ways from above (old dp[c]) + ways from the left
    return dp[n - 1];
  }
  public int minPathSum(int[][] g) {                     // LeetCode 64
    int m = g.length, n = g[0].length;
    int[][] dp = new int[m][n];
    for (int r = 0; r < m; r++)
      for (int c = 0; c < n; c++) {
        if (r == 0 && c == 0) dp[r][c] = g[r][c];
        else if (r == 0) dp[r][c] = dp[r][c - 1] + g[r][c];
        else if (c == 0) dp[r][c] = dp[r - 1][c] + g[r][c];
        else dp[r][c] = Math.min(dp[r - 1][c], dp[r][c - 1]) + g[r][c];
      }
    return dp[m - 1][n - 1];
  }
  public int minimumTotal(List<List<Integer>> tri) {     // LeetCode 120: triangle, bottom-up in O(n) space
    int n = tri.size();
    int[] dp = new int[n + 1];
    for (int r = n - 1; r >= 0; r--)
      for (int c = 0; c <= r; c++) dp[c] = tri.get(r).get(c) + Math.min(dp[c], dp[c + 1]);
    return dp[0];
  }
  public int maximalSquare(char[][] m) {                 // LeetCode 221
    int rows = m.length, cols = m[0].length, best = 0;
    int[][] dp = new int[rows + 1][cols + 1];            // dp[r][c] = side of the biggest square with bottom-right corner (r-1, c-1)
    for (int r = 1; r <= rows; r++)
      for (int c = 1; c <= cols; c++)
        if (m[r - 1][c - 1] == '1') {
          dp[r][c] = 1 + Math.min(dp[r - 1][c - 1], Math.min(dp[r - 1][c], dp[r][c - 1]));
          best = Math.max(best, dp[r][c]);
        }
    return best * best;
  }
}
```
- **Maximal square**: a square of side `k` ending here needs squares of side `k - 1` ending at the left, above and diagonal. The smallest of the three limits it.

## Two Strings: Longest Common Subsequence
> **State**: `dp[i][j]` = LCS length of the first `i` chars of `a` and the first `j` chars of `b`. **Last decision**: compare `a[i-1]` and `b[j-1]`. Equal → they extend the LCS (`dp[i-1][j-1] + 1`). Different → drop one of them: `max(dp[i-1][j], dp[i][j-1])`.
```java Lcs.java
class Solution {
  public int longestCommonSubsequence(String a, String b) {   // LeetCode 1143
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];                  // row 0 and column 0 stay 0: empty string has LCS 0
    for (int i = 1; i <= m; i++)
      for (int j = 1; j <= n; j++)
        dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
            ? dp[i - 1][j - 1] + 1
            : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp[m][n];
  }
}
```
- To **recover** the actual subsequence, walk back from `dp[m][n]`: if the chars match, take it and go diagonal; otherwise move toward the larger neighbour.
- Many problems are LCS in disguise: **shortest common supersequence**, **minimum deletions to make two strings equal** (`m + n - 2·LCS`), **longest palindromic subsequence** (LCS of a string and its reverse).

## Edit Distance, Distinct Subsequences, Regex
```java EditDistance.java
class Solution {
  public int minDistance(String a, String b) {           // LeetCode 72: insert, delete, replace
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = i;           // turn a[0..i) into "" : i deletions
    for (int j = 0; j <= n; j++) dp[0][j] = j;           // turn "" into b[0..j) : j insertions
    for (int i = 1; i <= m; i++)
      for (int j = 1; j <= n; j++)
        dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
            ? dp[i - 1][j - 1]                           // characters match: free
            : 1 + Math.min(dp[i - 1][j - 1], Math.min(dp[i - 1][j], dp[i][j - 1]));   // replace, delete, insert
    return dp[m][n];
  }
  public int numDistinct(String s, String t) {           // LeetCode 115: how many subsequences of s equal t
    int m = s.length(), n = t.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = 1;           // "" is a subsequence of any prefix exactly once
    for (int i = 1; i <= m; i++)
      for (int j = 1; j <= n; j++) {
        dp[i][j] = dp[i - 1][j];                         // do not use s[i-1]
        if (s.charAt(i - 1) == t.charAt(j - 1)) dp[i][j] += dp[i - 1][j - 1];   // or use it to match t[j-1]
      }
    return dp[m][n];
  }
  public boolean isMatch(String s, String p) {           // LeetCode 10: '.' = any char, 'x*' = zero or more x
    int m = s.length(), n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 2; j <= n; j++) if (p.charAt(j - 1) == '*') dp[0][j] = dp[0][j - 2];   // "a*b*" can match the empty string
    for (int i = 1; i <= m; i++)
      for (int j = 1; j <= n; j++) {
        char pc = p.charAt(j - 1);
        if (pc == '*') {
          dp[i][j] = dp[i][j - 2];                       // zero copies of the preceding element
          char prev = p.charAt(j - 2);
          if (prev == '.' || prev == s.charAt(i - 1)) dp[i][j] |= dp[i - 1][j];   // one more copy of it
        } else {
          dp[i][j] = dp[i - 1][j - 1] && (pc == '.' || pc == s.charAt(i - 1));
        }
      }
    return dp[m][n];
  }
}
```
! Edit distance: **replace** looks diagonal, **delete** looks up, **insert** looks left.

## Palindromes
```java PalindromeDp.java
class Solution {
  public String longestPalindrome(String s) {            // LeetCode 5: expand around each centre, O(n^2), O(1) space
    int start = 0, end = 0;
    for (int i = 0; i < s.length(); i++) {
      int len = Math.max(expand(s, i, i), expand(s, i, i + 1));   // odd-length and even-length centres
      if (len > end - start + 1) { start = i - (len - 1) / 2; end = i + len / 2; }
    }
    return s.substring(start, end + 1);
  }
  private int expand(String s, int l, int r) {
    while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) { l--; r++; }
    return r - l - 1;
  }
  public int countSubstrings(String s) {                 // LeetCode 647: how many palindromic substrings
    int count = 0;
    for (int c = 0; c < 2 * s.length() - 1; c++) {       // 2n - 1 centres (letters and gaps between letters)
      int l = c / 2, r = l + c % 2;
      while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) { count++; l--; r++; }
    }
    return count;
  }
  public int longestPalindromeSubseq(String s) {         // LeetCode 516: subsequence, not substring
    int n = s.length();
    int[][] dp = new int[n][n];                          // dp[i][j] = answer for s[i..j]
    for (int i = n - 1; i >= 0; i--) {
      dp[i][i] = 1;
      for (int j = i + 1; j < n; j++)
        dp[i][j] = s.charAt(i) == s.charAt(j) ? dp[i + 1][j - 1] + 2 : Math.max(dp[i + 1][j], dp[i][j - 1]);
    }
    return dp[0][n - 1];
  }
}
```
- Longest palindromic **substring** (contiguous) vs **subsequence** (may skip). Expand-around-centre is O(n^2); **Manacher's algorithm** does it in O(n) (sheet 26).

## Knapsack Family
```java Knapsack.java
class Solution {
  // Classic 0/1 knapsack: best total value with capacity limit, each item at most once.
  static int knapsack(int[] weight, int[] value, int capacity) {
    int[] dp = new int[capacity + 1];                    // dp[w] = best value using capacity w
    for (int i = 0; i < weight.length; i++)
      for (int w = capacity; w >= weight[i]; w--)        // DOWNWARD: item i at most once
        dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);
    return dp[capacity];
  }
  public int findTargetSumWays(int[] nums, int target) { // LeetCode 494: put + or - before each number
    int sum = Arrays.stream(nums).sum();
    if (Math.abs(target) > sum || (sum + target) % 2 != 0) return 0;
    int s = (sum + target) / 2;                          // P - N = target and P + N = sum  =>  P = (sum + target) / 2
    int[] dp = new int[s + 1];                           // count subsets of nums that add up to s
    dp[0] = 1;
    for (int x : nums)
      for (int j = s; j >= x; j--) dp[j] += dp[j - x];
    return dp[s];
  }
  public int lastStoneWeightII(int[] stones) {           // LeetCode 1049: split into two groups, minimise the difference
    int sum = Arrays.stream(stones).sum(), half = sum / 2;
    boolean[] dp = new boolean[half + 1];
    dp[0] = true;
    for (int x : stones)
      for (int s = half; s >= x; s--) dp[s] |= dp[s - x];
    for (int s = half; s >= 0; s--) if (dp[s]) return sum - 2 * s;   // the largest reachable sum below half
    return sum;
  }
}
```
! Reduce the story to a known shape: "assign + or -" → subset sum; "split into two groups" → subset sum to `total / 2`.

## Stock With At Most K Transactions
```java StockK.java
class Solution {
  public int maxProfit(int k, int[] prices) {            // LeetCode 188 (k = 2 is LeetCode 123)
    if (prices.length == 0 || k == 0) return 0;
    int[] buy = new int[k + 1], sell = new int[k + 1];
    Arrays.fill(buy, Integer.MIN_VALUE / 2);             // buy[j]: best profit while holding a stock in transaction j
    for (int p : prices)
      for (int j = 1; j <= k; j++) {
        buy[j] = Math.max(buy[j], sell[j - 1] - p);      // start transaction j after finishing j - 1
        sell[j] = Math.max(sell[j], buy[j] + p);         // finish transaction j today
      }
    return sell[k];
  }
}
```

## Interval DP: Burst Balloons
> When the answer for a range `[l, r]` depends on **splitting the range**, make the state `dp[l][r]` and loop by increasing **length**. The trick in Burst Balloons: choose the **last** balloon `k` to burst in `(l, r)`, because then its neighbours are the fixed boundaries `a[l]` and `a[r]`, and the two sides are independent.
```java BurstBalloons.java
class Solution {
  public int maxCoins(int[] nums) {                      // LeetCode 312
    int n = nums.length;
    int[] a = new int[n + 2];
    a[0] = a[n + 1] = 1;                                 // virtual balloons of value 1 at both ends
    for (int i = 0; i < n; i++) a[i + 1] = nums[i];
    int[][] dp = new int[n + 2][n + 2];                  // dp[l][r] = best coins bursting everything strictly between l and r
    for (int len = 2; len <= n + 1; len++)
      for (int l = 0; l + len <= n + 1; l++) {
        int r = l + len;
        for (int k = l + 1; k < r; k++)                  // k = the LAST balloon burst in (l, r)
          dp[l][r] = Math.max(dp[l][r], dp[l][k] + a[l] * a[k] * a[r] + dp[k][r]);
      }
    return dp[0][n + 1];
  }
}
```
- Other interval DPs: **matrix chain multiplication**, **palindrome partitioning (min cuts)**, **strange printer**, **minimum cost to merge stones**. Order: short ranges first.

## Bitmask DP (n up to about 15-20)
> Use an **integer as a set**: bit `i` = "city `i` is visited". State `dp[mask][last]` = cheapest way to visit exactly the cities in `mask`, ending at `last`. There are `2^n × n` states and `n` transitions each: **O(2^n · n^2)**, far better than the `n!` brute force.
```java Tsp.java
class Tsp {
  static int tour(int[][] dist) {                        // shortest round trip visiting every city once, starting at city 0
    int n = dist.length;
    if (n == 1) return 0;
    int full = (1 << n) - 1, inf = Integer.MAX_VALUE / 2;
    int[][] dp = new int[1 << n][n];
    for (int[] row : dp) Arrays.fill(row, inf);
    dp[1][0] = 0;                                        // only city 0 visited, standing at city 0
    for (int mask = 1; mask <= full; mask++)
      for (int last = 0; last < n; last++) {
        if (dp[mask][last] == inf || (mask >> last & 1) == 0) continue;
        for (int next = 0; next < n; next++) {
          if ((mask >> next & 1) == 1) continue;         // already visited
          int nm = mask | 1 << next;
          dp[nm][next] = Math.min(dp[nm][next], dp[mask][last] + dist[last][next]);
        }
      }
    int best = inf;
    for (int last = 1; last < n; last++) best = Math.min(best, dp[full][last] + dist[last][0]);   // return home
    return best;
  }
}
```

## Space Optimisation Cheat Sheet
- `dp[i][j]` needs only row `i - 1` → keep **two rows**, or **one row** if you update in the right direction (left to right if it depends on the left, right to left for 0/1 knapsack).
- `dp[i][j]` needs `dp[i-1][j-1]` as well as the left cell → save the diagonal in a temp variable before overwriting.
- If you must **reconstruct** the answer (the actual string or path), keep the full table, or store the choice made at each cell.

## Common Mistakes
- Off-by-one between the table index and the string index (`dp[i]` is about the first `i` characters, so the character is `s.charAt(i - 1)`).
- Forgetting the base row and column (`dp[i][0]` and `dp[0][j]`).
- Iterating in the wrong order so a cell reads a value not yet computed.
- Substring vs subsequence (contiguous vs not).
- Memory limits: a `10^4 × 10^4` table of ints is 400 MB. Roll the rows.

## Explain It Like This
> "Let dp[i][j] be the edit distance between the first i characters of a and the first j characters of b. If the last characters match, it equals dp[i-1][j-1]. Otherwise it is 1 plus the best of replace (diagonal), delete (up) or insert (left). I fill the table row by row; it is O(m × n) time and space, reducible to O(n) space with two rows."

## Interview Q&A
Q*: What is the recurrence for LCS?
A: If a[i-1] equals b[j-1] then dp[i][j] = dp[i-1][j-1] + 1; otherwise dp[i][j] = max(dp[i-1][j], dp[i][j-1]). The first row and column are 0. It is O(m × n) time.
Q*: Explain edit distance.
A: dp[i][j] is the minimum operations to turn the first i characters of a into the first j of b. Base cases are i deletions or j insertions. If the last characters match it is dp[i-1][j-1]; otherwise one plus the minimum of replace (diagonal), delete (above) and insert (left).
Q*: How can you reduce 2D DP space?
A: If a row depends only on the previous row, keep two rows or even a single array updated in the correct direction, making it O(n) space. You lose the ability to reconstruct the path unless you store extra information.
Q: How do you turn Target Sum into a subset-sum problem?
A: Let P be the sum of numbers with plus signs and N the rest. P - N = target and P + N = total, so P = (total + target) / 2. Count subsets of the numbers that sum to P with a 0/1 knapsack.
Q: What is interval DP?
A: A DP whose state is a range [l, r] and whose transition tries every split or "last element" k inside it, combining dp[l][k] and dp[k][r]. Ranges are processed in order of increasing length. Burst Balloons and matrix chain multiplication are examples.
Q: When do you use bitmask DP?
A: When n is small (about 20 or fewer) and the state must remember which subset of items has been used or visited, such as the travelling salesman problem. A mask in an int encodes the subset, giving 2^n states.

## The Idea
> BFS finds the path with the fewest **edges**. When edges have **costs** (distance, price, time), you need algorithms that find the path with the smallest **total cost**.
- **Weighted graph**: each edge `(u, v, w)` has a weight. Store the adjacency list as `List<List<int[]>>` where each entry is `{neighbour, weight}`.
- Three questions, three families: **shortest path from one source** (Dijkstra, Bellman-Ford), **between all pairs** (Floyd-Warshall), **cheapest way to connect everything** (minimum spanning tree).
! Pick the algorithm by the edges: all weights equal → BFS. Non-negative weights → Dijkstra. Negative weights → Bellman-Ford. All pairs, small graph → Floyd-Warshall.

## Which Shortest-Path Algorithm?
```text
algorithm       works with              time              space   use when
BFS             unweighted              O(V + E)          O(V)    fewest edges, grids
0-1 BFS         weights 0 or 1          O(V + E)          O(V)    deque, 0-edges first
Dijkstra        weights >= 0            O((V + E) log V)  O(V)    one source (default)
Bellman-Ford    negative ok             O(V * E)          O(V)    neg. cycles, K edges
Floyd-Warshall  negative ok, all pairs  O(V^3)            O(V^2)  V up to ~400
```

## Dijkstra (greedy + a min-heap)
> Keep the best known distance to every node. Repeatedly take the **unfinished node with the smallest distance** (a min-heap does this), and **relax** its edges: if going through it gives a shorter route to a neighbour, update that neighbour. A node's distance is final the moment it is popped, **provided no edge is negative**.
```java Dijkstra.java
class Solution {
  // adj.get(u) holds {v, weight} pairs; weights must be >= 0. Returns the distance from src to every node.
  static int[] dijkstra(List<List<int[]>> adj, int src) {
    int[] dist = new int[adj.size()];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));   // {node, distance}
    pq.offer(new int[] {src, 0});
    while (!pq.isEmpty()) {
      int[] top = pq.poll();
      int u = top[0], d = top[1];
      if (d > dist[u]) continue;                         // stale entry: a shorter path to u was already processed
      for (int[] e : adj.get(u)) {
        int v = e[0], nd = d + e[1];
        if (nd < dist[v]) { dist[v] = nd; pq.offer(new int[] {v, nd}); }   // relax; no decrease-key, so push a new entry
      }
    }
    return dist;
  }

  public int networkDelayTime(int[][] times, int n, int k) {   // LeetCode 743: nodes are 1..n
    List<List<int[]>> adj = new ArrayList<>();
    for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());
    for (int[] t : times) adj.get(t[0]).add(new int[] {t[1], t[2]});
    int[] dist = dijkstra(adj, k);
    int max = 0;
    for (int i = 1; i <= n; i++) {
      if (dist[i] == Integer.MAX_VALUE) return -1;       // some node is unreachable
      max = Math.max(max, dist[i]);                      // the signal reaches everyone when the slowest node hears it
    }
    return max;
  }

  public int minimumEffortPath(int[][] h) {              // LeetCode 1631: cost of a path = its biggest single height step
    int rows = h.length, cols = h[0].length;
    int[][] effort = new int[rows][cols];
    for (int[] row : effort) Arrays.fill(row, Integer.MAX_VALUE);
    effort[0][0] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[2], b[2]));   // {r, c, effort}
    pq.offer(new int[] {0, 0, 0});
    int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
    while (!pq.isEmpty()) {
      int[] cur = pq.poll();
      int r = cur[0], c = cur[1];
      if (cur[2] > effort[r][c]) continue;
      if (r == rows - 1 && c == cols - 1) return cur[2];
      for (int[] d : dirs) {
        int nr = r + d[0], nc = c + d[1];
        if (nr < 0 || nc < 0 || nr >= rows || nc >= cols) continue;
        int e = Math.max(cur[2], Math.abs(h[nr][nc] - h[r][c]));   // "sum" is replaced by "max": Dijkstra still works
        if (e < effort[nr][nc]) { effort[nr][nc] = e; pq.offer(new int[] {nr, nc, e}); }
      }
    }
    return 0;
  }
}
```
- **Why negative edges break it**: Dijkstra assumes that once a node is popped nothing can reach it more cheaply. A negative edge later on could.
- **Complexity**: each edge can add one heap entry, so the heap holds up to E entries and each push or pop costs O(log E) = O(log V). Total **O((V + E) log V)**.
- Dijkstra works for any "path cost" that only **gets worse** along the path (sum, max, product of probabilities ≤ 1 with a max-heap, as in problem 1514).
! Dijkstra = BFS with a priority queue instead of a plain queue.

## Bellman-Ford (negative edges, at most K edges)
> A shortest path has at most `V - 1` edges. So **relax every edge, `V - 1` times**. If a V-th round still improves something, a **negative cycle** is reachable. Capping the rounds at `K + 1` finds the best path using at most `K` edges.
```java BellmanFord.java
class Solution {
  // edges are {u, v, w}. Returns distances, or null if a negative cycle is reachable from src.
  static int[] bellmanFord(int n, int[][] edges, int src) {
    final int INF = Integer.MAX_VALUE / 2;
    int[] dist = new int[n];
    Arrays.fill(dist, INF);
    dist[src] = 0;
    for (int round = 1; round < n; round++) {
      boolean changed = false;
      for (int[] e : edges)
        if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]]) { dist[e[1]] = dist[e[0]] + e[2]; changed = true; }
      if (!changed) break;                               // converged early
    }
    for (int[] e : edges)                                // one more pass: any improvement means a negative cycle
      if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]]) return null;
    return dist;
  }

  public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {   // LeetCode 787: at most k stops
    final int INF = Integer.MAX_VALUE / 2;
    int[] dist = new int[n];
    Arrays.fill(dist, INF);
    dist[src] = 0;
    for (int i = 0; i <= k; i++) {                       // k stops = k + 1 flights
      int[] next = dist.clone();                         // relax from the PREVIOUS round only, so a round adds exactly one edge
      for (int[] f : flights)
        if (dist[f[0]] != INF) next[f[1]] = Math.min(next[f[1]], dist[f[0]] + f[2]);
      dist = next;
    }
    return dist[dst] == INF ? -1 : dist[dst];
  }
}
```
- Using the same array in a round (instead of a copy) would let a path use more than one new edge per round and break the "at most K" limit.
- Typical uses: currency arbitrage (a negative cycle in `-log(rate)`), problems with **negative** costs, or an **edge-count limit**.

## Floyd-Warshall (all pairs)
> For every pair `(i, j)`: is going **through `k`** shorter than the best known route? Allow intermediate nodes `0..k` one `k` at a time. **`k` must be the outermost loop.**
```java FloydWarshall.java
class Solution {
  static int[][] floyd(int n, int[][] edges) {           // edges are {u, v, w}; INF = unreachable
    final int INF = 1_000_000_000;                       // INF + INF still fits in an int
    int[][] d = new int[n][n];
    for (int[] row : d) Arrays.fill(row, INF);
    for (int i = 0; i < n; i++) d[i][i] = 0;
    for (int[] e : edges) d[e[0]][e[1]] = Math.min(d[e[0]][e[1]], e[2]);
    for (int k = 0; k < n; k++)                          // intermediate node: OUTERMOST loop
      for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
          if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
    return d;
  }

  public int findTheCity(int n, int[][] edges, int threshold) {   // LeetCode 1334: city with the fewest cities within threshold
    int[][] edgesBothWays = new int[edges.length * 2][];
    for (int i = 0; i < edges.length; i++) {
      edgesBothWays[2 * i] = edges[i];
      edgesBothWays[2 * i + 1] = new int[] {edges[i][1], edges[i][0], edges[i][2]};
    }
    int[][] d = floyd(n, edgesBothWays);
    int best = -1, bestCount = Integer.MAX_VALUE;
    for (int i = 0; i < n; i++) {
      int count = 0;
      for (int j = 0; j < n; j++) if (i != j && d[i][j] <= threshold) count++;
      if (count <= bestCount) { bestCount = count; best = i; }     // ties: the larger index wins
    }
    return best;
  }
}
```
- O(V^3) time, O(V^2) space. Works with negative edges (a negative `d[i][i]` after the run reveals a negative cycle). Great when `V <= 400` and you need many pairs.

## Minimum Spanning Tree (MST)
> A **spanning tree** connects all `V` nodes with exactly `V - 1` edges and no cycle. The **minimum** spanning tree has the smallest total weight (cheapest cables, roads, pipes). Two greedy algorithms:
- **Kruskal**: sort all edges by weight; add an edge if it joins **two different components** (check with **union-find**, sheet 18); stop at `V - 1` edges. **O(E log E)**. Best for sparse graphs and edge lists.
- **Prim**: grow one tree from a start node; always add the **cheapest edge leaving the tree** (a min-heap, or an O(V^2) array scan for dense graphs). **O(E log V)**. Best for dense graphs.
- Why greedy is correct (**cut property**): the cheapest edge crossing any split of the nodes into two groups belongs to some MST.
```java Mst.java
class Solution {
  static class DSU {                                     // tiny union-find with path compression
    int[] p;
    DSU(int n) { p = new int[n]; for (int i = 0; i < n; i++) p[i] = i; }
    int find(int x) { return p[x] == x ? x : (p[x] = find(p[x])); }
    boolean union(int a, int b) { int ra = find(a), rb = find(b); if (ra == rb) return false; p[ra] = rb; return true; }
  }
  // Kruskal: edges are {u, v, w}. Returns the MST weight, or -1 if the graph is not connected.
  static long kruskal(int n, int[][] edges) {
    int[][] sorted = edges.clone();
    Arrays.sort(sorted, (a, b) -> Integer.compare(a[2], b[2]));
    DSU dsu = new DSU(n);
    long total = 0;
    int used = 0;
    for (int[] e : sorted) if (dsu.union(e[0], e[1])) { total += e[2]; used++; }   // joins two components: keep it
    return used == n - 1 ? total : -1;
  }
  // Prim with a heap: adj.get(u) holds {v, weight}.
  static long prim(int n, List<List<int[]>> adj) {
    boolean[] inTree = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));   // {node, cost to attach it}
    pq.offer(new int[] {0, 0});
    long total = 0;
    int count = 0;
    while (!pq.isEmpty() && count < n) {
      int[] top = pq.poll();
      if (inTree[top[0]]) continue;
      inTree[top[0]] = true;
      total += top[1];
      count++;
      for (int[] e : adj.get(top[0])) if (!inTree[e[0]]) pq.offer(new int[] {e[0], e[1]});
    }
    return count == n ? total : -1;
  }
  public int minCostConnectPoints(int[][] pts) {         // LeetCode 1584: complete graph, Manhattan distances, Prim in O(n^2)
    int n = pts.length, total = 0;
    int[] minDist = new int[n];
    Arrays.fill(minDist, Integer.MAX_VALUE);
    minDist[0] = 0;
    boolean[] inTree = new boolean[n];
    for (int step = 0; step < n; step++) {
      int u = -1;
      for (int v = 0; v < n; v++) if (!inTree[v] && (u == -1 || minDist[v] < minDist[u])) u = v;   // closest outside node
      inTree[u] = true;
      total += minDist[u];
      for (int v = 0; v < n; v++)
        if (!inTree[v]) minDist[v] = Math.min(minDist[v], Math.abs(pts[u][0] - pts[v][0]) + Math.abs(pts[u][1] - pts[v][1]));
    }
    return total;
  }
}
```
! MST connects everything cheaply (no cycle). Shortest path finds the cheapest route between two nodes. They are different questions.

## Bridges (Tarjan's low-link)
> A **bridge** is an edge whose removal disconnects the graph (a critical connection). In one DFS record each node's **discovery time** `disc` and `low` = the earliest discovery time reachable from its subtree using at most one back edge. A tree edge `u → v` is a bridge if **`low[v] > disc[u]`**: `v`'s subtree cannot reach `u` or anything above it except through this edge.
```java Bridges.java
class Solution {
  public List<List<Integer>> criticalConnections(int n, List<List<Integer>> connections) {   // LeetCode 1192
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (List<Integer> c : connections) { adj.get(c.get(0)).add(c.get(1)); adj.get(c.get(1)).add(c.get(0)); }
    int[] disc = new int[n], low = new int[n];           // 0 = not visited yet
    List<List<Integer>> bridges = new ArrayList<>();
    dfs(0, -1, adj, disc, low, new int[] {0}, bridges);
    return bridges;
  }
  private void dfs(int u, int parent, List<List<Integer>> adj, int[] disc, int[] low, int[] timer, List<List<Integer>> bridges) {
    disc[u] = low[u] = ++timer[0];
    for (int v : adj.get(u)) {
      if (v == parent) continue;                         // do not walk straight back over the tree edge
      if (disc[v] == 0) {
        dfs(v, u, adj, disc, low, timer, bridges);
        low[u] = Math.min(low[u], low[v]);
        if (low[v] > disc[u]) bridges.add(List.of(u, v));   // nothing in v's subtree climbs above u
      } else low[u] = Math.min(low[u], disc[v]);         // back edge to an ancestor
    }
  }
}
```
- The same low-link idea finds **articulation points** (nodes whose removal disconnects) and **strongly connected components** (Tarjan).

## Eulerian Path: Reconstruct Itinerary (Hierholzer)
> An **Eulerian path** uses **every edge exactly once**. Hierholzer's algorithm: DFS following unused edges, and add a node to the route only when it is **stuck (post-order)**; the route is built in reverse.
```java Itinerary.java
class Solution {
  public List<String> findItinerary(List<List<String>> tickets) {   // LeetCode 332: smallest lexical order, starts at JFK
    Map<String, PriorityQueue<String>> graph = new HashMap<>();
    for (List<String> t : tickets) graph.computeIfAbsent(t.get(0), k -> new PriorityQueue<>()).add(t.get(1));
    LinkedList<String> route = new LinkedList<>();
    visit("JFK", graph, route);
    return route;
  }
  private void visit(String airport, Map<String, PriorityQueue<String>> graph, LinkedList<String> route) {
    PriorityQueue<String> next = graph.get(airport);
    while (next != null && !next.isEmpty()) visit(next.poll(), graph, route);   // use each ticket once, smallest first
    route.addFirst(airport);                             // add on the way back: dead ends end up last
  }
}
```

## Strongly Connected Components (concept)
- In a **directed** graph, an **SCC** is a maximal group where every node can reach every other. Collapsing each SCC to one node gives a **DAG**.
- **Kosaraju**: DFS to get finishing order, reverse all edges, DFS in reverse finishing order; each DFS tree is one SCC. **Tarjan**: one DFS with the low-link trick. Both O(V + E).
- Uses: dependency cycles, 2-SAT, finding "mutually reachable" groups.

## Common Mistakes
- Using Dijkstra with **negative** weights. Use Bellman-Ford.
- `Integer.MAX_VALUE + weight` overflow when relaxing from an unreachable node. Use `MAX_VALUE / 2`, or skip nodes that are still infinite.
- Forgetting the stale-entry check (`if (d > dist[u]) continue`) in Dijkstra, which makes it much slower.
- Floyd-Warshall loops in the wrong order (`k` must be outermost).
- Treating MST as shortest path (or the reverse).
- Directed vs undirected edges when building the adjacency list.

## Explain It Like This
> "Edges have non-negative costs, so I use Dijkstra: a min-heap ordered by distance. I pop the closest unfinished node, relax its edges, and skip stale heap entries. Each edge is relaxed once, so it's O((V + E) log V)."

## Interview Q&A
Q*: How does Dijkstra's algorithm work and what is its complexity?
A: It repeatedly extracts the unfinished node with the smallest known distance from a min-heap, and relaxes its outgoing edges, updating neighbours whose distance improves. With a binary heap it runs in O((V + E) log V). It requires non-negative edge weights.
Q*: Why does Dijkstra fail with negative edges?
A: It assumes that once a node is popped its distance is final. A negative edge discovered later could provide a cheaper path to a node already finalised, so the greedy assumption breaks.
Q*: Dijkstra vs Bellman-Ford vs Floyd-Warshall?
A: Dijkstra: one source, non-negative weights, fastest. Bellman-Ford: one source, handles negative weights and detects negative cycles in O(V·E), and can limit the number of edges. Floyd-Warshall: all pairs in O(V^3), simple, good for small graphs.
Q: What is a minimum spanning tree and how do you find one?
A: A subset of edges connecting all nodes without cycles at minimum total weight. Kruskal sorts edges and adds those joining different components using union-find; Prim grows a tree from a start node taking the cheapest crossing edge with a heap.
Q: Kruskal vs Prim?
A: Kruskal is edge-based, O(E log E), and works well for sparse graphs. Prim is node-based, O(E log V) with a heap or O(V^2) with an array, and works well for dense graphs. Both produce the same total weight.
Q: How do you find bridges in a graph?
A: Run one DFS tracking discovery time and low-link values. A tree edge u to v is a bridge when low[v] is greater than disc[u], meaning v's subtree has no back edge to u or an ancestor. O(V + E).

# 23 | Trie (Prefix Tree) | What a trie is and why autocomplete uses it, insert/search/startsWith, array children vs hash map children, wildcard search, replace words, collecting words by prefix, Word Search II with pruning, the binary trie for maximum XOR | Trie

## The Idea
> A trie is a tree where **each edge is one character**, and a **path from the root spells a prefix**. Words that share a beginning share the same path, so `car`, `card` and `care` all walk `c → a → r` first. It is the data structure behind **autocomplete, spell check and IP routing**.
```text
words: "to", "tea", "ted", "ten", "in"          (* = a word ends here)

           (root)
           /    \
          t      i
         / \      \
        o*  e      n*
           /|\
          a* d* n*
```
- Each node has **children** (one per possible next character) and a flag **`end`** (a stored word finishes here).
- **Insert / search / startsWith** take **O(L)**, where L is the length of the word, **regardless of how many words are stored**. A hash set also gives O(L) lookup (hashing the string) but **cannot answer prefix questions** without scanning every word.
- Space: up to (total characters) nodes, each holding an array of 26 pointers (or a small map).
! Trie = the right tool whenever the question says **prefix**.

## Trie vs HashSet vs Sorted List
```text
need                       HashSet        sorted list + bin. search Trie
exact lookup               O(L) average   O(L log n)                O(L)
any word starting with p?  O(n * L) scan  O(L log n)                O(L)
list words with prefix p   O(n * L) scan  O(L log n + matches)      O(L + subtree)
wildcard "." search        scan all       scan all                  DFS with pruning
memory                     least          small                     most
```

## The Standard Trie
```java Trie.java
class Trie {                                             // LeetCode 208
  private static class Node {
    Node[] next = new Node[26];                          // children for 'a'..'z'
    boolean end;                                         // true if a word ends at this node
  }
  private final Node root = new Node();

  void insert(String word) {
    Node cur = root;
    for (char ch : word.toCharArray()) {
      int i = ch - 'a';
      if (cur.next[i] == null) cur.next[i] = new Node(); // create the path as needed
      cur = cur.next[i];
    }
    cur.end = true;                                      // mark the word's last node
  }
  boolean search(String word) {                          // exact word
    Node n = find(word);
    return n != null && n.end;
  }
  boolean startsWith(String prefix) {                    // any word with this prefix
    return find(prefix) != null;
  }
  private Node find(String s) {                          // walk the path; null if it breaks
    Node cur = root;
    for (char ch : s.toCharArray()) {
      cur = cur.next[ch - 'a'];
      if (cur == null) return null;
    }
    return cur;
  }

  // Autocomplete: every stored word that starts with the prefix, in alphabetical order.
  List<String> withPrefix(String prefix) {
    List<String> out = new ArrayList<>();
    Node start = find(prefix);
    if (start != null) collect(start, new StringBuilder(prefix), out);
    return out;
  }
  private void collect(Node n, StringBuilder path, List<String> out) {
    if (n.end) out.add(path.toString());
    for (int i = 0; i < 26; i++) {                       // children in order a..z give sorted output
      if (n.next[i] == null) continue;
      path.append((char) ('a' + i));
      collect(n.next[i], path, out);
      path.deleteCharAt(path.length() - 1);              // backtrack
    }
  }
}
```
- **`search` vs `startsWith`** differ only in the final check: `search` also needs `end == true`. "app" is a prefix of "apple" but is not a stored word unless it was inserted.
- Edge case: the **empty prefix** walks no edges and lands on the root, so `startsWith("")` returns `true` even for an empty trie. LeetCode guarantees a non-empty prefix; in your own code decide what the empty prefix should mean.
- **Children as `Node[26]`** is fastest for lowercase letters. For arbitrary characters use `Map<Character, Node>` (slower, but only pays for children that exist).

## Wildcard Search: Add and Search Words
> For a normal letter follow one child. For **`.`** try **every** child (DFS). The trie keeps this cheap because dead branches are pruned immediately.
```java WordDictionary.java
class WordDictionary {                                   // LeetCode 211
  private static class Node { Node[] next = new Node[26]; boolean end; }
  private final Node root = new Node();

  void addWord(String word) {
    Node cur = root;
    for (char ch : word.toCharArray()) {
      int i = ch - 'a';
      if (cur.next[i] == null) cur.next[i] = new Node();
      cur = cur.next[i];
    }
    cur.end = true;
  }
  boolean search(String word) { return dfs(word, 0, root); }
  private boolean dfs(String w, int i, Node node) {
    if (node == null) return false;
    if (i == w.length()) return node.end;
    char ch = w.charAt(i);
    if (ch != '.') return dfs(w, i + 1, node.next[ch - 'a']);
    for (Node child : node.next)                         // '.' matches any letter: try every branch
      if (child != null && dfs(w, i + 1, child)) return true;
    return false;
  }
}
```

## Replace Words (shortest root)
```java ReplaceWords.java
class Solution {
  private static class Node { Node[] next = new Node[26]; boolean end; }
  public String replaceWords(List<String> dictionary, String sentence) {   // LeetCode 648
    Node root = new Node();
    for (String d : dictionary) {
      Node cur = root;
      for (char ch : d.toCharArray()) {
        int i = ch - 'a';
        if (cur.next[i] == null) cur.next[i] = new Node();
        cur = cur.next[i];
      }
      cur.end = true;
    }
    StringBuilder sb = new StringBuilder();
    for (String w : sentence.split(" ")) {
      if (sb.length() > 0) sb.append(' ');
      Node cur = root;
      int len = 0;
      for (char ch : w.toCharArray()) {
        if (cur.end || cur.next[ch - 'a'] == null) break;   // found a root, or no root fits this word
        cur = cur.next[ch - 'a'];
        len++;
      }
      sb.append(cur.end ? w.substring(0, len) : w);         // the shortest root wins because we stop at the first end
    }
    return sb.toString();
  }
}
```

## Word Search II: Trie + Backtracking (the classic Hard)
> Searching the board once **per word** repeats work. Instead build a trie of all the words and DFS the board **once**, walking the trie in step. A path that is **not a prefix of any word** is cut off immediately, and a node that holds a complete word is reported (then cleared, so it is found once).
```java WordSearchII.java
class Solution {
  private static class Node { Node[] next = new Node[26]; String word; }   // 'word' is set on the node where a word ends

  public List<String> findWords(char[][] board, String[] words) {          // LeetCode 212
    Node root = new Node();
    for (String w : words) {
      Node cur = root;
      for (char ch : w.toCharArray()) {
        int i = ch - 'a';
        if (cur.next[i] == null) cur.next[i] = new Node();
        cur = cur.next[i];
      }
      cur.word = w;
    }
    List<String> out = new ArrayList<>();
    for (int r = 0; r < board.length; r++)
      for (int c = 0; c < board[0].length; c++) dfs(board, r, c, root, out);
    return out;
  }
  private void dfs(char[][] b, int r, int c, Node node, List<String> out) {
    if (r < 0 || c < 0 || r >= b.length || c >= b[0].length) return;
    char ch = b[r][c];
    if (ch == '#' || node.next[ch - 'a'] == null) return;  // visited cell, or no word continues this way
    node = node.next[ch - 'a'];
    if (node.word != null) { out.add(node.word); node.word = null; }   // found: report once
    b[r][c] = '#';                                          // mark visited
    dfs(b, r + 1, c, node, out);
    dfs(b, r - 1, c, node, out);
    dfs(b, r, c + 1, node, out);
    dfs(b, r, c - 1, node, out);
    b[r][c] = ch;                                           // undo
  }
}
```

## The Binary Trie: Maximum XOR of Two Numbers
> Write each number in **binary** (31 bits) and insert it into a trie whose edges are the bits `0` and `1`. To maximise `x XOR y`, you want `y` to differ from `x` in the **highest bits first**. Walk down the trie, and at each level prefer the child with the **opposite bit** if it exists.
```java MaxXor.java
class Solution {
  public int findMaximumXOR(int[] nums) {                // LeetCode 421: values are non-negative (31 bits)
    int[][] trie = new int[nums.length * 31 + 2][2];     // trie[node][bit] = child index; 0 means "none" (node 0 is the root)
    int nodes = 1, best = 0;
    for (int x : nums) {                                 // insert every number
      int cur = 0;
      for (int b = 30; b >= 0; b--) {
        int bit = (x >> b) & 1;
        if (trie[cur][bit] == 0) trie[cur][bit] = nodes++;
        cur = trie[cur][bit];
      }
    }
    for (int x : nums) {                                 // best partner for each number
      int cur = 0, xor = 0;
      for (int b = 30; b >= 0; b--) {
        int want = 1 - ((x >> b) & 1);                   // the opposite bit makes this XOR bit a 1
        if (trie[cur][want] != 0) { xor |= 1 << b; cur = trie[cur][want]; }
        else cur = trie[cur][1 - want];                  // no opposite available: forced to take the same bit
      }
      best = Math.max(best, xor);
    }
    return best;
  }
}
```

## When a Trie Is (and Is Not) the Answer
- **Use** for: autocomplete / suggestions, spell check, "longest common prefix of many words", dictionary with wildcards, "words that start with ...", many-words-in-a-grid searches, XOR maximisation (binary trie), IP longest-prefix routing.
- **Not needed** for plain "have I seen this word?" (a HashSet is simpler and lighter) or one-off prefix checks on few words.
- **Variants** worth naming: **compressed trie / radix tree** (merge chains of single-child nodes to save memory), **suffix trie / suffix tree / suffix array** (all suffixes, for substring queries), **Aho-Corasick** (a trie plus failure links to match many patterns in one pass).

## Common Mistakes
- Forgetting the `end` flag, so `search("app")` wrongly succeeds after inserting only `"apple"`.
- Mixing up `search` (needs `end`) and `startsWith` (does not).
- `ch - 'a'` on uppercase or non-letters throws `ArrayIndexOutOfBoundsException`. Use a map for other alphabets.
- In Word Search II: not marking cells visited, or not clearing found words (duplicates in the result).
- Memory: `Node[26]` per node is heavy for very large dictionaries.

## Explain It Like This
> "I'll store the words in a trie: each node is a letter and each root-to-node path is a prefix. Checking whether any word starts with a prefix just walks that path, so it's O(length of the prefix), no matter how many words are stored. A hash set can't answer prefix queries without scanning all words."

## Interview Q&A
Q*: What is a trie and what are its operations' complexities?
A: A prefix tree in which each edge is a character and each node can mark the end of a word. Insert, search and prefix check all take O(L) for a word of length L, independent of the number of stored words.
Q*: Trie vs hash set for storing words?
A: A hash set gives O(L) exact lookup with less memory but cannot answer prefix queries efficiently. A trie answers prefix queries, autocomplete and wildcard searches directly, at the cost of more memory.
Q*: How do you implement wildcard search?
A: Walk the trie letter by letter. For a normal letter follow the matching child; for a wildcard recurse into every existing child. Dead branches end immediately.
Q: Why use a trie for Word Search II?
A: It lets one DFS over the board check all words at once and prune any path that is not a prefix of some word, instead of running a separate search per word.
Q: How does a binary trie find the maximum XOR pair?
A: Insert each number's bits from most significant to least. For each number, walk down preferring the opposite bit at each level to produce a 1 in the XOR; the larger bits matter most, so this greedy choice is optimal. O(31·n).
Q: How can you reduce a trie's memory?
A: Use a map or sorted array for children instead of a full array per node, compress single-child chains into one edge (a radix tree), or store the words in a sorted array and binary search when memory matters more than speed.

# 24 | Bit Manipulation & Math | Binary and two's complement, the bitwise operators, the handful of tricks that solve most bit questions (clear lowest bit, isolate lowest bit, XOR cancellation), single number, counting bits, bitmasks for subsets, GCD, sieve of Eratosthenes, modular arithmetic, fast power with mod, nCr | Bits & Math

## The Idea
> Computers store integers as **bits** (0 and 1). Bit tricks do a job in one CPU instruction that a loop would do in many, and a few classic problems are **only** elegant with bits (find the one number that appears once, use an integer as a set).
- **Binary place values** (right to left): 1, 2, 4, 8, 16 ... `13 = 8 + 4 + 1 = 1101`.
- Java `int` is **32 bits**, `long` is **64 bits**, in **two's complement**: the top bit is the sign bit. To negate: **flip all bits and add 1** (`-x = ~x + 1`). So `Integer.MIN_VALUE = -2^31` has no positive counterpart.
- Max values: `Integer.MAX_VALUE = 2^31 - 1 = 2,147,483,647`. `Long.MAX_VALUE = 2^63 - 1`.
! Think of an int as a row of 32 on/off switches.

## The Operators
```text
operator  name                  example (4-bit)       meaning
&         AND                   1100 & 1010 = 1000    1 only where both are 1
|         OR                    1100 | 1010 = 1110    1 where either is 1
^         XOR                   1100 ^ 1010 = 0110    1 where they differ
~         NOT                   ~1100 = 0011          flip every bit (-x - 1)
<<        left shift            0011 << 2 = 1100      multiply by 2^k
>>        arithmetic right      keeps the sign bit    divide by 2^k, rounds down
>>>       logical right (Java)  fills with 0          treats the int as unsigned
```
```java BitBasics.java
int x = 0b1101;                                          // 13
System.out.println(Integer.toBinaryString(x));           // 1101
System.out.println((x >> 1) + " " + (x << 1));           // 6 26
System.out.println((x & 1) == 1 ? "odd" : "even");       // test the lowest bit
System.out.println((x >> 2 & 1));                        // 1: read bit number 2 (counting from 0)
System.out.println(x | 1 << 1);                          // 15: set bit 1
System.out.println(x & ~(1 << 2));                       // 9: clear bit 2
System.out.println(x ^ 1 << 3);                          // 5: toggle bit 3
System.out.println(-8 >> 1);                             // -4: arithmetic shift keeps the sign
System.out.println(-8 >>> 28);                           // 15: logical shift fills with zeros
System.out.println(Integer.bitCount(255) + " " + Long.numberOfTrailingZeros(8L));   // 8 3
System.out.println(1 << 31);                             // -2147483648: shifting into the sign bit
```
- **Precedence trap**: `&`, `|`, `^` bind **weaker than `==`**. Write `(x & 1) == 1`, not `x & 1 == 1`.
- `1 << n` is an `int`. For `n >= 31` use `1L << n`.

## The Five Tricks to Memorise
```text
x & (x - 1)     clears the LOWEST set bit (count bits, power-of-two test)
x & -x          isolates the LOWEST set bit (Fenwick tree, single number III)
a ^ a = 0       a number cancels itself; a ^ 0 = a (find the odd one out)
x ^ y           1 where the bits differ (swap, add without +)
(mask >> i) & 1 tests bit i (bitmask subsets)
```
! XOR is the "cancel pairs" operator: it is commutative and associative, `a ^ a = 0`, `a ^ 0 = a`.

## Single Number, Counting Bits, Missing Number
```java BitTricks.java
class Solution {
  public int singleNumber(int[] nums) {                  // LeetCode 136: everything appears twice except one
    int x = 0;
    for (int n : nums) x ^= n;                           // pairs cancel, the single number remains
    return x;
  }
  public int singleNumberII(int[] nums) {                // LeetCode 137: everything appears three times except one
    int ones = 0, twos = 0;                              // per bit: count of 1s seen, modulo 3, stored in two variables
    for (int x : nums) {
      ones = (ones ^ x) & ~twos;
      twos = (twos ^ x) & ~ones;
    }
    return ones;
  }
  public int[] singleNumberIII(int[] nums) {             // LeetCode 260: two numbers appear once, the rest twice
    int xor = 0;
    for (int n : nums) xor ^= n;                         // = a ^ b, and a != b so xor != 0
    int low = xor & -xor;                                // a bit where a and b differ
    int a = 0;
    for (int n : nums) if ((n & low) != 0) a ^= n;       // group by that bit: each group cancels down to one answer
    return new int[] {a, xor ^ a};
  }
  public int hammingWeight(int n) {                      // LeetCode 191: number of 1 bits
    int count = 0;
    while (n != 0) { n &= n - 1; count++; }              // each step removes the lowest set bit
    return count;
  }
  public int[] countBits(int n) {                        // LeetCode 338: bit counts for 0..n
    int[] r = new int[n + 1];
    for (int i = 1; i <= n; i++) r[i] = r[i >> 1] + (i & 1);   // i has the bits of i/2 plus its last bit
    return r;
  }
  public int missingNumber(int[] nums) {                 // LeetCode 268: 0..n with one missing
    int x = nums.length;
    for (int i = 0; i < nums.length; i++) x ^= i ^ nums[i];    // every present number cancels with its index
    return x;
  }
  public boolean isPowerOfTwo(int n) {                   // LeetCode 231: exactly one bit set
    return n > 0 && (n & (n - 1)) == 0;
  }
  public int reverseBits(int n) {                        // LeetCode 190
    int r = 0;
    for (int i = 0; i < 32; i++) { r = (r << 1) | (n & 1); n >>>= 1; }   // >>>: treat n as unsigned
    return r;
  }
  public int getSum(int a, int b) {                      // LeetCode 371: add without the + operator
    while (b != 0) {
      int carry = (a & b) << 1;                          // positions where both are 1 produce a carry
      a ^= b;                                            // add without carrying
      b = carry;                                         // then add the carries, repeat until none remain
    }
    return a;
  }
  public int rangeBitwiseAnd(int left, int right) {      // LeetCode 201: AND of every number in [left, right]
    int shift = 0;
    while (left != right) { left >>= 1; right >>= 1; shift++; }   // only the common prefix of the two survives
    return left << shift;
  }
}
```

## Bitmasks: an Integer as a Set
> With `n <= 20`, bit `i` of `mask` means "element `i` is chosen". `mask` runs from `0` to `2^n - 1` and visits **every subset**.
```java Bitmask.java
class Solution {
  static List<List<Integer>> subsets(int[] nums) {       // all 2^n subsets without recursion
    int n = nums.length;
    List<List<Integer>> out = new ArrayList<>();
    for (int mask = 0; mask < (1 << n); mask++) {
      List<Integer> s = new ArrayList<>();
      for (int i = 0; i < n; i++) if ((mask >> i & 1) == 1) s.add(nums[i]);
      out.add(s);
    }
    return out;
  }
  static void submasks(int mask) {                       // iterate every non-empty subset of a given mask
    for (int sub = mask; sub > 0; sub = (sub - 1) & mask) System.out.print(sub + " ");
    System.out.println();
  }
}
```
- Bitmasks also give **set operations in one instruction**: union `a | b`, intersection `a & b`, difference `a & ~b`, membership `a >> i & 1`, add `a | 1 << i`, remove `a & ~(1 << i)`. They are the state in **bitmask DP** (sheet 21).

## GCD, LCM, Primes
> **Euclid's algorithm**: `gcd(a, b) = gcd(b, a % b)`, ending when `b == 0`. It takes O(log min(a, b)) steps. **lcm(a, b) = a / gcd(a, b) * b** (divide first to avoid overflow).
> **Sieve of Eratosthenes**: to list primes below `n`, for each prime `p` mark `p*p, p*p + p, ...` as composite. **O(n log log n)**.
```java MathBasics.java
class Solution {
  static int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }
  static long lcm(int a, int b) { return (long) a / gcd(a, b) * b; }

  public int countPrimes(int n) {                        // LeetCode 204: primes strictly below n
    if (n < 3) return 0;
    boolean[] composite = new boolean[n];
    int count = 0;
    for (int i = 2; i < n; i++) {
      if (composite[i]) continue;
      count++;                                           // i is prime
      for (long j = (long) i * i; j < n; j += i) composite[(int) j] = true;   // smaller multiples were marked by smaller primes
    }
    return count;
  }
  static boolean isPrime(int n) {                        // trial division up to sqrt(n): O(sqrt n)
    if (n < 2) return false;
    for (int d = 2; (long) d * d <= n; d++) if (n % d == 0) return false;
    return true;
  }
  public boolean isHappy(int n) {                        // LeetCode 202: repeat "sum of squares of digits"; does it reach 1?
    int slow = n, fast = next(n);
    while (fast != 1 && slow != fast) { slow = next(slow); fast = next(next(fast)); }   // Floyd cycle detection
    return fast == 1;
  }
  private int next(int n) { int s = 0; while (n > 0) { int d = n % 10; s += d * d; n /= 10; } return s; }
}
```

## Modular Arithmetic
- "Return the answer **modulo 10^9 + 7**" means the true answer is too big for a `long`. Take `% MOD` after **every** addition and multiplication so numbers stay small. 10^9 + 7 is a **prime** (needed for division).
- `(a + b) % m = ((a % m) + (b % m)) % m`, same for `*`. For subtraction add `m` first: `((a - b) % m + m) % m`.
- **Division** does not work with `/`. Use the **modular inverse**: for prime `p`, `a^(-1) ≡ a^(p-2) (mod p)` (**Fermat's little theorem**).
- **Fast exponentiation** (square and multiply): `a^b` in **O(log b)** by halving the exponent, with `% MOD` at each step.
```java ModMath.java
class ModMath {
  static final long MOD = 1_000_000_007L;

  static long modPow(long base, long exp, long mod) {
    long result = 1;
    base %= mod;
    while (exp > 0) {
      if ((exp & 1) == 1) result = result * base % mod;  // this bit of the exponent is set: multiply it in
      base = base * base % mod;                          // base^1, base^2, base^4, base^8 ...
      exp >>= 1;
    }
    return result;
  }
  static long modInverse(long a, long p) { return modPow(a, p - 2, p); }   // p must be prime

  static long nCr(int n, int r, long mod) {              // n choose r modulo a prime
    if (r < 0 || r > n) return 0;
    long num = 1, den = 1;
    for (int i = 1; i <= r; i++) {
      num = num * (n - r + i) % mod;                     // n * (n-1) * ... * (n-r+1)
      den = den * i % mod;                               // r!
    }
    return num * modInverse(den, mod) % mod;             // divide by r! using the inverse
  }
}
```
! Overflow rule: `(a * b) % MOD` is safe in `long` only if both are already below MOD (about 10^9, product under 10^18).

## Integer and String Arithmetic (carry loops)
```java Arithmetic.java
class Solution {
  public int reverse(int x) {                            // LeetCode 7: return 0 if the reversed value overflows an int
    int r = 0;
    while (x != 0) {
      int d = x % 10;
      x /= 10;
      if (r > Integer.MAX_VALUE / 10 || (r == Integer.MAX_VALUE / 10 && d > 7)) return 0;    // would exceed 2147483647
      if (r < Integer.MIN_VALUE / 10 || (r == Integer.MIN_VALUE / 10 && d < -8)) return 0;   // would go below -2147483648
      r = r * 10 + d;
    }
    return r;
  }
  public String addBinary(String a, String b) {          // LeetCode 67
    StringBuilder sb = new StringBuilder();
    int i = a.length() - 1, j = b.length() - 1, carry = 0;
    while (i >= 0 || j >= 0 || carry != 0) {
      int sum = carry + (i >= 0 ? a.charAt(i--) - '0' : 0) + (j >= 0 ? b.charAt(j--) - '0' : 0);
      sb.append(sum & 1);                                // the digit
      carry = sum >> 1;                                  // the carry
    }
    return sb.reverse().toString();
  }
  public String multiply(String a, String b) {           // LeetCode 43: multiply two big numbers given as strings
    if (a.equals("0") || b.equals("0")) return "0";
    int[] prod = new int[a.length() + b.length()];
    for (int i = a.length() - 1; i >= 0; i--)
      for (int j = b.length() - 1; j >= 0; j--) {
        int p = (a.charAt(i) - '0') * (b.charAt(j) - '0') + prod[i + j + 1];
        prod[i + j + 1] = p % 10;
        prod[i + j] += p / 10;
      }
    StringBuilder sb = new StringBuilder();
    for (int d : prod) if (!(sb.length() == 0 && d == 0)) sb.append(d);   // skip leading zeros
    return sb.toString();
  }
}
```

## Common Mistakes
- `x & 1 == 1` (precedence bug). Parenthesise: `(x & 1) == 1`.
- `1 << 32` or `1 << 40` on an `int` (wraps around). Use `1L << n`.
- Right-shifting negative numbers with `>>` when you wanted an unsigned shift (`>>>`).
- Overflow in `a * b`, `a + b`, `Math.abs(Integer.MIN_VALUE)` (still negative). Cast to `long` **before** the operation.
- Forgetting `% MOD` after a subtraction (negative results).
- Using `/` for modular division instead of an inverse.

## Explain It Like This
> "Every number appears twice except one. XOR is commutative and a ^ a = 0, so XOR-ing the whole array cancels all the pairs and leaves the single number. One pass, O(n) time, O(1) space."

## Interview Q&A
Q*: How do you check if a number is a power of two?
A: A positive power of two has exactly one bit set, so n > 0 && (n & (n - 1)) == 0. Subtracting 1 flips the lowest set bit and everything below it, so the AND is zero only when there was a single set bit.
Q*: How do you find the single number when every other number appears twice?
A: XOR all the numbers. XOR is commutative and associative, a ^ a = 0 and a ^ 0 = a, so pairs cancel and the unique number remains. O(n) time, O(1) space.
Q*: What does n & (n - 1) do?
A: It clears the lowest set bit of n. Repeating it until n is zero counts the set bits (Brian Kernighan's algorithm), with one iteration per set bit.
Q: Difference between >> and >>> in Java?
A: >> is an arithmetic shift that copies the sign bit, so negative numbers stay negative. >>> is a logical shift that fills with zeros, treating the value as unsigned.
Q: Why take results modulo 10^9 + 7?
A: Counts can be astronomically large, so problems ask for the answer modulo a large prime that fits in a long even after multiplying two residues. Apply the modulus after each operation to avoid overflow; 10^9 + 7 being prime allows division through modular inverses.
Q: How does the sieve of Eratosthenes work?
A: For each number from 2 upward that is still unmarked (so prime), mark all its multiples starting from its square as composite. It lists all primes below n in O(n log log n) time and O(n) space.

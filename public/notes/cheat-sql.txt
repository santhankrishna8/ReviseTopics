## SQL Sub-Languages
- **DDL**: `CREATE`, `ALTER`, `DROP`, `TRUNCATE` (structure).
- **DML**: `INSERT`, `UPDATE`, `DELETE`, `MERGE` (rows).
- **DQL**: `SELECT`. **DCL**: `GRANT`, `REVOKE`. **TCL**: `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`.
- Strings in `'single quotes'`; identifiers in `"double"` (standard), `` `backticks` `` (MySQL), `[brackets]` (SQL Server). Results on this page: PostgreSQL on the sample data (card 3).

## Execution Order
```text
written : SELECT DISTINCT cols FROM JOIN WHERE
          GROUP BY HAVING ORDER BY LIMIT
runs as : 1 FROM + JOIN   2 WHERE   3 GROUP BY
          4 HAVING   5 SELECT (aliases, windows)
          6 DISTINCT   7 ORDER BY   8 LIMIT
```
- So: no SELECT aliases in `WHERE`, no aggregates in `WHERE` (use `HAVING`), no window functions in `WHERE` (wrap in a CTE).

## CREATE TABLE & Constraints
```sql
CREATE TABLE products (
  product_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sku VARCHAR(20) NOT NULL UNIQUE,
  price NUMERIC(10, 2) NOT NULL CHECK (price >= 0),
  discount NUMERIC(4, 2) DEFAULT 0,
  dept_id INT REFERENCES departments (dept_id)
    ON DELETE SET NULL ON UPDATE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE order_items (
  order_id INT REFERENCES orders (order_id) ON DELETE CASCADE,
  product_id INT REFERENCES products (product_id),
  qty INT NOT NULL CHECK (qty > 0),
  PRIMARY KEY (order_id, product_id)  -- composite
);
```
- FK actions: `CASCADE`, `SET NULL`, `SET DEFAULT`, `RESTRICT`, `NO ACTION` (default).

## ALTER · DROP · TRUNCATE
```sql
ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
ALTER TABLE customers ALTER COLUMN phone TYPE VARCHAR(30);
ALTER TABLE customers RENAME COLUMN phone TO mobile;
ALTER TABLE customers ADD CONSTRAINT uq_mobile UNIQUE (mobile);
ALTER TABLE customers DROP CONSTRAINT uq_mobile;

TRUNCATE TABLE old_orders;
DROP TABLE IF EXISTS old_orders;
```
- MySQL: `MODIFY COLUMN`. SQL Server: `ALTER COLUMN phone VARCHAR(30)`, `sp_rename`.

## DELETE vs TRUNCATE vs DROP
```text
           DELETE         TRUNCATE        DROP
removes    chosen rows    all rows        whole table
WHERE      yes            no              no
triggers   yes            no              no
rollback   yes            PG/SQL Server   (DDL)
identity   kept           reset           gone
```

## Keys
- **Primary key**: unique + NOT NULL, one per table. **Candidate key**: any minimal unique column set. **Unique key**: allows NULLs.
- **Foreign key**: references another table's key (referential integrity). **Composite key**: several columns.
- **Natural** key (email) vs **surrogate** key (identity, UUID).

## UPDATE & DELETE
```sql
UPDATE employees SET salary = salary * 1.10 WHERE dept_id = 2;
UPDATE orders o SET status = 'priority'
FROM customers c
WHERE o.customer_id = c.customer_id AND c.city = 'Mumbai';  -- with a join
DELETE FROM customers c WHERE NOT EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
) RETURNING name;  -- Divya
DELETE FROM orders WHERE status = 'cancelled';
```
- MySQL: `UPDATE orders o JOIN customers c ON ... SET ...`. Always run the `WHERE` as a `SELECT` first.

## Upsert & MERGE
```sql
INSERT INTO customers (customer_id, name, city) VALUES (1, 'Anil K', 'Goa')
ON CONFLICT (customer_id) DO UPDATE SET name = EXCLUDED.name, city = EXCLUDED.city;
INSERT INTO customers (customer_id, name) VALUES (2, 'x') ON CONFLICT DO NOTHING;
MERGE INTO customers t
USING (VALUES (3, 'Chetan R'), (9, 'Ira')) AS s (id, name)
ON t.customer_id = s.id
WHEN MATCHED THEN UPDATE SET name = s.name
WHEN NOT MATCHED THEN INSERT (customer_id, name) VALUES (s.id, s.name);
```
- MySQL: `ON DUPLICATE KEY UPDATE`. SQL Server / Oracle: `MERGE`.

## SELECT Basics
```sql
SELECT name, salary * 12 AS annual FROM employees;
SELECT DISTINCT dept_id FROM employees;  -- 1, 2, 3, NULL
SELECT COUNT(DISTINCT dept_id) FROM employees;  -- 3
SELECT DISTINCT ON (dept_id) dept_id, name, salary
FROM employees ORDER BY dept_id, salary DESC;  -- top earner per dept (PG)
```

## WHERE Operators
```sql
SELECT name FROM employees WHERE dept_id IN (2, 3);  -- John, Priya, Karan, Neha
SELECT name FROM employees WHERE salary BETWEEN 90000 AND 115000; -- John, Priya, Karan (inclusive)
SELECT name FROM employees WHERE name LIKE 'A%';  -- Asha, Arjun
SELECT name FROM employees WHERE name LIKE '_e%';  -- Meena, Neha
SELECT name FROM employees WHERE name ILIKE 'a%';  -- case-insensitive (PG)
SELECT name FROM employees WHERE dept_id = 1 OR dept_id = 2 AND salary > 125000;  -- Asha, Ravi, Meena
SELECT name FROM employees WHERE (dept_id = 1 OR dept_id = 2) AND salary > 125000; -- Asha
```
- `AND` binds tighter than `OR`: use parentheses. `%` = any run, `_` = one character.

## NULL Logic
```sql
SELECT name FROM employees WHERE email IS NULL;  -- Arjun (= NULL never matches)
SELECT name FROM employees WHERE dept_id <> 1;  -- John, Priya, Karan, Neha (not Arjun!)
SELECT name FROM employees WHERE dept_id IS DISTINCT FROM 1;  -- + Arjun
```
- Comparisons with NULL are UNKNOWN; WHERE keeps only TRUE. `NOT IN (subquery with a NULL)` returns **nothing**: use `NOT EXISTS`.

## CASE · COALESCE · NULLIF
```sql
SELECT name,
  CASE WHEN salary >= 120000 THEN 'senior'
       WHEN salary >= 90000 THEN 'mid'
       ELSE 'junior' END AS band,
  COALESCE(email, 'no email') AS contact,  -- first non-NULL
  NULLIF(dept_id, 3) AS not_hr  -- NULL when equal
FROM employees;
-- x / NULLIF(y, 0) avoids division by zero
```
- `COALESCE` = MySQL `IFNULL`, SQL Server `ISNULL`, Oracle `NVL`.

## ORDER BY & Pagination
```sql
SELECT name, salary FROM employees ORDER BY salary DESC LIMIT 3;  -- Asha, Ravi, Meena
SELECT name FROM employees ORDER BY emp_id LIMIT 3 OFFSET 3;  -- John, Priya, Karan
SELECT name FROM employees ORDER BY emp_id OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY;
SELECT name FROM employees ORDER BY dept_id NULLS FIRST;
SELECT emp_id, name FROM employees WHERE emp_id > 6 ORDER BY emp_id LIMIT 3;  -- keyset paging
```
- SQL Server: `SELECT TOP 3`. Oracle 12c+: `FETCH FIRST 3 ROWS ONLY`. No `ORDER BY` = no guaranteed order.

## String Functions
```sql
SELECT UPPER('sql'), LOWER('SQL'), LENGTH('hello'),  -- SQL, sql, 5
  'Data' || 'base', CONCAT('a', NULL, 'b'),  -- Database, ab
  SUBSTRING('database' FROM 1 FOR 4),  -- data
  LEFT('database', 4), RIGHT('database', 4),  -- data, base
  POSITION('b' IN 'database'),  -- 5
  TRIM('  hi  '), REPLACE('a-b', '-', '+'),  -- hi, a+b
  LPAD('7', 3, '0'), SPLIT_PART('a,b,c', ',', 2);  -- 007, b
```
- `||` with NULL gives NULL; `CONCAT` skips NULL. SQL Server: `LEN`, `CHARINDEX`, `+` to concatenate.

## Date Functions

SELECT CURRENT_DATE, NOW(),

## Aggregates
```sql
SELECT COUNT(*), COUNT(email), COUNT(DISTINCT dept_id),  -- 8, 7, 3
       SUM(salary), AVG(salary), MAX(salary)  -- 835000, 104375, 150000
FROM employees;
SELECT SUM(amount) FROM orders WHERE 1 = 0;  -- NULL (not 0)
```
- `COUNT(col)` and every aggregate skip NULLs; `COUNT(*)` counts rows.

## GROUP BY & HAVING
```sql
SELECT dept_id, COUNT(*) AS n, ROUND(AVG(salary)) AS avg_sal
FROM employees
WHERE hire_date < '2023-01-01'  -- filters ROWS
GROUP BY dept_id
HAVING COUNT(*) >= 2  -- filters GROUPS
ORDER BY avg_sal DESC;  -- 1: 3, 130000 · 2: 3, 105000
SELECT d.name, COUNT(e.emp_id)  -- Legal 0 (COUNT(*) would say 1)
FROM departments d LEFT JOIN employees e ON e.dept_id = d.dept_id
GROUP BY d.name;
```
- Every selected column must be grouped or aggregated.

## Conditional Aggregation (Pivot)
```sql
SELECT customer_id,
  COUNT(*) AS orders,
  SUM(CASE WHEN status = 'delivered' THEN amount ELSE 0 END) AS delivered,
  COUNT(*) FILTER (WHERE status <> 'cancelled') AS valid
FROM orders GROUP BY customer_id ORDER BY customer_id;
-- 1: 3, 350, 3 · 2: 2, 0, 2 · 3: 1, 0, 0
SELECT SUM(CASE WHEN EXTRACT(MONTH FROM order_date) = 1 THEN amount END) AS jan,
       SUM(CASE WHEN EXTRACT(MONTH FROM order_date) = 2 THEN amount END) AS feb
FROM orders;  -- 350, 550
```

## STRING_AGG & ROLLUP
```sql
SELECT dept_id, STRING_AGG(name, ', ' ORDER BY name)
FROM employees GROUP BY dept_id;  -- 1: Asha, Meena, Ravi · 2: John, Karan, Priya
SELECT dept_id, SUM(salary) FROM employees
WHERE dept_id IS NOT NULL
GROUP BY ROLLUP (dept_id);  -- per dept + grand total (NULL row)
```
- MySQL `GROUP_CONCAT`, Oracle `LISTAGG`. Also `CUBE`, `GROUPING SETS`.

## Join Types
```text
INNER   only matches                   A ∩ B
LEFT    all of A + matches or NULL     A
RIGHT   all of B + matches or NULL     B
FULL    everything from both           A ∪ B
CROSS   every A row x every B row      |A| x |B|
SELF    table joined to itself         hierarchies
```

## Join Examples
```sql
SELECT e.name, d.name FROM employees e JOIN departments d ON d.dept_id = e.dept_id;  -- 7 rows
SELECT e.name, d.name FROM employees e LEFT JOIN departments d ON d.dept_id = e.dept_id; -- 8: Arjun + NULL
SELECT e.name, d.name FROM employees e FULL JOIN departments d ON d.dept_id = e.dept_id; -- 9: + Legal
SELECT e.name AS emp, m.name AS manager
FROM employees e LEFT JOIN employees m ON m.emp_id = e.manager_id;  -- self join
SELECT * FROM employees JOIN departments USING (dept_id);
```

## ON vs WHERE (outer joins)
```sql
SELECT c.name, o.order_id FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id AND o.status = 'placed';
-- Anil 106, Bina 105, Chetan NULL, Divya NULL
SELECT c.name, o.order_id FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.status = 'placed';
-- Anil 106, Bina 105: WHERE turned it into an INNER join
```

## Anti-Join & Semi-Join
```sql
SELECT c.name FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;  -- Divya (no orders)
SELECT c.name FROM customers c WHERE NOT EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);  -- Divya
SELECT d.name FROM departments d WHERE EXISTS (
  SELECT 1 FROM employees e WHERE e.dept_id = d.dept_id);  -- 3 depts
```

## Set Operations
```sql
SELECT city FROM customers UNION SELECT location FROM departments;  -- distinct
SELECT city FROM customers UNION ALL SELECT location FROM departments; -- 8 rows
SELECT city FROM customers INTERSECT SELECT location FROM departments; -- Pune, Mumbai, NULL
SELECT location FROM departments EXCEPT SELECT city FROM customers;  -- Delhi
```
- Same column count and types; one `ORDER BY` at the end. Oracle: `MINUS`.

## Subqueries
```sql
SELECT name FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);  -- scalar
SELECT name FROM customers WHERE customer_id IN (
  SELECT customer_id FROM orders WHERE amount >= 300);  -- Anil, Bina
SELECT name FROM employees e WHERE salary > (  -- correlated
  SELECT AVG(salary) FROM employees x WHERE x.dept_id = e.dept_id);  -- Asha, John, Karan
SELECT name FROM employees WHERE salary > ALL (
  SELECT salary FROM employees WHERE dept_id = 2);  -- Asha, Ravi, Meena
SELECT c.name, r.amount FROM customers c CROSS JOIN LATERAL (
  SELECT amount FROM orders o WHERE o.customer_id = c.customer_id
  ORDER BY order_date DESC LIMIT 1) r;  -- latest order each
```

## CTEs (WITH)
```sql
WITH dept_avg AS (
  SELECT dept_id, AVG(salary) AS avg_sal FROM employees GROUP BY dept_id
), high AS (
  SELECT dept_id FROM dept_avg WHERE avg_sal > 100000
)
SELECT e.name FROM employees e JOIN high USING (dept_id);
```
- A named subquery for one statement: readable, reusable, can be recursive.

## Recursive CTE
```sql
WITH RECURSIVE chain AS (
  SELECT emp_id, name, 1 AS lvl, name::TEXT AS path
  FROM employees WHERE manager_id IS NULL  -- anchor
  UNION ALL
  SELECT e.emp_id, e.name, c.lvl + 1, c.path || ' > ' || e.name
  FROM employees e JOIN chain c ON e.manager_id = c.emp_id
)
SELECT path FROM chain ORDER BY path;  -- Asha, Asha > Arjun, ..., Neha
SELECT generate_series(1, 5);  -- 1..5 (PG)
```

## Ranking Window Functions
```sql
SELECT name, salary,
  ROW_NUMBER() OVER (ORDER BY salary DESC, emp_id) AS rn,
  RANK()       OVER (ORDER BY salary DESC) AS rnk,
  DENSE_RANK() OVER (ORDER BY salary DESC) AS drnk
FROM employees WHERE dept_id = 1;
-- Asha 1 1 1 · Ravi 2 2 2 · Meena 3 2 2
```
- ROW_NUMBER unique · RANK gaps after ties (1,2,2,4) · DENSE_RANK no gaps (1,2,2,3). Windows keep every row (unlike GROUP BY).

## LAG · LEAD · Running Total
```sql
SELECT order_id, amount,
  LAG(amount) OVER (ORDER BY order_date) AS prev,
  LEAD(amount) OVER (ORDER BY order_date) AS next,
  SUM(amount) OVER (ORDER BY order_date) AS running,  -- 250 350 750 900 950 1250
  SUM(amount) OVER (PARTITION BY customer_id ORDER BY order_date) AS per_cust,
  AVG(amount) OVER (ORDER BY order_date
      ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg,
  ROUND(100.0 * amount / SUM(amount) OVER (), 1) AS pct
FROM orders ORDER BY order_date;
```

## Window Frames
```text
ORDER BY alone  = RANGE UNBOUNDED PRECEDING..CURRENT ROW
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW   moving window
ROWS BETWEEN UNBOUNDED PRECEDING
     AND UNBOUNDED FOLLOWING   whole partition (LAST_VALUE)
OVER ()         = the whole result
```

## Views
```sql
CREATE VIEW dept_summary AS
SELECT d.name AS dept, COUNT(e.emp_id) AS headcount
FROM departments d LEFT JOIN employees e ON e.dept_id = d.dept_id
GROUP BY d.name;
SELECT * FROM dept_summary WHERE headcount > 0;
CREATE MATERIALIZED VIEW month_rev AS
SELECT DATE_TRUNC('month', order_date) AS m, SUM(amount) AS rev FROM orders GROUP BY 1;
REFRESH MATERIALIZED VIEW month_rev;
```
- View = stored query (no data). Materialised view = stored result, refreshed on demand.

## Functions · Procedures · Triggers
```sql
CREATE FUNCTION dept_payroll(p INT) RETURNS NUMERIC LANGUAGE sql
AS $$ SELECT COALESCE(SUM(salary), 0) FROM employees WHERE dept_id = p $$;
SELECT dept_payroll(1);  -- 390000.00
CREATE PROCEDURE raise(p INT, pct NUMERIC) LANGUAGE plpgsql AS $$
BEGIN UPDATE employees SET salary = salary * (1 + pct / 100) WHERE dept_id = p; END $$;
CALL raise(3, 10);
CREATE TABLE audit (emp_id INT, old_sal NUMERIC, new_sal NUMERIC);
CREATE FUNCTION log_sal() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN INSERT INTO audit VALUES (OLD.emp_id, OLD.salary, NEW.salary); RETURN NEW; END $$;
CREATE TRIGGER trg AFTER UPDATE OF salary ON employees
FOR EACH ROW EXECUTE FUNCTION log_sal();
```
- Function returns a value, used in SELECT. Procedure: `CALL`/`EXEC`, can manage transactions. SQL Server T-SQL, Oracle PL/SQL, MySQL `DELIMITER //`.

## JSON (PostgreSQL)
```sql
SELECT '{"a": {"city": "Pune"}}'::JSONB -> 'a' ->> 'city';  -- Pune
SELECT '{"a": 1, "b": 2}'::JSONB @> '{"a": 1}';  -- true
SELECT JSONB_BUILD_OBJECT('id', emp_id, 'name', name) FROM employees WHERE emp_id = 1;
SELECT JSON_AGG(name ORDER BY name) FROM employees WHERE dept_id = 2;  -- ["John","Karan","Priya"]
```
- `->` returns JSON, `->>` text. MySQL: `col->>'$.name'`. SQL Server: `JSON_VALUE`.

## Transactions
```sql
BEGIN;
UPDATE employees SET salary = salary - 5000 WHERE emp_id = 1;
UPDATE employees SET salary = salary + 5000 WHERE emp_id = 8;
SAVEPOINT s1;
DELETE FROM orders WHERE order_id = 101;
ROLLBACK TO SAVEPOINT s1;  -- undo only the delete
COMMIT;
```
- **ACID**: Atomicity (all or nothing) · Consistency (constraints hold) · Isolation · Durability (survives crashes, via the WAL).

## Isolation Levels
```text
level             dirty  non-repeat  phantom
READ UNCOMMITTED  yes    yes         yes
READ COMMITTED    no     yes         yes   <- PG, SQL Server, Oracle default
REPEATABLE READ   no     no          yes   <- MySQL default
SERIALIZABLE      no     no          no
```
- **MVCC**: readers see a snapshot and don't block writers. SERIALIZABLE may abort: retry.

## Locking
```sql
BEGIN;
SELECT * FROM orders WHERE order_id = 105 FOR UPDATE;  -- lock the row
UPDATE orders SET status = 'shipped' WHERE order_id = 105;
COMMIT;
SELECT order_id FROM orders WHERE status = 'placed'
ORDER BY order_id LIMIT 1 FOR UPDATE SKIP LOCKED;  -- job queue
```
- **Deadlock**: two transactions wait on each other; the DB kills one. Lock in a fixed order, keep transactions short, retry.

## Indexes
```sql
CREATE INDEX idx_orders_cust ON orders (customer_id);
CREATE INDEX idx_orders_cust_date ON orders (customer_id, order_date);
CREATE INDEX idx_cover ON orders (customer_id) INCLUDE (amount);
CREATE INDEX idx_open ON orders (order_date) WHERE status = 'placed';
CREATE UNIQUE INDEX uq_email ON employees (LOWER(email));
```
- B-tree default (=, <, >, ORDER BY, `LIKE 'abc%'`). Composite index (a, b) serves `a` and `a+b`, **not** `b` alone (leftmost prefix). Clustered = physical row order (one per table). Indexes speed reads, slow writes.

## When Indexes Are Skipped
```text
WHERE YEAR(d) = 2026       -> d >= '2026-01-01' AND d < '2027-01-01'
WHERE amount * 2 > 100     -> amount > 50
WHERE name LIKE '%son'     -> trigram / full-text index
WHERE LOWER(email) = 'x'   -> expression index
implicit type casts, tiny tables, low selectivity, stale stats
```

## EXPLAIN
```sql
EXPLAIN ANALYZE SELECT c.name, SUM(o.amount)
FROM customers c JOIN orders o ON o.customer_id = c.customer_id
GROUP BY c.name;
```
- Read inside-out. Scans: Seq · Index · Index Only · Bitmap. Joins: Nested Loop · Hash · Merge. Red flag: estimated rows far from actual.

## Normalisation
- **1NF**: atomic values, no repeating groups. **2NF**: no partial dependency on a composite key. **3NF**: no transitive dependency (non-key → non-key). **BCNF**: every determinant is a key.
- Prevents insert, update and delete anomalies. Denormalise on purpose for reporting (OLAP).
- 1:1 = FK + UNIQUE · 1:N = FK on the many side · M:N = junction table.

## Nth Highest Salary
```sql
SELECT DISTINCT salary FROM employees
ORDER BY salary DESC OFFSET 1 LIMIT 1;  -- 2nd: 120000
SELECT MAX(salary) FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);  -- 120000
SELECT salary FROM (
  SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS r
  FROM employees) t
WHERE r = 3 LIMIT 1;  -- 3rd: 115000
```

## Duplicates
```sql
SELECT salary, COUNT(*) FROM employees
GROUP BY salary HAVING COUNT(*) > 1;  -- 120000, 2
CREATE TEMP TABLE emails (id INT, email TEXT);
INSERT INTO emails VALUES (1, 'a@x'), (2, 'b@x'), (3, 'a@x');
DELETE FROM emails WHERE id IN (
  SELECT id FROM (SELECT id, ROW_NUMBER() OVER (
    PARTITION BY email ORDER BY id) AS rn FROM emails) t
  WHERE rn > 1);  -- keeps ids 1, 2
```

## Top N per Group
```sql
SELECT dept_id, name, salary FROM (
  SELECT e.*, DENSE_RANK() OVER (
    PARTITION BY dept_id ORDER BY salary DESC) AS r
  FROM employees e) ranked
WHERE r <= 2;
-- 1: Asha, Ravi, Meena · 2: Karan, John · 3: Neha · NULL: Arjun
SELECT d.name, e.name FROM employees e JOIN departments d USING (dept_id)
WHERE (e.dept_id, e.salary) IN (
  SELECT dept_id, MAX(salary) FROM employees GROUP BY dept_id);  -- max per dept
```

## Self-Join Classics
```sql
SELECT e.name, m.name AS manager FROM employees e
JOIN employees m ON m.emp_id = e.manager_id
WHERE e.salary > m.salary;  -- Karan earns more than John
SELECT m.name, COUNT(*) FROM employees e
JOIN employees m ON m.emp_id = e.manager_id
GROUP BY m.name;  -- Asha 3, John 2
```

## Running Total & Growth
```sql
WITH monthly AS (
  SELECT DATE_TRUNC('month', order_date)::DATE AS m, SUM(amount) AS rev
  FROM orders WHERE status <> 'cancelled' GROUP BY 1)
SELECT m, rev,
  SUM(rev) OVER (ORDER BY m) AS cumulative,  -- 350, 750, 1100
  ROUND(100.0 * (rev - LAG(rev) OVER (ORDER BY m))
        / LAG(rev) OVER (ORDER BY m), 1) AS growth -- NULL, 14.3, -12.5
FROM monthly;
SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY salary) FROM employees;  -- median 112500
```

## Gaps & Islands
```sql
CREATE TEMP TABLE logins (uid INT, d DATE);
INSERT INTO logins VALUES (1, '2026-10-01'), (1, '2026-10-02'), (1, '2026-10-03'),
  (1, '2026-10-05'), (1, '2026-10-06');
SELECT uid, MIN(d), MAX(d), COUNT(*) AS streak FROM (
  SELECT uid, d, d - (ROW_NUMBER() OVER (PARTITION BY uid ORDER BY d))::INT AS grp
  FROM logins) t
GROUP BY uid, grp ORDER BY 2;  -- 10-01..10-03 (3), 10-05..10-06 (2)
```

## Gotchas
- `= NULL` never matches; `NOT IN` + NULL → no rows; `SUM` of nothing = NULL; `NULL + 1` = NULL.
- `5 / 2 = 2` (integer division in PG and SQL Server): use `5 / 2.0`.
- `BETWEEN` is inclusive: with timestamps use `>= start AND < next_day`.
- WHERE on the right table of a LEFT JOIN makes it an INNER join.
- Joining two one-to-many tables then summing double counts: aggregate first.
- Functions on indexed columns and leading `%` skip indexes.

## Interview One-Liners
- **WHERE vs HAVING**: rows before grouping vs groups after.
- **UNION vs UNION ALL**: dedupe (slower) vs keep all.
- **Primary vs unique key**: not null, one per table vs nullable, many.
- **RANK vs DENSE_RANK vs ROW_NUMBER**: 1,2,2,4 · 1,2,2,3 · 1,2,3.
- **EXISTS vs IN**: stops at first match, NULL-safe vs list compare.
- **Clustered vs non-clustered**: row order vs separate pointer structure.
- **View vs materialised view**: query vs stored result.
- **OLTP vs OLAP**: many small writes vs big analytic reads.
- **SQL injection**: always use parameterised queries.
- **Partitioning vs sharding vs replication**: split in one DB · across servers · copies.

# 01 | Git Interview Cheat Sheet | The commands, workflows and "undo" recipes you are asked about, with hooks. | Git on one page

### Basics

## How Git Works
> Git is a **distributed version control system**: every clone holds the full history. Data flows **working directory -> staging area -> local repo -> remote**.
```text
git add  ->  staging      git commit  ->  local repo      git push  ->  remote (origin)
git fetch / git pull  <-  remote       git checkout/switch/restore  ->  working directory
```
- A commit is a snapshot with a hash and a parent pointer; **branches and tags are just pointers** to commits; **HEAD** is where you are.
! Three areas: working, staged, committed.

## Everyday Commands
```bash
git clone <url>        git status         git diff / git diff --staged
git add -p             git commit -m "msg"        git log --oneline --graph --all
git switch -c feature  git switch main    git branch -d feature
git fetch              git pull --rebase  git push -u origin feature
```
! `git add -p` stages chunks deliberately.

## Merge vs Rebase
> **Merge** joins histories with a merge commit (keeps true history). **Rebase** replays your commits on top of another branch (linear history, rewrites commits).
```bash
git switch feature && git rebase main     # tidy before a PR
git switch main && git merge --no-ff feature
git rebase -i HEAD~3                      # squash, reword, reorder
```
- **Golden rule:** never rebase commits already pushed to a shared branch.
! Rebase your private branch; merge shared ones.

## Resolving Conflicts
- Git marks conflicts with `<<<<<<<`, `=======`, `>>>>>>>`. Edit the file, `git add` it, then `git merge --continue` or `git rebase --continue`. Abort with `--abort`.
- Prevent: small PRs, frequent `pull --rebase`.
! Conflicts are normal; keep changes small.

### Undoing Things

## Undo Recipes
```bash
git restore file                 # discard working changes        git restore --staged file   # unstage
git commit --amend               # fix last commit (not if pushed)
git revert <hash>                # new commit that undoes it (safe on shared branches)
git reset --soft HEAD~1          # undo commit, keep changes staged
git reset --hard HEAD~1          # undo commit AND discard changes (dangerous)
git reflog                       # find "lost" commits, then git reset --hard <hash>
```
! Shared branch: `revert`. Local mess: `reset`. Panic: `reflog`.

## Stash, Cherry-pick, Bisect
```bash
git stash -u && git stash pop        # park changes        git cherry-pick <hash>   # copy one commit
git bisect start; git bisect bad; git bisect good <hash>     # binary search for the bug-causing commit
```
! Stash to switch tasks, cherry-pick for hotfixes, bisect for regressions.

## Reset vs Revert vs Checkout
- `reset` moves the branch pointer (rewrites history). `revert` adds an inverse commit. `restore/checkout` change files or HEAD.
! Reset rewrites; revert records.

### Collaboration

## Branching Strategies
- **GitHub Flow:** short feature branches + PR into `main`. **Git Flow:** `main`, `develop`, release/hotfix branches. **Trunk-based:** tiny commits to main with feature flags (best for CI/CD).
! Pick the simplest strategy the team can follow.

## .gitignore, Tags, Hooks
- `.gitignore` for build output and secrets (does not untrack files already committed: `git rm --cached`). **Tags** mark releases (`git tag -a v1.2.0 -m ""`). **Hooks** (pre-commit) lint and test.
! Never commit secrets; if you do, rotate them.

## Fork, Pull Request, Code Review
- Fork -> branch -> push -> PR -> review -> squash/merge. Good PR: small, described, tests included, linked issue.
! A PR is a conversation, not a dump.

### More Git

## Internals, Submodules & Worktrees
- Objects: **blob** (file), **tree** (directory), **commit**, **tag**, stored by SHA. `git cat-file -p <hash>`. `git worktree add ../hotfix main` checks out another branch in a new folder; **submodules** pin another repo at a commit; `git clean -fd` removes untracked files; `git blame` / `git log -S"text"` find history.
! Branches are 41-byte files pointing at a commit.

## Signed Commits & Large Repos
- Sign with `git commit -S` (GPG/SSH) for verified badges; **Git LFS** stores large binaries; shallow clone `--depth 1`; sparse checkout for monorepos; `.gitattributes` for line endings.
! Use LFS for assets, not git history.

### Must-Know Questions

## Git Questions
Q*: `git pull` vs `git fetch`?
A: `fetch` downloads remote changes without touching your branch; `pull` is fetch plus merge (or rebase).
Q*: Merge vs rebase?
A: Merge preserves history with a merge commit; rebase rewrites commits for a linear history; don't rebase shared branches.
Q*: How do you undo a pushed commit?
A: `git revert <hash>` and push, which adds an inverse commit without rewriting shared history.
Q*: How do you resolve a merge conflict?
A: Open the conflicted files, choose the right content, remove markers, `git add`, then continue the merge or rebase.
Q: What is `git stash`?
A: It saves uncommitted changes temporarily so you can switch branches and restore them later with `stash pop`.
Q: Reset --soft vs --mixed vs --hard?
A: Soft keeps changes staged, mixed (default) keeps them unstaged, hard discards them.

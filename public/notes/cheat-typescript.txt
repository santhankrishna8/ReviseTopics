# 01 | TypeScript Cheat Sheet | Concepts on one page: what each feature is, what it is for, how it compares with plain JavaScript or the alternative, and only the tricky code | TypeScript on one page

## What is TypeScript?
> **What:** a **statically typed superset of JavaScript** by Microsoft (2012). You write `.ts`, the compiler `tsc` checks types and outputs plain JavaScript.
- **Types exist only at compile time** (type erasure): at runtime it is just JS, so external data still needs runtime validation (Zod).
- **vs JavaScript**: catches bugs before running (typos, wrong arguments, `undefined` access), great autocomplete and refactoring, self-documenting code. Cost: a build step and learning the type system.
- Used by Angular (required), most React/Next.js/Node projects. TS 6 (2026) turns `strict` on by default; TS 7 (Jul 2026) is the compiler rewritten in Go (~10x faster).

## tsconfig.json
- `target` (JS version emitted) · `module` / `moduleResolution` (`nodenext` for Node, `bundler` for Vite/Angular) · `strict` · `outDir`/`rootDir` · `lib` · `paths` (aliases) · `declaration` (emit `.d.ts`) · `skipLibCheck`.
- **strict** = `noImplicitAny` + `strictNullChecks` + `strictFunctionTypes` + more. Always on.
- Extra safety: `noUncheckedIndexedAccess` (`arr[i]` may be undefined), `noImplicitOverride`, `exactOptionalPropertyTypes`.
- `tsc --noEmit` = type-check only (CI); bundlers just strip types without checking.

## Basic Types
- Primitives: `string`, `number` (all numbers are floats), `bigint`, `boolean`, `symbol`, `null`, `undefined`.
- Arrays `number[]` / `Array<number>`; **tuples** `[string, number]` (fixed positions); `readonly number[]`.
- **Type inference**: `let x = 5` is already `number`; annotate parameters and public APIs, let locals infer.
- Use lowercase `string`, never the wrapper `String`.

## any vs unknown vs never vs void
```text
any      checking OFF (avoid)
unknown  anything, but must narrow before use
never    no value: always throws / impossible
void     returns nothing useful
```
- Use `unknown` for JSON, `catch (e)` errors and external input.

## Union, Intersection & Literal Types
- **Union** `A | B`: one OR the other; only common members usable until you narrow. `string | number`.
- **Intersection** `A & B`: has everything of both. `Timestamps & User`.
- **Literal types**: exact values: `type Dir = 'up' | 'down'`. A great replacement for enums.
- `as const`: makes a value deeply `readonly` with literal types: `const cfg = { mode: 'dark' } as const`.

## Interfaces
> **What:** a named description of an **object's shape**: properties, optional (`?`), `readonly`, methods.
- Can **extend** other interfaces and be **merged** (two declarations with the same name combine), which is how libraries are augmented.
- A class can `implements` an interface (the compiler checks it; nothing is inherited).

## Type Aliases & interface vs type
> **What:** `type Name = ...` gives a name to **any** type: unions, tuples, functions, primitives, mapped/conditional types.
```text
                    interface         type
object shapes       yes               yes
unions / tuples     no                yes
extend             extends            & intersection
declaration merge   yes               no
best for            public object     unions, functions,
                    contracts         computed types
```

## Enums vs Union Types
- **enum**: `enum Role { Admin, User }` creates a real runtime object (numeric enums map both ways: `Role[0] === 'Admin'`). String enums: `enum C { Red = 'RED' }`.
- **Union of literals** `type Role = 'admin' | 'user'` or an `as const` object: zero runtime code, simpler, works with type stripping.
- Modern preference: **unions / `as const`** unless you need an iterable runtime object.

## Structural Typing
> **What:** compatibility is decided by **shape**, not by name ("duck typing"). Any object with the required properties fits an interface, without `implements`.
- **vs Java/C# nominal typing**: there, a class must explicitly declare it implements a type.
- **Excess property check**: an object literal passed directly can't have extra properties (catches typos); a variable can.
- Exception: classes with `private`/`#private` members are only compatible with themselves. Use **branded types** for nominal IDs.

## Optional Chaining, ?? and Assertions
- `a?.b?.c`: stops at `null`/`undefined` and returns `undefined` instead of throwing.
- `x ?? 'default'`: fallback only for `null`/`undefined`. `||` also replaces `0`, `''`, `false`: a classic bug.
- `value!`: **non-null assertion** (you promise it isn't null). `x as Type`: **type assertion**: changes what the compiler believes, never the value. Both are unchecked: prefer narrowing.
- `satisfies` (4.9): checks a value against a type **without widening** it: keeps literal keys and autocomplete.

## Functions
- Typed parameters and return: `function add(a: number, b: number): number`. Optional `b?: number` (must come last), default `b = 1`, rest `...xs: number[]`.
- Function types: `type Handler = (e: Event) => void`.
- **Overloads**: several signatures + one implementation, when the return type depends on the argument type.
- A `void` callback may still return a value (it is ignored). `async` functions return `Promise<T>`; `Awaited<T>` unwraps it.

## Classes in TypeScript
- Access modifiers `public` (default), `protected`, `private`; plus `readonly`, `static`, `abstract`, `override`.
- **private vs #private**: `private` is compile-time only (erased, reachable at runtime); `#field` is real JavaScript privacy enforced by the engine.
- **Parameter properties**: `constructor(private repo: Repo) {}` declares and assigns a field in one go (used everywhere in Angular).
- `strictPropertyInitialization`: every field must be initialised (or marked `!` when a framework sets it).

## Abstract Classes vs Interfaces (TS)
- **Abstract class**: exists at runtime, can hold code and state, single inheritance, can't be instantiated.
- **Interface**: compile-time only (zero JS output), many per class, no implementation.
- Angular uses abstract classes as **DI tokens** because interfaces vanish at runtime.

## Decorators
> **What:** functions applied with `@name` to classes, methods, accessors or fields to add metadata or wrap behaviour.
- **TS 5 standard decorators** (TC39): no parameter decorators.
- **experimentalDecorators** (older): used by **Angular**, NestJS, TypeORM; supports parameter decorators like `@Inject()`.

## Generics
> **What:** **type parameters** that make functions, classes and interfaces reusable while keeping exact types: `function first<T>(xs: T[]): T`.
- **Why vs any**: `any` loses type information; generics keep it (`first(['a'])` returns `string`).
- **Constraints**: `<T extends { length: number }>`; `<K extends keyof T>` for safe property access `T[K]`.
- **Defaults** `<T = unknown>`, **const type params** `<const T>` (5.0) keep literal types, `NoInfer<T>` (5.4) stops a parameter from driving inference.
```ts
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }
const age = getProp({ name: 'Ann', age: 30 }, 'age');   // number
// getProp({ name: 'Ann' }, 'email');                   // compile error
```

## Narrowing
> **What:** TypeScript refines a broad type to a specific one based on your checks (control-flow analysis).
- `typeof x === 'string'`, `x instanceof Date`, `'swim' in pet`, `Array.isArray(x)`, equality `x === null`, truthiness `if (x)`.
- **Type guard**: a function returning `pet is Fish`. **Assertion function**: `asserts x is T` (throws if not).
- Gotcha: `typeof null === 'object'`; `if (count)` also skips `0`.

## Discriminated Unions
> **What:** a union whose members share a literal **tag** property (`kind`, `type`, `status`); checking the tag narrows to one member.
- **Why**: models states safely (`loading | success | error`), no invalid combinations.
- **Exhaustiveness**: assign the leftover to `never` so adding a new member breaks compilation until handled.
```ts
type Shape = { kind: 'circle'; r: number } | { kind: 'square'; side: number };
function area(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.r ** 2;
    case 'square': return s.side ** 2;
    default: { const nope: never = s; throw new Error(String(nope)); }
  }
}
```

## Utility Types
```text
Partial<T>       all properties optional (PATCH bodies)
Required<T>      all required
Readonly<T>      all readonly (shallow)
Pick<T, K>       keep some keys
Omit<T, K>       drop some keys
Record<K, V>     object type from keys + value type
Exclude<U, X>    remove members from a union
Extract<U, X>    keep matching members
NonNullable<T>   remove null | undefined
ReturnType<F>    function's return type
Parameters<F>    function's parameter tuple
Awaited<T>       unwrap a Promise
```

## keyof, typeof & Indexed Access
- `keyof T`: union of a type's keys. `typeof value`: the type of a variable (in a type position).
- `T['age']`: the type of one property. `T[number]`: element type of an array/tuple.
- Classic: `const roles = ['admin', 'user'] as const; type Role = (typeof roles)[number];` → `'admin' | 'user'`.

## Mapped & Conditional Types
- **Mapped**: build a new type by looping over keys: `{ [K in keyof T]?: T[K] }` (this is `Partial`). `-?` removes optional, `-readonly` removes readonly, `as` renames keys.
- **Conditional**: `T extends U ? X : Y`; **infer** captures part of a type: `T extends (...a: any) => infer R ? R : never` (this is `ReturnType`).
- Conditional types **distribute** over unions: `ToArray<string | number>` → `string[] | number[]`.
- **Template literal types**: `` `on${Capitalize<E>}` `` builds string types like `'onClick'`.

## Modules & Declaration Files
- Any file with `import`/`export` is a **module** (own scope); otherwise a global script.
- `import type { X }` imports types only (erased). Named vs default exports; `export * from`.
- **`.d.ts` files** contain only types describing JavaScript: shipped with packages, from `@types/x` (DefinitelyTyped), or your own `declare module 'x'`.
- `declare` describes something that exists at runtime without emitting code. `declare global { }` adds globals from a module.

## Newer Features
- `satisfies` (4.9) · `accessor` fields (4.9) · standard decorators and `const` type params (5.0).
- `using` (5.2): resources disposed automatically at the end of the scope (`Symbol.dispose`), like Java try-with-resources.
- `NoInfer` (5.4) · inferred type predicates in `filter` (5.5) · `erasableSyntaxOnly` (5.8) for Node's type stripping.

## Gotchas
```ts
const xs: number[] = [];
const first = xs[0];             // typed number, actually undefined
const keys = Object.keys({ a: 1 });   // string[], not ('a')[]
const anyNonNull: {} = 42;       // {} means "any non-null value"
[10, 9, 1].sort();               // [1, 10, 9]: sorts as strings
const data = JSON.parse('{}');   // any: validate external data
```
- `readonly` is shallow. `@ts-ignore` hides errors forever: prefer `@ts-expect-error`.

## Interview One-Liners
- **interface vs type**: extendable/mergeable object contracts vs any type including unions.
- **any vs unknown**: no checking vs must narrow first.
- **never**: values that can't exist; exhaustive switches.
- **Generics**: reusable code with type parameters instead of `any`.
- **Union vs intersection**: either vs both.
- **Type assertion vs narrowing**: trust me vs proven by a check.
- **private vs #private**: compile-time vs runtime.
- **Enum vs union**: runtime object vs zero-cost literal types.
- **Why TypeScript**: fewer runtime bugs, tooling, safer refactoring at scale.
